# 系统设计：从任务要求到可验证的方案

这里把模型、硬件、运行时和平台放回同一道设计题：给定任务、质量、期限与预算，怎样选出可行方案，并说明选择在什么条件下会改变？

第一次阅读先看全景，再进入[26 篇机制主线](../guides/系统阅读路线.md)。已有模型与系统基础时，可以沿[系统设计阅读路线](../guides/系统设计阅读路线.md)完成下面的案例。正文中的教学预算、源码行为和设备实测各有明确边界。

## 用同一模型完成两类设计

[训练方案](../09_Training_Systems/训练并行方案设计.md)与[推理方案](../10_Inference_Serving/推理并行方案设计.md)使用相同的教学模型容量配置：80 亿参数、32 层、8 个 KV 头、头维 128、BF16 权重。训练增加梯度、优化器和激活，推理增加变长请求与 KV；两者分别固定任务目标和设备预算，比较候选方案。

参数用于教学核算，不对应某个实际 checkpoint；给定阶段时间不充当 GPU 测量。负载篇复用推理案例的输入／输出长度，但其驻留时间另有假设。每篇完整列出本篇条件，不把不同阶段的假设混成一组实测。

## 借鉴来源与本系列的分工

组织方式参考[李博杰《深入理解 AI Infra：量化分析与系统设计》](https://bojieli.github.io/ai-infra-book/)：先建立系统图景，再从具体负载与约束推导设计。这里的算例独立设定；模型、并行、源码与正确性细节继续由现有专题承担。涉及研究结论的文章另列一手来源，型号规格与软件支持按具体版本核对。
