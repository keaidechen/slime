# 质量约束下的成本与预算：从计算量到有效产出

前置：[负载与状态](负载状态与资源需求.md)。资源需求说明系统要做多少工作；预算还需要回答：哪些结果算交付，什么时候必须完成，模型会服务多久？先定义这些条件，才能比较更大模型、更多数据、更高并行度或更多推理尝试。

## 先固定交付口径

设观察期总成本为 $K$，同时满足质量与时限的任务数为 $Q$，则单位有效产出成本为 $K/Q$。$Q=0$ 时该比值没有有限值。失败、超时、取消后的残余计算、空闲预留和重试都进入分子；不能只统计成功任务花掉的资源。

质量与时限是联合条件。若回答质量通过率为 90%，响应达标率为 90%，两者同时通过不一定是 81%；要对同一批任务直接统计。更快输出、较低 loss 或更多生成 token 都不能单独替代任务质量。测量方法见[实验统计与质量评估](../12_Performance_Reliability/实验统计与质量评估.md)。

| 决策 | 先固定的合同 | 必须同时报告 |
|---|---|---|
| 训练 | 数据、质量目标、截止时间 | 达标训练次数、有效 token、恢复损失、总设备时间 |
| 在线服务 | 任务分布、质量、TTFT/ITL/完成时限 | 接纳率、联合达标率、达标吞吐、费用 |
| Agent / RL | 任务成功条件、工具与尝试预算 | 环境成本、有效轨迹、重试、任务成功率 |

对丢弃请求的系统，接纳后达标率与全量提交任务达标率都要保留。否则拒绝困难请求就会让指标看起来更好。

## 训练计算预算怎样影响模型与数据

对稠密 Transformer 的主要参数矩阵运算，常用近似是

$$C\approx6ND,$$

其中 $N$ 是参数量，$D$ 是训练 token 数，$C$ 的单位是 FLOP。系数 6 近似合并前向与反向。长上下文 Attention、重算、优化器、稀疏激活与数据浪费需要另建账，不能靠这个系数全部吸收。有效训练 token 与实际执行位置也要区分。

它首先给出候选规模，不直接给出墙钟时间。时间还依赖有效计算速度、访存、通信、流水气泡与恢复；具体展开见[训练方案案例](../09_Training_Systems/训练并行方案设计.md)。

一种经验 loss 拟合形式是

$$L(N,D)=E+\frac{A}{N^\alpha}+\frac{B}{D^\beta},\qquad A,B,\alpha,\beta>0.$$

$E$ 是拟合的不可约项，其余系数由一组相容实验拟合。固定 $C$，代入 $D=C/(6N)$，令对 $N$ 的导数为零，有

$$N_*^{\alpha+\beta}=\frac{\alpha A}{\beta B}\left(\frac{C}{6}\right)^\beta.$$

因此在该拟合成立的范围内，$N_*\propto C^{\beta/(\alpha+\beta)}$，$D_*\propto C^{\alpha/(\alpha+\beta)}$。例如仅作教学假设 $\alpha=\beta$，预算变成 4 倍时，最优模型和数据各变成 2 倍；把全部增量只给模型会偏离这个拟合下的最优点。参数与数据协同扩展的实验依据见 [Hoffmann 等，Training Compute-Optimal Large Language Models](https://arxiv.org/abs/2203.15556)。

Scaling law 是实验范围内的经验关系。更换数据质量、训练配方或模型结构后，应重新校准并留出验证点；重复同一数据不保证等同于新增独立数据。也不能把语言建模 loss 的改善直接换算成工具任务成功率。先用小规模实验淘汰候选，再用目标任务验证质量约束。

## 训练最省计算的模型，未必全生命周期最省钱

较小模型可能需要更多训练数据才能达到目标，却在大量后续请求中降低服务成本。将推理需求纳入规模选择，正是 [Beyond Chinchilla-Optimal](https://arxiv.org/abs/2401.00448v3)研究的问题。推理总需求、延迟限制和拟合区间都会改变选择，不能把某个参数/token 比例当作通用答案。

下面不使用论文测量或真实云价格，而给出两个已通过同一最低质量要求的假想候选。一次提交只尝试一次，各候选的成本与成功率在所讨论负载区间内假设不变：

| 输入 | 候选 A | 候选 B |
|---|---:|---:|
| 一次性训练与发布成本／成本单位 | 10000 | 16000 |
| 每次提交的平均服务成本 | 0.040 | 0.027 |
| 同时满足质量与时限的概率 | 0.80 | 0.90 |
| 每项有效产出的服务成本 | 0.050 | 0.030 |

服务成本按全量提交统计，已分摊预留资源和失败开销。最后一行为成本除以联合通过率。这里的目标 $Q$ 是长期累计有效交付量；大样本规划中预计需要提交 $Q/p$ 项任务，并不保证每个指定用户任务最终成功。

$$K_A(Q)=10000+0.05Q,\qquad K_B(Q)=16000+0.03Q.$$

令两式相等，得到 **$Q=300000$ 项有效交付**。10 万项时 A/B 为 15000/19000；100 万项时为 60000/46000。预计模型很快被替换时，较低的一次性投入可能更重要；服务量大时，较低的持续成本可能收回投入。

若目标是同一批固定的 10 万项提交，则应分别计算其成本和 8 万／9 万有效结果，不能偷偷换成相同交付量。模型版本变化、流量变化和价格变化也会改变分界点。

## 资源效率如何变成费用

教学例：预留 4 张 GPU，每张每小时 2 成本单位；服务忙碌时集群共输出 1000 token/s。若一小时内执行该服务的忙碌时间比例为 25%，则输出 90 万 token，GPU 成本为 8，约 8.89 单位／百万输出 token。比例为 50% 时，得到 180 万 token，约 4.44 单位／百万输出 token。

这里的忙碌时间比例不是监控面板的 SM 利用率。例子假定忙碌时的批次组成和吞吐不变，只展示固定预留成本如何被分摊。真实增长可能提高 batch 效率，也可能挤压时限，因此必须重新测量达标吞吐。还需加入 CPU、网络、存储、环境和运维费用；若已包含在整机租价中，不再重复相加。

单位 token 成本适合比较相同任务分布下的服务实现。模型改变输出长度、工具次数或成功率时，最终回到单位有效任务成本。Agent 中的资源·时间积分见[环境容量与生命周期](../11_RL_Systems/Agent环境容量与生命周期.md)。

## 把质量改进也放进预算

增大模型、延长思考、采样多条候选和调用工具都是用资源换取质量的候选手段。对每种方案记录联合达标率、总尝试数、临界路径和环境驻留，再比较有效产出成本。

多次尝试的成功事件可能高度相关；选择器也可能选错。不能直接用 $1-(1-p)^k$ 宣称执行 $k$ 次后的质量，除非独立性与选择条件成立。重试还受总期限和最大次数约束，应按真实执行树计算停止条件。RL 同理：提高奖励不自动证明目标质量提升，须保留[独立评估](../11_RL_Systems/奖励评估与质量闭环.md)。

最后将决策写成可复核的表：固定合同 → 候选输入 → 容量与时间可行性 → 达标产出与成本 → 结论翻转点 → 待测参数。带着这张表进入[训练设计](../09_Training_Systems/训练并行方案设计.md)和[推理设计](../10_Inference_Serving/推理并行方案设计.md)，再由[证据与因果](../12_Performance_Reliability/证据与因果.md)区分估算与实测。
