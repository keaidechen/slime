# Omni 训练与后训练

[多阶段运行时](../10_Inference_Serving/Omni多阶段运行时.md)假定编码器、理解骨干和生成器可以交换有意义的表示。这种配合来自数据、目标和优化过程。本篇重点不是列一张通用训练配方，而是确定每种任务看到了什么、预测了什么、梯度更新了谁。

## 从任务契约开始组织数据

“对齐”至少有三种含义：同一声音与文字的语义对应，音频/视频片段的时间对应，以及编码器特征与骨干输入空间的适配。一个数据集解决了其中一种，不代表另两种也正确。

| 任务 | 输入 | 监督目标与容易遗漏的字段 |
|---|---|---|
| 语音转写 | 波形或音频特征 | 文本；语言、有效时长、说话人等元数据 |
| 音频问答 | 音频 + 问题 | 回答；非语言声音也可能决定答案 |
| 音视频定位 | 帧、声音、时间戳 | 事件/片段；时间基准和抽帧策略 |
| 文本到语音 | 文本及可选音色条件 | codec 或连续声学表示；码本布局和有效帧 |
| 语音对话 | 用户流、历史与模型输出流 | 双方时间关系；停顿、重叠、打断及继续策略 |
| 条件图像生成 | 文本/参考图与噪声状态 | 噪声、速度等训练目标；时间采样和图像变换 |

样本应保留媒体身份、变换参数、目标区间、授权使用范围和数据版本，便于定位重复、泄漏与错误标签。训练/评估划分要考虑同一原视频的相邻切片、同一说话人或近重复图像，不能只随机打散文件名。

## 分阶段训练改变的是梯度路径

一种可分析的路线是先固定已有编码器与骨干、训练连接模块，再按任务解冻部分模块，随后加入更多生成任务及交互数据。这是设计选项，不是所有 Omni 模型必经的顺序。

“冻结参数”表示不更新该组权重。若编码器输入也不需要梯度，其输出可以停止反向传播并被缓存；若冻结的是位于两个可训练模块之间的模块，仍可能需要穿过它计算输入梯度。因此冻结不总等于整个模块无需反向计算。

用一个标量例子看清楚：编码器输出 `h=θx`，投影输出 `y=wh`，损失 `L=(y-target)²/2`。取 x=3、θ=2、w=0.5、target=1，则 h=6、y=3、L=2：

\[
\frac{\partial L}{\partial w}=(y-1)h=12,
\qquad
\frac{\partial L}{\partial\theta}=(y-1)wx=3.
\]

冻结 θ 后，投影梯度仍是 12，θ 不更新；解冻后 θ 才使用梯度 3。预先缓存 h 只在编码器、输入处理和增强固定时成立；给编码器加可训练 LoRA 也会改变 h，不能以“基础权重没动”为由继续用旧缓存。LoRA 的状态边界见[微调与后训练](预训练微调与后训练的系统边界.md)。

## Attention mask 与 loss mask 各管什么

Attention mask 限制模型可以读哪些位置；loss mask 决定哪些位置参与目标。把用户音频对应的标签设成不计损失，只是移除该位置的监督，不会阻止输出读取未来输入。如果训练能看完整音频、推理只能看过去片段，存在因果条件不一致。

Teacher forcing（教师强制）在训练时提供正确的历史目标，用来预测下一个目标。例如用 codec 帧 `c[t-1]` 预测 `c[t]`。多码本模型还需明确同一帧内哪些码本已可见；如果把正在预测的码本同时送入输入，会产生目标泄漏。文本和音频不同步时，不能仅把两串标签靠左对齐就认为任务定义完成。

padding 是为了张量对齐而补的无效位置，既不应计入有效目标分母，也不应被当作真实媒体时间。多样本 packing 还要隔离样本间的可见性；相关推导见[数据管线](数据管线与训练演进.md)。

## 损失归一化会改变任务权重

设文本有效位置 Nₜ=2，交叉熵总和 Sₜ=2；音频有效码本索引 Nₐ=8，交叉熵总和 Sₐ=16。交叉熵衡量对正确类别分配概率的好坏，这里只使用给定损失值讨论汇总方式。

按所有索引一起平均为 `(2+16)/(2+8)=1.8`。若先分别平均，再让两个任务各占一半，则为 `0.5×(2/2)+0.5×(16/8)=1.5`。前者隐含地给索引较多的模态更大权重；改变 codec 码本数就可能改变训练方向，即使音频秒数不变。

更一般地：

\[
L=\lambda_t\frac{S_t}{N_t}+\lambda_a\frac{S_a}{N_a}.
\]

Nₐ 可以选索引数、帧数或其他口径，但必须与论文/实现的目标一致。没有音频目标时，不计算 `0/0`；是否重新归一化剩余任务权重也是显式策略。分布式训练要先明确全局有效计数，不能随意平均各 rank 的局部均值。

用可微的独立例子验证梯度：`Lₜ=(w-1)²`，`Lₐ=(w+1)²`，w=0.5。等权任务平均的损失为 1.25，梯度为 1；按 2:8 的位置数加权则损失为 1.85，梯度为 2.2。脚本用有限差分复核这两种目标，说明差异会进入参数更新，而不仅是日志数字变化。

## 连续生成目标与离散目标并存

codec 索引通常可以使用离散分类目标，图像生成网络则可能学习噪声或速度。在[计算图篇](../02_Model_Architecture/Omni理解与生成计算图.md)的一维插值中，目标速度是 `data-noise=3`；若模型预测 2.5，平方误差为 0.25。这个数与文本交叉熵的量纲、分布和梯度尺度不同，直接相加之前应定义权重和归一化。

音频波形重建还可能涉及频谱与感知目标。不要仅因为不同模态都写成 loss，就认为它们可以按 token 数统一比较。应分别记录各目标、梯度尺度与任务质量，并检查某个模态是否压制其他模态。

## 采样和系统预算也要按任务核算

假设训练按样本数以 1:1 混合短文本与长音频。它既不保证监督位置各占一半，也不保证 GPU 时间各占一半。应记录样本、有效目标数、媒体时长/分辨率和估算计算量；按长度或 shape 分桶可减少 padding，但也可能改变任务的到达顺序。

音频解码、重采样、视频抽帧和增强常在 CPU 数据管线发生。GPU 等待数据时，先查供给和缓存，而不是立刻增加并行度。随机裁剪需要保留对齐标签；切到一句话中间却保留完整句子标签，会把预处理错误变成训练目标。

## 后训练要覆盖交互，而不只奖励转写

SFT 用示范行为训练；偏好或 RL 则需要定义什么输出更好。语音任务可分别观察内容正确、发音清晰、说话人一致、自然停顿、响应时间与打断处理。单一 ASR 转写分数可能鼓励“转写容易但韵律不自然”的声音；只奖励短延迟也可能鼓励过早回答或截断内容。

流式示范应标明当时已经到达的输入，哪些文本/音频已经交付，是否发生重叠和打断。离线完整对话不能直接当作全双工轨迹：模型可能从未来语句获得本不该知道的信息。对媒体生成，质量奖励还需防止只迎合某个评分器；独立人工/任务评估仍需保留。

若对离散 codec 动作做策略优化，行为概率必须对应实际采样的码本与 mask；不能拿同段 ASR 文本的概率代替 codec 动作概率。连续扩散动作的概率与目标另有定义，也不能直接套文本 PPO 的 token 公式。通用概率契约见[行为概率与异步校正](../11_RL_Systems/行为概率与异步校正.md)。

## 自测

**把 padding 的 loss 设成零，再除以补齐后的长度，正确吗？** 不一定。如果目标是有效位置平均，分母仍应排除 padding，否则短样本权重随补齐量变化。

**只用离线转写质量证明交互模型训练成功，缺什么？** 缺对流式可见上下文、播放连续性、打断、时序及生成质量的评估。下一篇[性能与质量评估](../12_Performance_Reliability/Omni性能与质量评估.md)把这些要求变成可测量的问题。
