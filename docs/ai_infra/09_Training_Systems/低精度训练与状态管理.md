# 低精度训练：计算、缩放与持久状态

> 前置：[浮点表示](../01_Math_Numerics/浮点数与低精度.md)、[一次更新](训练步与优化器.md)。这里解释通用状态与成本，不给所有硬件通用的 FP8/FP4 配方。

## 一次更新有多种精度

“FP8 训练”通常描述部分计算路径。它不直接说明优化器、通信或 checkpoint 的表示。

| 对象 | 精度选择影响什么 | 生命周期 |
|---|---|---|
| 前向权重和激活 | GEMM 吞吐、读取量与量化误差 | 一次执行或可复用副本 |
| 反向输入与中间结果 | 梯度误差、范围与 kernel 选择 | 前后向之间 |
| 梯度累加 buffer | 小梯度累计是否丢失 | 多个 microbatch |
| 梯度通信 | 带宽、归约误差与缩放顺序 | 一次 collective |
| 主权重和优化器矩 | 小更新与长期优化轨迹 | 跨成功更新 |
| scale、amax 等元数据 | 如何解释低精度值、下一次量化 | 取决于 scaling recipe |

例如 BF16 计算权重、FP32 主权重和两个 FP32 Adam 矩可以同时存在。把计算副本从两字节改成一字节，只减少这一份状态；激活、通信 buffer 和图内存还要单独计账。容量基础见[显存核算](../04_Memory_Storage/GPU内存组成与显存核算.md)。

## scale 是表示的一部分

本篇统一用反量化尺度 $s$ 表示 $x\approx s q$。示意量化为 $q=Q(x/s)$，其中 $Q$ 是目标格式的舍入和范围处理；有些 API 把 $1/s$ 称作 scale，阅读实现必须先核对方向。

设格式有限幅值上界为 $F$，张量最大绝对值为 $a$，忽略 margin 时可取 $s=a/F$。这是范围安排，不保证所有元素都有足够精度。全零张量还需定义非零安全尺度。

Per-tensor scaling 为整个张量使用一个尺度；per-channel 或 per-block scaling 增加局部尺度。后者可以减少局部分布差异的影响，却增加元数据、布局转换和 kernel 约束。不能只按“FP8/FP4”名称比较两种表示。

## Current 与 delayed scaling

Current scaling 先观察当前张量的 amax，再量化当前值；delayed scaling 使用历史统计决定本次尺度，并记录新统计用于后续执行。TE 的 [2.14 current scaling 说明](https://docs.nvidia.com/deeplearning/transformer-engine-releases/release-2.14/user-guide/features/low_precision_training/fp8_current_scaling/fp8_current_scaling.html)展示了观察、缩放、转换以及分布式 amax 同步的成本；[recipe API](https://docs.nvidia.com/deeplearning/transformer-engine/api/common.html)定义了 delayed scaling 的历史状态。current scaling 按 2.14 解释；recipe API 于 2026-10-12 核对为 2.20.2，配置应随实际安装版本再次核对。

若历史 amax 为 1、当前张量突然出现幅值 4，本次按历史设置的范围可能不足，具体饱和行为取决于转换实现。扩大范围能减少饱和，却让小值的有效精度更难保持。应观察饱和比例、层级误差和梯度，而不是只看是否有 NaN。

amax 的归约组由逻辑张量与通信契约决定：若多个 shard 要作为同一尺度的张量消费，就需要一致尺度；若每块保留自己的尺度，则必须一起传输对应元数据。把所有 rank 的统计无条件合并也可能改变 recipe。

## Loss scaling 与张量量化缩放

Loss scaling 将 loss 乘系数 $c$，反向得到 $c g$，更新前 unscale 恢复 $g$。张量量化尺度用于表示 $x\approx s q$。两者作用不同；更换张量尺度不能代替梯度裁剪前的 unscale。

在梯度累积、通信、非有限值检测和裁剪之间，需要保持统一顺序。FP16 某些场景需要 loss scaling，不代表 BF16、FP8 或 FP4 都应套同一规则。完整更新算例见[unscale 与 AdamW](<训练步与优化器.md#一次完整更新从缩放梯度到adamw与跳步>)。

## 重算、参数预取与 checkpoint

重算要满足同一量化语义：若再次执行前向时推进了历史统计，可能让用于反向的值偏离原前向；框架需管理 recipe 状态和 RNG。参数预取则要明确传输低精度副本还是主权重、谁产生尺度、何时转换与释放。

恢复是否保存 scaling history，取决于 recipe 与所声称的恢复精度。权重和 Adam 矩都相同，但历史尺度丢失，恢复后前几步仍可能与连续执行不同。Current scaling 没有同样的历史窗口，也不意味着配置、布局和其他状态可以省略。

| 改动 | 应保持的对象 | 新增成本与证据 |
|---|---|---|
| BF16 GEMM → 低精度 GEMM | shape、目标、容差定义 | 量化、转换与真实 kernel 时间 |
| 参数 gather 使用量化表示 | shard 与尺度相容 | amax 归约、尺度传输、转换 buffer |
| 低精度 + 重算 | 前后向所用 recipe/RNG | 重算时的统计推进和峰值内存 |
| 低精度 + 恢复 | 参数、优化器、必要精度状态 | 连续运行与恢复后的短程对照 |

逐层输出、梯度和一次更新对照用于发现局部错误；持续训练的 loss 与任务评估用于判断长期可接受性。速度比较包含量化开销，并固定 batch、并行布局和硬件。
