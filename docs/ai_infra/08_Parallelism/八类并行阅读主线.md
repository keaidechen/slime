# 八类并行：从瓶颈到机制、实现与代价

这是一张后续章节的地图，不要求第一次就记住八种实现。**并行度（degree）**表示多少个参与者共同分担某一类工作。先区分三件事：分数据让多个副本同时学习，分计算让多个设备完成同一个算子或模型，分状态让副本不必各存一整份训练状态。

| 缩写 | 全称与直觉 |
|---|---|
| DP / DDP | Data Parallelism / DistributedDataParallel，数据并行及其一种实现：同模型、不同数据 |
| ZeRO / FSDP | Zero Redundancy Optimizer / Fully Sharded Data Parallel，把重复的训练状态分开保存 |
| TP | Tensor Parallelism，张量并行：一起算同一层 |
| PP | Pipeline Parallelism，流水线并行：每个阶段负责不同层 |
| SP | Sequence Parallelism，序列并行：本书此处指在 TP 组内切分部分逐 token 运算的激活 |
| CP | Context Parallelism，上下文并行：拆分长序列，Attention 时交换必要信息 |
| EP | Expert Parallelism，专家并行：将 MoE 的不同专家放在不同设备 |
| ETP | Expert Tensor Parallelism，专家张量并行：进一步拆分单个专家内部的矩阵 |

分类不是八个独立设备轴。主线接下来依次手算 DP、TP、ZeRO/FSDP、PP；SP、CP、EP、ETP 是按模型需求进入的分支。

## 1. 一张问题表

表中的 AG/RS/A2A 分别是 AllGather、ReduceScatter、All-to-All；prefetch 是提前取数据，bubble 是设备因依赖而空等，unit 是一次参数展开的单元，FC1/FC2 是专家的两层线性变换。

设 `D/T/P/C/E/X` 分别为 dense DP、TP、PP、CP、EP、ETP degree；`H` 是 hidden size，`F` 是 FFN intermediate size，`S` 是序列长度。以下是定性/局部理论结果，不是实测加速比。

| 方式 | 出发点 | 怎么做 | 能期待的结果 | 代价或副作用 |
|---|---|---|---|---|
| DP/DDP | 单副本能训练，但数据吞吐不足 | 各副本处理不同样本，合并同一参数的梯度 | 扩大样本并发；固定全局 batch 时减少每副本工作 | 全模型状态仍复制；通信尾部；增大全局 batch 会影响优化过程 |
| ZeRO/FSDP | 参数/梯度/优化器副本冗余导致 OOM | 在数据并行域分片状态，必要时计算前 gather 参数 | 被分片的持久状态随组大小减少 | full-param、prefetch 峰值；AG/RS；小 unit 多次启动、大 unit 峰值高 |
| TP | 单层权重或计算太大 | 切单层矩阵维度，组合局部乘积 | 可分片矩阵参数约降为 `1/T`；分摊部分层内计算 | 高频 collective；GEMM 变小；复制项不随 T 缩小 |
| PP | 多层累计状态过大 | 不同 stage 保存不同层，流水执行 microbatch | 按层分摊状态；可缩小层内跨节点通信范围 | bubble、P2P、stage 不均；早期 stage 激活在途量大 |
| SP | TP 后 norm/residual 等激活仍重复 | 在 TP 组上切 token，TP 子图边界 AG/RS | 这些激活约降为 `1/T` | 完整输入临时 gather；norm 参数梯度仍要 TP SUM；不是独立 GPU 轴 |
| CP | 长上下文激活超限 | 切 token/context，attention 交换所需信息 | 局部 token/激活约降为 `1/C`，支持更长上下文 | KV 通信、causal 不均、packed 索引；参数本身仍复制 |
| EP | MoE 全部专家参数过大 | 将不同 expert 放到不同 owner，路由 token | 每个 owner 持有约 `N_experts/E` 个专家 | A2A、动态 split、热点、临时缓冲；drop 会改变训练语义 |
| ETP | 单个 expert 仍太大 | 同一 expert 的 FC1/FC2 沿 intermediate 切分 | 单 expert 可分片权重约降为 `1/X` | expert TP AG/RS；expert GEMM 更小；与 EP、EDP 共同竞争固定 rank 数 |

“约降为”只针对表中被切的项。峰值显存还包含 workspace、通信、保存的 activation、padding 与 allocator；不能用全模型显存直接除并行度。

## 3. 从单卡出发怎样选择

先测一次完整训练 step 的峰值，并区分构模、forward、backward、optimizer 四段。

- 模型能放下而吞吐不足：以 DP 为基线，保持目标 batch 定义清楚。
- 优化器状态占比大：先比较 Distributed Optimizer/FSDP；不要只因 OOM 就提高 TP。
- 单层矩阵大：看 TP；专家矩阵大：看 ETP，同时核对已有 EP degree。
- 层数累计状态大：看 PP，但先算 microbatch 数，防止容量问题解决后 bubble 成为主导。
- TP 后 norm 等激活仍大：看 SP；长 attention context 的激活大：看 CP。
- MoE 参数多：看 EP；检查每 expert token 数，避免扩卡后 GEMM 和网络效率下降。

这是定位流程，不是固定优先级。带宽、GQA/MLA、激活重计算、序列分布和 batch 约束都可能改变选择。

## 4. 两张网格，而不是一条八项乘法式

先看四卡例子，设 TP=2、DP=2。rank 0/1 合作处理数据批 A，rank 2/3 合作处理数据批 B；TP 组为 {0,1}、{2,3}，相同参数分片的 DP 同步组为 {0,2}、{1,3}。这里一共是两个数据副本，不是四个；SP 若沿现有 TP 组切激活，也不再乘一个独立卡数。

进阶：下面对应本仓库 [Megatron 源码快照](../13_Source_Analysis/megatron/02_parallelism/01_parallel_state_and_tensor_parallel.md)的标准 decoder 场景，W 是总 rank 数。Dense 指非专家层，expert 指专家层。同一批设备在两类层里可以使用不同的通信组划分：

```text
W = TP × CP × dense_DP × PP
W = ETP × EP × expert_DP × PP
```

`expert_DP`（EDP）复制同一 expert shard；ETP ranks 持有同一 expert 的不同 shard。SP 使用 TP group；FSDP/Distributed Optimizer 沿对应的数据复制域分片状态。CP ranks 合作处理同一条序列，因此 CP 不能当作新增样本副本计入 global batch。

具体八卡映射见 [ETP](ExpertTensorParallelism.md)。组顺序、整除和 PP groups 一致性要由 `parallel_state.initialize_model_parallel` 检查；上式不是任意模型/异构分布的充分可运行条件。

## 5. 最终结果要分三种证据

| 证据层 | 本仓库入口 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 数学/状态机 | `python3 docs/ai_infra/examples/parallel_runtime_walkthroughs.py` | 小例子的输出、梯度、调度依赖等成立 | 真实 backend、异步 stream、网络正确 |
| ETP 数学与两网格 | `python3 docs/ai_infra/examples/etp_reference.py` | ETP 切分前后输出/梯度一致，EP+ETP 重组保持 token 归属 | NCCL A2A、TE GroupedMLP 或 checkpoint 可用 |
| 多卡一步等价 | [真实执行的证据边界](../13_Source_Analysis/megatron/05_design_and_failures/03_parallelism_validation.md) | 指定环境/模型/路径下的实现对齐 | 任意组合都受支持、长程收敛或性能最优 |

性能评估另需稳态 step time、峰值 HBM、通信暴露时间和正确性基线。能启动、loss 有限、GPU utilization 高，都不能单独作为并行方案成功的结论。
