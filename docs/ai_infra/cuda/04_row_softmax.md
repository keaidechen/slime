# 4. 从求和归约到逐行 Softmax

[上一章](<03_debug_profile_and_slime.md>) · [目录](<README.md>) · [下一章](<05_materialized_attention.md>)

这一章只增加一个问题：**一行有多个值，如何让线程先协作得到共同的统计量，再分别写回结果？** 完整实现为 [attention_lab.cu](<examples/attention_lab.cu>) 中的 `warp_reduce`、`block_reduce` 和 `row_softmax`。

## 4.1 先在纸上计算一行

**Softmax 是把一组分数变成非负、和为 1 的权重的函数**。本章逐行独立计算：每行先求指数，再除以该行共同的指数和。它解决“如何把任意有限分数变成可比较的归一化权重”的问题；不是选出最大项下标的 argmax，较小项也可以获得权重。

直接除以原始分数和并不可靠：`[-1,1]` 的和为零，还含负数。先取指数可以把有限分数变成正数，再进行归一化。

对长度 C 的一行，令 x_j 为第 j 个 score（也叫 logit），j=0,…,C−1：

```text
Z = sum_{k=0}^{C-1} exp(x_k)
p_j = exp(x_j) / Z
```

`exp(x)=e^x`，e≈2.71828；`ln` 是它的逆运算，所以 `exp(ln(4))=4`。Z 是归一化常数，p 的形状与 x 相同，都是 `[C]`。这里 x、Z、p 都无量纲，指数的输入也必须无量纲。每个 p_j>0，且 `sum(p)=sum(exp(x))/Z=1`。将分数差增大，会改变指数之间的比例；把所有分数都加同一个常数则不改变比例。

**数值稳定化**是在数学结果不变的前提下，改写计算过程以避免溢出等问题。这里采用“先减去整行最大值，再求指数”。对有限输入 `x=[0, ln(2), ln(4)]`：

```text
m = max(x) = ln(4)
e = exp(x-m) = [1/4, 1/2, 1]
l = sum(e) = 7/4
p = e/l = [1/7, 2/7, 4/7]
```

减最大值不改变结果，因为分子、分母都乘上同一个 `exp(-m)`。它让指数输入不大于零，避免直接计算 `exp(1000)` 的溢出。算法因此分成三轮：求最大值 → 求指数之和 → 写归一化结果。每一轮必须使用整行共同的 m/l，不能各线程各自归一化。

把等价变换逐步展开，m 为本行最大值，l（小写字母 L）为平移后的指数和：

```text
p_j = exp(x_j) / sum_k exp(x_k)
    = [exp(-m)*exp(x_j)] / [exp(-m)*sum_k exp(x_k)]
    = exp(x_j-m) / sum_k exp(x_k-m)
    = exp(x_j-m) / l
```

只要至少一个有效输入有限，最大项的指数就是 1，其他项在 0 到 1 之间，因此实数计算中 `1<=l<=有效元素数`。这避免了指数溢出与分母为零；极小项在有限精度中仍可能下溢为零，稳定化不代表没有任何舍入误差。若每个线程分别选自己的 m，则共同因子不再相同：对 `[0,ln(4)]`，两线程各减自己的值会得到 `[1,1]`，归一化成 `[1/2,1/2]`，而正确结果是 `[1/5,4/5]`。

## 4.2 一条线程可以处理多个元素

**跨步分工**让线程按固定间隔处理多个元素，而不要求线程数等于列数。每条线程先把自己的元素合并成局部统计量，再由线程间归约得到整行统计量；这样固定大小的 block 也能处理较长的行。局部最大值只代表该线程负责的子集，不是整行最大值。

先用 32 线程的 block，即一个完整 warp，负责一行。线程 t 处理 `t, t+32, t+64, ...`。`cols=70` 时，线程 0 处理 0/32/64，线程 6 处理 6/38，最后一段只有 6 个有效元素。

源码中的第一轮是：

```cpp
float local_max = -CUDART_INF_F;
for (int j = t; j < cols; j += B)
    local_max = fmaxf(local_max, x[row * cols + j]);
```

`B` 是本次编译实例的线程数。没有元素的线程保留负无穷，它对取最大值没有影响。求和时对应的中性值是 0。**无有效数据的线程仍参与协作，只是贡献中性值。**

先用 4 个“工作者”模拟一行 7 个元素 `[0,ln(2),ln(4),0,ln(2),ln(4),0]`，不把它误当成真实 4-lane warp：

| 工作者 | 元素下标 | 局部最大值 | 共同 m=ln(4) 后的局部指数和 |
|---|---|---|---|
| 0 | 0、4 | ln(2) | 1/4+1/2=3/4 |
| 1 | 1、5 | ln(4) | 1/2+1=3/2 |
| 2 | 2、6 | ln(4) | 1+1/4=5/4 |
| 3 | 3 | 0 | 1/4 |

先合并第二列统计量得到 m，再合并最后一列得到 `l=15/4`，每个工作者才可给自己负责的元素写概率，结果为 `[1,2,4,1,2,4,1]/15`。局部循环缩短要在线程间交换的数据量，但它没有让局部统计量自动成为整行统计量。

## 4.3 shuffle：在线程寄存器之间传值

**warp shuffle 是同一 warp 内线程交换寄存器值的协作机制**。它让某个 lane 获得另一个参与 lane 的值，无需先通过 shared 中转；本节用它把各线程的局部统计量合并成 warp 统计量。它的作用范围是 warp，不能直接合并不同 warp 的值。

`__shfl_down_sync(mask, x, delta)` 让当前 lane 取得编号较大 lane 的 x；这里所有 32 个 lane 都执行，使用完整 mask `0xffffffffu`。例如 delta=16 时，lane 0 取得 lane 16 的值。它不需要先把 x 放进 shared。

```cpp
for (int delta = 16; delta > 0; delta >>= 1) {
    float other = __shfl_down_sync(0xffffffffu, x, delta);
    x = IsMax ? fmaxf(x, other) : x + other;
}
```

这是编译期参数 `IsMax` 控制的同一个归约结构。每轮距离减半，最后 **lane 0** 的值覆盖 32 个输入；其他 lane 的值不能当成完整结果。以 8 lane 的缩小示意来看，lane 0 先接上 4，再接上已包含 2/6 的 2，最后接上已包含 1/3/5/7 的 1。完整示例使用真正的 32 lane。

本实现的前提是完整 warp、所有 lane 在这些调用处共同参与；不能把 mask 原样复制进任意提前退出或分歧分支。shuffle 传的是参与线程的值，不替你完成任意 shared/global memory 的同步。API 约束见 [CUDA C++ Language Extensions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html)。

参与 mask 是一个 32 位整数，第 t 位声明 lane t 参与这次协作；`0xffffffffu` 的 32 位全部为 1。它不是“这个 lane 有几个输入”的标记。处理 7 个元素时，完整 warp 的后 25 个 lane 没有数据但仍可带着中性值参与；若让它们提前退出，再使用完整 mask，就不再满足本实现的协作前提。down 形式的归约只保证 lane 0 收齐结果；后续 shared 写回与广播才让整块线程获得同一个值。

## 4.4 四个 warp 怎样合成一个 block 的结果

**本节的 block 归约采用分层合并**：先在各 warp 内归约，再通过 shared 交接各 warp 的部分结果，最后合并并广播给整个 block。shuffle 只解决 warp 内交换，shared 与 block barrier 则解决跨 warp 的数据交接；这是本节选择的实现方式，不是所有 block 归约都必须采用的结构。

把 B 增大到 128，即四个 warp，按以下步骤得到同一个 block 结果：

1. 每条线程先归约自己的元素，然后四个 warp 各自得到一个结果。
2. 每个 warp 的 lane 0 写 `scratch[warp]`，得到四个 partials。
3. 全 block barrier 后，第一个 warp 的 lane 0..3 分别读取它们，其他 lane 填中性值。
4. 第一个 warp 再归约，lane 0 把最终值写回 `scratch[0]`。
5. 全 block barrier 后，所有线程读取 `scratch[0]`；再做一次 barrier，保护 scratch 被下一次归约复用。

第三道 barrier 看似多余，实际上避免快线程开始下一次归约、覆写 scratch 时，慢线程还未读走旧结果。这里选择容易检查的实现，不追求最少指令。

例如四个 warp 的局部和为 `[1,2,3,4]`，第一次 barrier 后第一个 warp 读取它们并得到 10，第二次 barrier 后四个 warp 各自将 10 读入私有变量。假如省略最后一道 barrier，快 warp 可能已开始求下一份统计量并写 scratch[0]，慢 warp 此时才读取“上一份结果”，于是读到新值。这是存储复用竞争，不是归约加法公式的问题。

硬件层次也正好贯穿这条路径：线程局部统计量通常在 SM 寄存器文件中；warp 内的 shuffle 交换参与 lane 的值；跨 warp 的四个 partial 通过该 block 的 16 字节 shared scratch 交接；最后用 block barrier 让所有 warp 看到结果。四个 warp 属于同一 block，因而在同一 SM 上协作；它们不是跨四个 SM 求和。32 线程版本的 scratch 则只有一个 float。

`block_reduce<B, true>` 求最大值，`block_reduce<B, false>` 求和。尖括号是 **C++ 模板参数**，例如 B=128 与 B=32 会生成不同的编译实例；括号里的 x/scratch 才是运行时参数。源码的 `static_assert` 要求 B 是 32 的倍数，launch 还必须真的启动 B 个线程。

## 4.5 完整 Softmax 的数据生命周期

这里的**数据生命周期**指某个中间值何时生成、何时可被使用、何时能覆盖或丢弃。Softmax 的最终输出依赖整行共同的最大值 m 和分母 l，因此必须先完成两次归约，再归一化；线程私有的局部值不能提前当作共同统计量。

| 阶段 | 线程私有值 | 整行共同值 | 是否可写最终 P |
|---|---|---|---|
| 扫描 x | local_max | 还没有 m | 否 |
| 最大值归约后 | 当前线程的元素 | m | 否 |
| 扫描 exp(x-m) | local_sum | m | 否 |
| 求和归约后 | 当前线程的元素 | m、l | 是 |

完整 kernel 重读输入来计算指数，容易理解但存在重复加载和求指数的成本。后续可以每线程保留多个寄存器值来复用；寄存器增长也会影响资源占用，不能默认这样一定更快。

对 R 行、C 列的非空 FP32 输入，该源码每元素在求 max、求和、写结果时各读取一次，并写一次输出，逻辑上共 `R*C*(3*4+4)=16RC` 字节；第二、三次扫描各计算一次 exp。硬件缓存可能避免重复 HBM 访问，但代码中的重复指数运算仍存在。若把指数值保留在线程私有存储，能少读一次并少算一次 exp，却需为每线程约 `ceil(C/B)` 个值提供存储。C 很大时可能增加寄存器压力甚至 spill；“融合”和“全部保留”都要受片上资源约束。

**mask（掩码）**指定哪些元素不参与归一化。本例将这些 score 写为 `-inf`，使其指数贡献为零。**全行都被 mask 时**，不能执行 `-inf-(-inf)`：本例在得到最大值后统一分支，把输出整行写零。这是教学接口约定，不是对“空集合上的 Softmax”套公式所得的概率分布。输入允许有限值及用于 mask 的负无穷；NaN/正无穷不在本示例支持范围内。

例如 `[0,-inf,ln(4)]` 的 m=ln(4)，指数为 `[1/4,0,1]`，结果 `[1/5,0,4/5]`；被 mask 项不占分母。若全为 `-inf`，所有线程在共同归约之后看到同一个最大值，因而可以一致进入写零分支并结束。它与“某些线程无输入就提前 return”不同：前者发生在共同统计量已获得后，后者会打断仍需全块参与的归约。

## 4.6 边界条件怎样暴露实现错误

Softmax 的**边界验证**要同时检查行长度、数值范围和有效元素集合：尾列会暴露索引和参与线程错误，大数会暴露稳定化错误，全 mask 行会暴露空行处理错误。下面用独立的高精度参考和这些输入，检查前面各阶段是否保持相同的整行语义。

从项目根目录编译与执行；环境要求沿用第 0 章：

```bash
nvcc -O2 -lineinfo -std=c++17 docs/ai_infra/cuda/examples/attention_lab.cu -o /tmp/slime_attention_lab
/tmp/slime_attention_lab
compute-sanitizer --tool memcheck /tmp/slime_attention_lab
compute-sanitizer --tool racecheck /tmp/slime_attention_lab
compute-sanitizer --tool synccheck /tmp/slime_attention_lab
```

程序也会执行后两章的 Attention。先只阅读 Softmax 部分即可。它比较 32/128 线程两种版本与 FP64 CPU 参考，覆盖 1、31、32、33、127、128、129、513 等列数，以及大正偏移、部分 mask、全 mask。

这几种输入揭示了不同的不变量：

| 输入或实现变化 | 数学与执行含义 |
|---|---|
| 输入 `[0,ln(2),ln(4)]` | 得到 `[1/7,2/7,4/7]` |
| 所有有限输入加 1000 | 权重应基本不变；直接 exp 原始分数会出问题 |
| 用 128 线程处理 7 个元素 | 121 个线程仍参与归约，不能提前 return |
| 只用线程私有 local_max 计算指数 | 各线程的指数基准不同，结果不再是整行 Softmax |

统计量沿“线程私有值 → warp → block → 每个线程”传播，各线程最终必须使用同一个行最大值与分母。GPU 示例尚需在目标机器编译和实测；本机的 CPU 检查不能证明这些 barrier 正确。
