# 5. 先实现一份普通 Attention

[上一章](<04_row_softmax.md>) · [目录](<README.md>) · [下一章](<06_online_attention.md>)

这一章将已有的矩阵乘和 Softmax 组合起来。完整实现仍在 [attention_lab.cu](<examples/attention_lab.cu>)，顺序为 `qk_scores → row_softmax → pv_output`。先固定一个 batch、一个 head，使用连续行优先 FP32 数据，无 dropout、无反向传播。

## 5.1 不跳过形状与下标

Attention（注意力）解决的是按内容汇总信息的问题：对一个待更新的位置，不是固定平均所有输入，而是先计算它与各候选位置的匹配分数，再按权重汇总候选携带的数据。query（查询）描述“当前要找什么”，key（键）用来参与匹配，value（值）是被汇总的内容。Q/K/V 在模型中通常来自输入的不同线性投影；本章直接把投影后的矩阵作为输入。

batch 表示独立样本的批次，head 表示一组独立的注意力投影与计算。先只处理一个 batch/head，可以避免这两个外层索引遮住内部的数学；不同 head 如何合并由模型后续操作决定。

| 张量 | 形状 | 一个元素的含义 |
|---|---|---|
| Q | `[Nq,d]` | query i 的特征 c |
| K | `[Nk,d]` | key j 的特征 c |
| V | `[Nk,dv]` | key j 对应的 value 通道 c |
| S、P | `[Nq,Nk]` | query i 对 key j 的分数、概率 |
| O | `[Nq,dv]` | query i 汇总后的通道 c |

首先算 `S[i,j]=sum_c(Q[i,c]*K[j,c])/sqrt(d)`，对每行 S 做 Softmax 得到 P，然后 `O[i,c]=sum_j(P[i,j]*V[j,c])`。公式中的 K 转置是为了让每个 Q 行与每个 K 行做点积；代码使用 `k[j*d+c]`，不需要先复制转置矩阵。

本章所有维度取正整数。这里 i∈[0,Nq) 是 query 行号，j∈[0,Nk) 是 key 行号，点积中的 c∈[0,d) 是特征号；区间 `[0,d)` 表示包含 0、不包含 d。输出公式中的 c 改为 value 通道号，范围为 [0,dv)。这两个通道维度不要求相等。写成形状链就是：

```text
Q[Nq,d] @ Kᵀ[d,Nk] -> S[Nq,Nk]
Softmax(S, 沿 key 维) -> P[Nq,Nk]
P[Nq,Nk] @ V[Nk,dv] -> O[Nq,dv]
```

为什么除以 sqrt(d)？先定义衡量数值波动的量：均值是平均水平，方差是“与均值之差的平方”的平均值，标准差是方差的平方根；E[·] 表示在所假设分布下取平均。用一个解释尺度的统计假设：各 Q/K 分量均值为 0、方差为 1，彼此独立，则一项乘积 q_c*k_c 的均值为 0、方差为 `E[q_c²]E[k_c²]=1`；d 个独立项相加，方差相加得到 d，标准差为 sqrt(d)。所有值除以 sqrt(d)，平方偏差就除以 d，方差变为 1，避免维度增大时仅因点积项数增多就让 Softmax 过度集中。例如 d=4 时标准差从 2 缩回 1，缩放系数为 1/2。

真实训练后的特征不必满足独立同分布假设；这里解释的是尺度选择的动机，不是关于任何输入的定理。也不是把点积变成余弦相似度：后者还要除以两个向量各自的长度。

用最小例子 `Q=[[1]]`、`K=[[0],[ln(3)]]`、`V=[[10],[20]]`：

```text
S = [0, ln(3)]
P = [1/4, 3/4]
O = [1/4*10 + 3/4*20] = [17.5]
```

Q 的行数决定输出多少行，V 的列数决定输出多少列。理解这一点后，再看 `Nq=3,Nk=7,d=5,dv=3` 的非方阵算例，避免所有维度碰巧相同而掩盖索引错误。

再把例子扩成两个 query、三个 key、两个 value 通道，保持每一步可手算：

```text
Q[2,1] = [[1],[0]]
K[3,1] = [[0],[ln(2)],[ln(4)]]
V[3,2] = [[1,0],[0,2],[3,1]]
S[2,3] = [[0,ln(2),ln(4)], [0,0,0]]     # d=1，缩放为 1
P[2,3] = [[1/7,2/7,4/7], [1/3,1/3,1/3]]
O[2,2] = [[13/7,8/7], [4/3,1]]
```

第一行第一通道是 `1/7*1+2/7*0+4/7*3=13/7`，第二通道是 `1/7*0+2/7*2+4/7*1=8/7`。第二个 query 全零，匹配分数相等，所以平均三个 value。K 决定“取多少”，V 决定“取来的是什么”；二者都有 Nk 行，是因为 key j 的权重必须乘同一个 j 对应的 value。

## 5.2 三个 kernel 分别拥有哪份输出

**输出分工**规定每个输出由哪个线程或 block 计算和写回；**数据依赖**规定后续 kernel 何时可以读取它。本节将 Attention 拆为分数 S、概率 P、加权输出 O 三个阶段，分别保存在 global memory 中，让两个问题可以独立检查。

`qk_scores` 的线程线性下标 `index` 拆为：

```cpp
int row = index / nk;
int key = index % nk;
for (int c = 0; c < d; ++c)
    value += q[row * d + c] * k[key * d + c];
```

这个线程拥有一个 S 元素，沿 d 做点积。第 2 章的 tiled GEMM 可以帮助理解后续复用；这里先保留最直接的标量实现，让张量之间的连接清晰。

`row_softmax` 的一个 block 拥有 S 的一行，最终写 P 的一行。`pv_output` 的一个线程拥有一个 O 元素，沿 Nk 累加。不同 kernel 在同一默认 stream 中依次启动，因此后者读取前者结果时，前者已经在设备执行顺序上完成；每两次 launch 之间不需要加一次 host 全设备同步。

```text
Q、K ── qk_scores ──> S（global）── row_softmax ──> P（global）
                                                    │
V ───────────────────────────────────────────────> pv_output ──> O（global）
```

这是数据依赖图；V 是 `pv_output` 的另一个输入，并不参与生成 P。

仍取 `[2,3]` 的 S，线性线程 index=4 得到 `row=4/3=1,key=4%3=1`，写 S[1,1]；计算 O[1,0] 的线程则使用 `index=1*dv+0=2`，它读 P 的整行与 V 的第 0 列。两处 index 虽然都线性编号，拆解时的“行宽”分别是 Nk 与 dv，不能交换。

在这条前向路径中，Q/K 的最后使用者是 qk_scores，S 的最后使用者是 row_softmax，P/V 的最后使用者是 pv_output，O 则供拷回或下游算子读取。从依赖上看，最后使用者完成后对应存储就能回收或复用；CPU 看到 launch 返回时还不能自行判定这个条件已经满足。配套驱动采用更简单的做法：先同步拷回并检查输出，再统一释放分配。若把后续 kernel 放入另一 stream，必须重新建立完成依赖。

## 5.3 mask 是分数计算的一部分

沿用上一章，**Attention mask**指定某个 query 允许访问哪些 key；**causal（因果）mask**进一步限制当前位置不能读取未来位置。它改变的是参与归一化的候选集合，因此必须在 Softmax 统计量形成之前生效。本节用可见 key 的前缀长度表示这种约束。

为了统一教学接口，`limits[i]` 表示第 i 行可见的 key 前缀长度：`0 <= j < limits[i]` 可以参与，其余 score 写为负无穷。

| 配置 | limits 的取法 |
|---|---|
| 全部可见 | 每行都是 Nk |
| 等长 causal | Nq=Nk，第 i 行为 i+1 |
| 全 mask 行 | 对应值为 0，约定 O 为零 |

例：长度 3 的 causal 对应 `[1,2,3]`，第 0 行只看 key 0。不能先对整行完成 Softmax，再把未来位置的概率直接清零：那样剩余概率的和一般不为 1。应先 mask，再确定 m/l。

例如自回归语言模型在第 i 个位置只能访问 0…i。对前面分数 `[0,ln(2),ln(4)]`，若 `limits[0]=2`，有效指数比例应是 `[1,2,0]`，正确 P=`[1/3,2/3,0]`，对应 O=`[1/3,4/3]`。若先对三项归一化再清零，只剩 `[1/7,2/7,0]`，和为 3/7，输出也被错误缩小。数学上再做一次正确的归一化可以补救非空行，但实现通常直接在求统计量之前 mask，避免多一轮工作及空行问题。

这里的 prefix 接口不表达任意稀疏 mask。**长度不等的 causal 对齐也不在本例约定内**；真实 FlashAttention 的右下对齐由现有 [变长与 KV cache 导读](<../appendices/source/flash_attention/04_backward_varlen_kvcache.md>)解释。

## 5.4 三个 kernel 为什么还不是 FlashAttention

**物化中间矩阵**是把完整 S/P 写入 global memory，供后续 kernel 读取。**FlashAttention** 则通过分块、在线归一化与片上复用，避免保存完整 S/P，减少显存占用和数据读写，同时保持同一稠密 Attention 数学定义。把三个普通 kernel 依次启动，只实现了计算阶段，还没有实现这种数据组织方式。

S 和 P 各有 `Nq*Nk` 个 FP32 数，各占 `4*Nq*Nk` 字节。取 Nq=Nk=4096，各为 64 MiB，两张共 128 MiB，尚未计 Q/K/V/O。这个数字与 FP16 的 32 MiB/张不同，讨论容量时必须标明 dtype。

容量和流量要分别数。若理想化为 S/P 各完整写一次、读一次，它们就产生 `4次×4字节×Nq×Nk=16NqNk` 字节的中间访问，上述规模为 256 MiB；而当前教学 Softmax 实际重读 S 三遍，PV 的不同输出线程还会重读 P，逻辑访问会更多。缓存可能吸收其中一部分，不能把这些计数直接当作 HBM 实测值。输入输出 Q/K/V/O 的容量则为 `4*(Nq*d+Nk*d+Nk*dv+Nq*dv)` 字节；序列增长时，S/P 的二次项往往先成为问题。

dense（稠密）Attention 指每个 query 与所有允许的 key 配对。两次矩阵乘的主工作量分别约为 `2NqNk*d` 与 `2NqNk*dv` FLOPs，合计 `2NqNk*(d+dv)`，还没计 Softmax。把三段融合进一次 kernel 可以减少启动和中间存取，但它仍要解决整行分母的依赖；仅删掉 S/P 分配而不重组算法，后续就失去了所需输入。

除了存储容量，还存在 S 写出和读入、P 写出和读入。我们希望把当前小块 S 用完即丢，而不是存整张矩阵；障碍在于 Softmax 的分母依赖整行。下一章解决的正是“没有同时拿到整行，怎样仍算出相同的归一化结果”。IO 出发点可参考 [FlashAttention 论文](https://arxiv.org/abs/2205.14135)。

## 5.5 输出的不变量与参考实现

**不变量**是正确实现必须保持的关系，用于在具体输出之外检查算法。例如重复一个 query 应重复对应输出行；改变 V 不应改变由 Q/K 决定的权重。参考实现给出数值答案，不变量则帮助定位形状、归一化或地址计算中的错误。

[CPU 参考](<examples/attention_cpu.py>)给出这些关系的数值对照：

```bash
python3 docs/ai_infra/cuda/examples/attention_cpu.py
```

有 GPU 时使用上一章的 `attention_lab.cu` 编译命令。CUDA 示例中的 CPU 参考用 double 累加每一行分数并一次性归一化，分别核对普通与在线两条 GPU 路径，避免只比较两份可能犯同一个错误的 kernel。

| 条件 | 输出关系 |
|---|---|
| 前文两个 key 的算例 | 输出 17.5 |
| 将 Q 行重复一次 | 对应 O 行也重复 |
| 改变 V，保持 Q/K 不变 | P 不变，O 改变 |
| 给所有 V 元素加常数 c | 每个非空输出通道加 c，全 mask 行仍按约定为零 |
| 读取 `k[key*d+c]` 而非 `k[c*Nk+key]` | K 实际按 `[Nk,d]` 行优先保存，数学转置不等于更改实际 stride |

这些关系分别约束形状、归一化与地址计算。下一章保持相同数学语义，改变中间状态的存储方式。
