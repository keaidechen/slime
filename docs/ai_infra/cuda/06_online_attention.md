# 6. 将普通 Attention 改成分块在线计算

[上一章](<05_materialized_attention.md>) · [目录](<README.md>) · [下一章](<07_mma_and_cute.md>)

这一章先推导状态更新，再对应 [attention_lab.cu](<examples/attention_lab.cu>) 的 `online_attention`。它是**用于理解 FlashAttention 核心算法的简化 CUDA 实现**：每个 block 处理一个 query，FP32 标量运算，不使用 Tensor Core，也不实现 FA2 的线程分工和性能优化。

## 6.1 为什么不能分别对每块做 Softmax

**分块在线 Attention**逐块读取 key/value，在每轮更新有限的统计状态，最后得到整行归一化输出，无需同时保留全部分数。这里 online 指算法按块增量更新，不意味着在线训练，也不意味着每块能独立给出最终答案。要保持第 5 章同一个 Attention 定义，各块必须共享一个整行归一化关系。

两块分数分别为 `[0,ln(2)]` 和 `[ln(4),ln(8)]`，分别 Softmax 都得到 `[1/3,2/3]`。拼起来的权重和为 2；即使再平均，也错误地赋予两块相同的总权重。真正的整行权重是 `[1,2,4,8]/15`，第二块权重总和应为 12/15。

所以每块不能只留下归一化后的局部输出；还要保存它在整个归一化过程中所占的“量”。

我们仍会访问每个有效 key，只是把“先保存全部 score 再求结果”改成“不断合并充分的统计量”。

## 6.2 用三个状态完整描述已经处理的 key

**在线状态**是丢弃旧分数后，仍足以继续合并新块的信息。这里保存最大值 m、平移后的指数和 l，以及同一基准下的加权分子向量 a。m 用于数值稳定，l 保留旧块的权重总量，a 保留旧块的输出贡献；少了后两者，只剩局部概率就无法恢复各块在整行中的相对权重。

对已处理的 key 集合，三个状态的精确定义为：

```text
m    = 当前最大的 score
l    = sum(exp(score-m))
a[c] = sum(exp(score-m) * V[key,c])
```

这里 a 是未归一化的输出向量；处理完所有 key 才输出 `a/l`。当新块使最大值从 m 升为 m_new，旧的每个指数必须换基准：

```text
exp(score-m_new) = exp(score-m) * exp(m-m_new)
```

定义 `alpha=exp(m-m_new)`，则：

```text
m_new = max(m, 当前块最大值)
p[j]  = exp(当前块score[j] - m_new)
l_new = alpha*l + sum(p)
a_new = alpha*a + sum_j(p[j]*V[j])
```

旧分母和旧分子必须一起缩放。p 是相对于共同基准的指数权重，尚未归一化；不能因为变量名像 probability 就认为它的和为 1。

为了确认三个状态已经足够，令 A 为已处理的有效 key 集合，T 为新块，两者不重叠；s_j 是缩放后的标量 score，V_j 形状为 `[dv]`。m/l 是标量，a 形状为 `[dv]`。score、指数权重和 l 无量纲；若 V 有某种数值单位，a 与最终输出保持该单位。以共同的新最大值 m′ 重写旧块分母：

```text
sum_{j∈A} exp(s_j-m′)
 = sum_{j∈A} exp((s_j-m)+(m-m′))
 = exp(m-m′) * sum_{j∈A} exp(s_j-m)
 = alpha*l
```

分子第 c 个分量同理，因为 alpha 不依赖 j，可以从求和中提出：

```text
sum_{j∈A} exp(s_j-m′)*V[j,c] = alpha*a[c]
```

再分别加上新块 T 的贡献，就得到上面的更新式。处理后的状态仍恰好描述集合 A∪T，所以对每块重复这个过程，最后的 `a/l` 就是整行结果。这是一个逐轮保持的数学不变量。因为 m′≥m，alpha∈[0,1]：新最大值不变时 alpha=1，变大时才需要缩小旧贡献。实现丢弃旧 score 后仍能正确更新，靠的正是这个共同缩放因子。

## 6.3 两轮完整算例，以及一个故意算错的版本

这一算例验证**换指数基准时，旧分母和旧分子必须一起缩放**。先算正确的两轮状态，再只改变这一条规则，观察错误来自哪一轮；它不是另一种 Attention 定义，也不能通过调整浮点容差补救。

继续取 scores=`[0,ln(2),ln(4),ln(8)]`，V=`[1,2,3,4]`，每块两个 key：

| 时刻 | m | alpha | l | a |
|---|---|---|---|---|
| 初始 | -inf | — | 0 | 0 |
| 第一块后 | ln(2) | 0 | 1.5 | 2.5 |
| 第二块后 | ln(8) | 1/4 | `1.5/4+1.5=1.875` | `2.5/4+5.5=6.125` |

最终 O=`6.125/1.875=49/15≈3.266667`。如果第二轮忘了缩放旧状态，就得到 `l=3, a=8, O≈2.666667`。这不是小的浮点误差，而是算法改变了。

表里的数来自以下步骤。第一块相对 ln(2) 的权重为 `[1/2,1]`，故 `l=1/2+1=1.5`、`a=1/2*1+1*2=2.5`；第二块把基准升至 ln(8)，`alpha=exp(ln(2)-ln(8))=1/4`，本块权重仍为 `[1/2,1]`，其分子贡献是 `1/2*3+1*4=5.5`。在最终共同基准下，全部四项权重实际上是 `[1/8,1/4,1/2,1]`，所以 `l=15/8`、`a=49/8`，除法后共同的 1/8 消掉。

多通道只把 a 变成向量，不增加分母个数。令同一组分数对应的 `V[4,2]=[[1,10],[2,0],[3,0],[4,10]]`：第一块 a=`[2.5,5]`，第二块贡献 `[5.5,10]`，最终 a=`[6.125,11.25]`，O=`[49/15,6]`。所有通道使用相同的 l=1.875，因为它们共享同一行 Attention 权重。

反过来先处理第二块，则先得到 `m=ln(8),l=1.5,a=5.5`；再处理第一块时最大值不变，alpha=1，新权重 `[1/8,1/4]` 贡献 l=0.375、a=0.625，最后仍得到 l=1.875、a=6.125。顺序不改变实数结果，但浮点数有限精度下仍须用容差比较。

[attention_cpu.py](<examples/attention_cpu.py>) 会打印这两轮 m/alpha/l/a，也会运行这个故意遗漏缩放的反例。参数 `rescale=False` **只用于演示错误**，不应作为正常算法选项。

## 6.4 把数学量分配给 CUDA 线程

**状态到线程的映射**决定谁计算、保存和更新每个数学量，以及谁需要读取它。公式里的标量或向量没有天然绑定某个线程：本例让行统计量通过 shared 协作，让输出分子按通道分给线程，以便跨轮保留而不重复写 global。

本例 `THREADS=128`，每个 block 拥有一个 query 行：

| 量 | 谁持有 | 生命周期 |
|---|---|---|
| 当前 tile 的 score | 线程 t 的寄存器，对应 key=base+t | 当前一轮 |
| m、l、alpha | shared 标量，线程 0 更新 | m/l 跨轮保留 |
| 当前 tile 的 p | shared `weights[128]` | 当前一轮，PV 读完后可覆盖 |
| a 的第 c 个通道 | 线程 c 的局部 `numerator` | 跨轮保留，最后除以 l |

前半轮 t 代表 key 列，后半轮 t 代表输出通道。**线程的任务由代码阶段决定，不是固定绑定一个数学维度。** 这也是理解真实 FA2 搬运和计算分工不同的第一步。

本实现限制 `1 <= dv <= 128`，从而每个有效输出通道恰好对应一个线程；d 由点积循环处理，Nk 可以超过一个 tile。更大的 dv 需要每线程持有多个输出，不能只改输入尺寸。

对应 [硬件与存储图](<01_execution_and_memory.md#memory-paths>)，四个 warp 在同一 SM 上共同维护这一行：score/numerator 是线程私有状态，weights 和 m/l/alpha 用 block 的 shared 交接，Q/K/V/O 则是 global 数据。源码中显式 shared 数组与标量合计 `128*4 + 4*4 + 3*4 = 540` 字节，实际编译分配仍可能有对齐等差异。这里省去整张 S/P 的 global 存储，却没有消除片上状态的成本。

一个 block 只有一个 query，因此 grid 只有 Nq blocks。Nq 很小时，即使 Nk 很长、每个 block 工作很多，也不一定能让很多 SM 同时忙碌。这说明“算法正确且省显存”不等于“硬件并行度足够”，也为第 9 章比较 FA2 的工作划分做准备。

## 6.5 沿 kernel 跑一轮

**一轮在线更新**先生成当前块分数，再建立共同指数基准，合并分母与分子，最后确认临时存储可以复用。数值步骤之外，每次交接还必须满足写完再读、读完再覆盖的执行依赖。下面按第 6.4 节的分工追踪同一个 block：

1. 线程 t 计算 `Q[row]` 与 `K[base+t]` 的点积，乘 `1/sqrt(d)`。无效 key 提供 `-inf`。
2. `block_reduce<THREADS,true>` 得到 tile 最大值。整块全无效则所有线程一起跳过这一轮。
3. 线程 0 更新 m/alpha，全 block 同步后大家使用同一个基准。
4. 每线程计算一个指数权重，写 `weights[t]`；再次归约得到 tile_sum。
5. 线程 0 更新 l；线程 c 将自己的 numerator 乘 alpha，再累加本块 `weights[j]*V[base+j,c]`。
6. 全 block 同步，保证 weights 的读者结束，才允许下一轮覆盖。

`block_reduce` 内部的 barrier 也使 weights 的写入在第 5 步可见；若以后重写 helper，不能只保留数值归约而忽略这一同步依赖。检查一个 barrier 时，要列出它前后的内存读写，而不是只看它离哪行代码最近。

初始 m=-inf。第一块非空时新最大值有限，alpha=`exp(-inf)=0`，正确丢弃初始零状态。全 mask 块被跳过，因此不会出现 `-inf-(-inf)`；全 mask 行最终 l=0，按接口约定输出零。这里假设有效 score 有限。

把第一轮缩成两个有效 key，其余 126 个线程提供中性值：线程 0/1 各算一个 score，归约得到 ln(2)，线程 0 发布 m 与 alpha；线程 0/1 写 weights[0/1]=1/2、1，其余写零。若 dv=2，只有线程 0/1 持有两个通道的 numerator，但全部 128 个线程仍执行归约和 barrier。末尾同步保护的不仅是 weights，还包括下轮可能更新的 alpha；不能让快线程发布新 alpha 时，慢线程还在按旧轮重缩放。

`valid=false` 时权重必须为零，边界之外的 K 地址不读取。当前 PV 循环仍可能读取 Nk 范围内、但被 prefix mask 屏蔽的 V，并乘零，因此本教程要求 V 是有限数；不能用“乘零”来掩盖非法地址或 NaN。无效线程和无效数据分别由控制流与中性值处理，两者都要正确。

## 6.6 改掉了哪些内存需求

**内存需求**要分别统计完整 global 张量、当前 tile 暂存和跨轮状态。在线算法省掉的是完整 S/P 的物化存储；为实现分块，它仍要保留当前权重、行统计量和输出累加器。本节比较的是这些数据的容量与生命周期，不预先断言哪个实现更快。

在线 kernel 不接收 S/P 指针，不为整张分数或概率矩阵分配设备存储。它读取 Q/K/V，保存当前 tile 权重和跨轮状态，最后只写 O。

示例驱动 `check_attention` 为了在同一次运行中比较两种实现，**仍然为普通版本分配了 S/P**。观察整个进程显存时不会看到这两块消失；要比较峰值显存，需要分别运行两条路径并去掉不使用的分配。

我们也没有减少完整 dense attention 所需的有效 Q/K 配对，更没有证明这个朴素在线 kernel 比优化库快。它的目的在于隔离算法：先确保分块和归一化正确，再优化指令与数据搬运。

从增长趋势看，一行不再需要 Nk 个 score 和 Nk 个概率都驻留在 global，而是保留当前 tile 的 T 个权重、dv 个 numerator 以及几个标量。若把同时处理的 query 行数记为 Bq、key 块高记为 Bk，后续高性能实现还要容纳 Q `[Bq,d]`、K `[Bk,d]`、V `[Bk,dv]`、当前 score `[Bq,Bk]` 和输出累加 `[Bq,dv]`；它们分布在 shared 与寄存器中，不能简单相加后全算作 shared。Bq/Bk 增大能增加复用，也会增加驻留状态、尾块浪费和同步压力。

本章的一 query/block 实现仍让多个 block 重复读取 K/V，并用标量循环计算点积和 PV。省去完整中间矩阵是算法层的收益；让许多 query 复用同一 K/V tile、使用 Tensor Core、减少归约与隐藏搬运延迟，则是后续独立的实现工作。

## 6.7 分块、遍历顺序与缩放的不变量

这里的**算法不变量**是：m/l/a 始终描述已经处理的有效 key 集合，非空行最终的 a/l 对应同一个整行 Attention，空行则沿用输出零的约定。改变分块大小或遍历顺序，在实数计算中不应改变答案；浮点计算仍用容差比较。下面据此检查实现，再引出可保存归一化信息的 LSE。

| 情形 | 结果及原因 |
|---|---|
| tile 大小为 1、2、7、32、128 | 与一次性归一化的参考在容差内一致 |
| 反向遍历 tile | 实数算法相同，浮点结果允许微小差异 |
| 输入包含全 mask 行、尾块和不同 dv | 空行输出零，边界不越界，输出 shape 不变 |
| 只缩放旧 l，不缩放旧 a | 分子分母使用不同指数基准，输出失去正确归一化 |
| 逐轮的 m/l/a 状态 | 能定位第一次偏离参考状态的轮次 |

CPU 脚本已包含分块尺寸/顺序组合验证。GPU 示例包含 Nk=129/257 的尾块、dv=17/128、等长 causal 和全 mask 行；还单列了最后一块最大值突然增大的例子：前 128 个 score 为 0、V 为 1，最后一个 score 为 ln(128)、V 为 3，正确输出为 2，以检查 GPU 代码是否同时缩放旧分子与分母。编译和 Sanitizer 命令见第 4 章。

### LSE：用一个标量保存归一化信息

**LSE（log-sum-exp，指数和的对数）**是整行未平移指数和 Z 的自然对数。它把 Softmax 的归一化常数存成一个标量：以后重新算出某个 score，就可以恢复对应权重，而不用保存整张 P；反向传播重算等场景可以利用这一点。本章 GPU 示例只输出 O，没有保存 LSE。

由 `Z=sum(exp(s_j))=exp(m)*l`，取自然对数得到 `LSE=ln(Z)=m+ln(l)`。上面四个 key 的例子中，`LSE=ln(8)+ln(15/8)=ln(15)`；以后重算某个 score s_j，就能用 `exp(s_j-LSE)` 恢复它的归一化权重。

若没有有效 key，数学上 Z=0、ln(Z)=−inf，输出 O 则仍按教学接口约定为零。实际库可能为特殊路径保存另外的哨兵值，不能把非空行推导直接套到空行的内部存储约定；第 9 章固定无 mask 的非空输入来对照实现。

在线状态更新始终围绕最大值、分母和加权分子三个量展开。接下来的 Tensor Core、CuTe 和流水改变执行方式；阅读时始终保留这三个状态作为算法对照。更多数学及 LSE 推导见 [在线 Softmax 导读](<../appendices/source/flash_attention/01_algorithm_and_online_softmax.md>)，它也说明真实代码的 `exp2`、scale 与延迟分母归约。
