## 1. RL 数据与数值正确性：系统优化前先确定等价关系

> 前置：[PPO/GRPO 的目标与算例](<25_RL目标与系统角色.md#s2>)。Tensor 是带形状的多维数值数组；DP 是数据并行，不同进程处理不同样本再合并梯度；prefill 是处理已知输入，decode 是逐步生成。目标：把算法目标写成分布式执行中的不变量。


<a id="s1-一个样本至少有四种身份"></a>

### 一个样本至少有四种身份

样本不仅是 prompt 和 response。需要分清逻辑 sample id、token 序列、生成时的 policy version，以及消费它的 training update。多轮任务还可能包含多个生成片段、环境动作和不同版本。

先画这条链：

```text
prompt/template/tokenizer
  → 行为策略生成 response + 行为 logprob
  → reward/filter
  → packing/mask/advantage
  → 当前策略前向与 loss
  → optimizer update
  → 导出与换权
```

任何优化若改变链中一步，都要列出哪些数学量保持不变，哪些只是允许在容差内变化。

例如同一道题生成三条回答，逻辑身份为 `(题目7,组2,候选0/1/2)`。候选 1 的评分请求超时重试，可以有两个评分 attempt，但仍只有一条候选回答；这条回答被拆成两个训练片段，也仍只有一个逻辑 rollout。反之，再独立采样一次相同文本属于另一次尝试。文本相等、执行次数相等和训练权重相等没有必然关系。

生成 worker 应把原始 token、行为概率和结束原因固定下来，判分 worker 给它附上带版本的结果，batch 构造器再决定 mask 和归约分母。数组可以从 GPU 搬到 CPU、对象存储或文件，但关联关系不能依赖临时的行号。若按长度排序以减少 padding，就要让奖励、概率、mask 和身份一起用同一个置换重排；只排序 token 会得到形状正确却语义错误的 batch。


<a id="s1-平均-loss-的平均通常不是全局-token-mean"></a>

### 平均 loss 的平均通常不是全局 token mean

rank 0 有 2 个有效 token，loss 为 `[1,3]`，local mean 是 2；rank 1 有 1 个有效 token，loss 为 `[9]`，local mean 是 9。

- 平均两个 local mean：`(2+9)/2 = 5.5`。
- 全局 token mean：`(1+3+9)/3 = 13/3`。

两个目标不同。PPO/GRPO 的具体实现也可能有 sequence mean、group mean 等目标，所以第一步是确认目标定义，不能见到不等长就擅自改为 token mean。

若目标确实是全局 token mean，先在每个 rank 把有效位置的损失相加，记为 $S_r$；再汇总有效 token 数，得到全局分母 N。若各自除以本地长度后直接按 rank 等权平均，就会让只有一个 token 的 rank 与拥有多个 token 的 rank 获得相同总权重；要从本地均值还原全局 token 均值，仍需按有效数量加权。

还要考虑 DDP 已经对 D 个参与者的梯度做一次平均。因此本地反向目标设为 $L_r=D S_r/N$，最终得到

$$\frac1D\sum_r\nabla L_r
=\frac1D\sum_r\frac D N\nabla S_r
=\frac1N\sum_r\nabla S_r.$$

乘 D 的作用是抵消后面的 rank 平均。回到两卡例子，$D=2,N=3$，本地目标值分别为 $2(1+3)/3=8/3$ 与 $2\times9/3=6$；取 rank 平均得到 $13/3$，与全局 token mean 相同，梯度也按上式采用相同权重。若本地只除以 N 而不补偿 D，最终梯度会额外缩小到目标的 1/D。

这里假设普通 DDP 梯度平均，没有额外的 microbatch、CP 或框架缩放；实际 Megatron/slime 必须把那些因子一起推导。用于日志的 detached sum/count 规约，也不能自动替代训练梯度路径。

DDP 是 DistributedDataParallel（分布式数据并行），rank 是通信组内的进程编号；这里 $D$ 是参与平均的进程数，$S_r$ 是第 $r$ 个进程上的损失和，$N$ 是整次更新的有效 token 数。若先把一批拆成若干 microbatch（用于控制峰值显存的小批次），应将 $S_r=\sum_k S_{r,k}$、$N=\sum_{r,k}N_{r,k}$ 放回同一公式；每个小批次反向 $D S_{r,k}/N$，累积后才更新。若每个小批次都按自己的 token 数取均值，目标就变成小批次等权。

教学例：一个进程分两次处理 `[1,3]` 和 `[9]`，两次分别按整步分母 3 贡献 $4/3$ 和 $9/3$，合计 $13/3$；先求均值再平均则得到 5.5。若框架还自动除以累积次数 2，须在其约定下补偿，不能重复除。全局分母可先从 CPU 上的 mask 统计，再在正确通信组中求和；含上下文分片或复制时只计唯一有效动作，不能把副本也加进去。

某个 rank 本地没有有效 token，不意味着它能自行退出本轮：其他 rank 可能仍需它参与集合通信。应贡献相容的零梯度并遵守训练器协议；若全局 $N=0$，则没有定义本次均值，应由所有参与者一致跳过或按明确规则处理。只在分母加小常数会掩盖“这一轮根本没有训练数据”。

运行纯 CPU 算例：[loss_normalization.py](<../examples/loss_normalization.py>)。


<a id="s1-mask-是训练目标的一部分"></a>

### Mask 是训练目标的一部分

至少区分 padding mask、attention mask、response loss mask，以及 partial rollout 中不参与本次 loss 的旧片段。它们不一定是同一个 tensor。

例如 `[prompt,prompt,response,response,pad]` 中，loss mask 可以是 `[0,0,1,1,0]`，但 attention 还需要表达可见上下文。不能为了少算 prompt 的 loss 就让 response 看不到 prompt。

检查项：shift 后 token 与 logprob 是否对齐；EOS 是否计入；截断与正常结束如何区分；全零 mask 分母怎么处理；packing 后样本边界是否泄漏 attention。

可以把 mask 的作用看成两个不同问题。Loss mask 的形状通常对应预测位置 `[B,T]`，回答“哪项损失计入目标”；概念上的 attention 可见性为 `[B,T,T]`，回答“每个位置可读哪些先前位置”，实现可用长度、分块描述或融合内核表达而不显式存储矩阵。Prompt 的 loss mask 为零，并不使它从 attention 图中消失。

把两个独立样本 `[p,a]`、`[q,b]` 打包成 `[p,a,q,b]` 时，第二个样本的 `b` 应看到 `q`，不应看到第一个样本的 `p,a`。单纯使用整个长度 4 的下三角因果 mask 会让 `b` 读到前一题。正确的独立样本 packing 要保留分段边界，使概念上的 attention 矩阵成为两个因果小块；还须按模型规则处理位置编码。这里减少的是 padding 浪费，并没有授权样本之间共享语义上下文。

Mask 也不是数值清洗器。假如工具位置缺失 logprob 而填了 NaN，先求指数或损失、最后乘零，仍可能得到 NaN，因为浮点运算中 `0 * NaN` 不是 0。应先只选有效位置计算，或在进入危险运算前按明确约定放入有限占位值；有效动作缺失概率则必须拒绝或有依据地补齐。


<a id="s1-行为-logprob-与当前-logprob"></a>

### 行为 logprob 与当前 logprob

重要性比值需要明确 numerator 和 denominator：一个来自正在优化的策略，另一个来自产生动作的行为策略或算法约定的旧策略。重新用当前权重算一遍，并不自动等价于生成时的行为 logprob。

温度、top-p/top-k、tokenizer/template、MoE 路由、精度和参数版本都可能影响对齐。返回更多 metadata 有助于追溯，但不保证恢复“完整随机性”或严格 on-policy；应按实际采样分布和算法定义验证。


<a id="s1-权重同步的正确性要拆成三层"></a>

### 权重同步的正确性要拆成三层

| 层次 | 要验证什么 | 例子 |
|---|---|---|
| 表示 | 名字、shape、dtype、shard 是否正确 | QKV 拼接顺序、TP 分片往返 |
| 发布 | 所有需要的 rank 是否完成，何时恢复请求 | 更新失败时不能仅更新 version 标签 |
| 语义 | 请求、KV、采样配置与权重是否匹配 | 旧 prefix KV 是否需要失效 |

暂停生成、abort 和换权出现在同一接口中，不代表跨进程事务或失败自动回滚。当前源码保证与生产层希望达到的目标必须分开写。


<a id="s1-局部数值一致与长期质量"></a>

### 局部数值一致与长期质量

小 batch 对齐用于发现 shape、mask、缩放与版本错误；若更改了异步程度或采样策略，还需要更长运行检查 reward/评估质量。短程 loss 正常不能证明长期训练等价，吞吐增加也不等于 time-to-quality 改善。

一个可操作的对齐顺序是：固定一份 token/组身份记录，先比每个有效位置的 logprob，再比优势和逐 token 损失，随后比全局分子/分母，最后比参数梯度。总 loss 恰好接近时，两处相反错误可能抵消；只比总数定位不了错位。绝对误差 $|x-y|$ 与相对误差 $|x-y|/\max(|x|,|y|,\epsilon)$ 也不能代替身份检查。容差应根据 dtype、规约顺序和任务敏感性确定，而不是对所有张量统一采用一个宽松阈值。


<a id="s1-目标与状态如何同时闭合"></a>

### 目标与状态如何同时闭合

两个 rank 的 token 数不同，先求局部平均再平均 rank 就会改变 token 的权重。对一条包含 prompt、回答、EOS 和 padding 的轨迹，token、logprob 和 mask 的对齐决定分子和分母实际在统计什么。

权重发布成功时，请求与缓存需要进入相容版本；中途失败则可能留下部分已更新的资源。数值容差只能解释舍入误差，不能替代 token 身份和版本不变量。性能判断还应分别说明有效产出和长期质量。

## 2. 奖励、过滤与独立评估：怎样定义有效进展

> 前置：[RL 目标](<25_RL目标与系统角色.md#s2>)。本节解释反馈和质量的系统契约；第 27 章再展开[版本与队列](<27_权重发布异步与资源调度.md#s1>)，具体任务判分在实现章节维护。

<a id="s2-训练奖励与评估承担不同职责"></a>

### 训练奖励与评估承担不同职责

奖励进入 advantage 或损失，评估回答模型是否在固定任务上改善。规则 verifier、学习的 reward model、环境成功率和独立保留集可以并存。

优化某个奖励信号可能利用判分漏洞，而没有提高目标任务表现。应检查输出长度、格式、异常答案与环境记录，使用独立数据和判分对照。奖励变高、loss 正常、生成吞吐增加，都不能单独证明质量改善。

<a id="s2-一份分数也有版本"></a>

### 一份分数也有版本

| 对象 | 需要保留的身份 | 不记录时的风险 |
|---|---|---|
| Policy artifact | 权重、adapter、精度、模板/tokenizer | 评估标签与实际生成模型不一致 |
| Agent harness | 代码与配置 revision、系统说明、工具 schema、上下文/记忆、重试与任务预算 | 运行条件变化被误认成模型训练收益 |
| Task/data | 数据 revision、sample ID、切分与去重规则 | 训练/评估混入或数据漂移 |
| Reward | 规则代码或 RM revision、prompt、尺度、异常策略 | 同一回答在不同时刻被不同判分 |
| Environment | 环境 revision、seed、工具和超时 | 成功率变化来自环境 |
| Eval recipe | sampling、长度、n、stop、汇总方法 | 两次分数无法比较 |

可以将这些身份一起保存为一次评估的 manifest。异步评估必须绑定一个完整可读快照，不能评分过程中不断装载新参数而把结果记为单一 checkpoint。

Agent 的评估对象包含模型与 harness 的组合。固定 harness 比较模型、固定模型比较 harness 的对照见[运行条件与评估](<28_Agent环境与多轮训练.md#s1-训练部署与评估需要对齐的是执行条件>)；预算、初态和判分保持可比，才能解释收益来源。

<a id="s2-从原始奖励到训练目标"></a>

### 从原始奖励到训练目标

区分 raw reward、后处理后的 reward、组统计和 advantage。裁剪、归一化、长度惩罚、拒绝无效样本，各自改变信号；应保留足够原始字段来复算。

例如明确规定 $R=R_{test}-\alpha\max(0,L-L_0)$：$R_{test}$ 是测试分数，$L$ 是回答有效 token 数，$L_0$ 是免罚长度，$\alpha$ 的单位是“分/token”。若通过测试得 1 分、$L_0=4$、$\alpha=0.1$，长度 3 和 7 的两条通过答案分别得 1 和 0.7。这样做鼓励在保证成功的同时减少长度，但也可能惩罚必要的长解法；只有单独记录原始成功率和长度，才能辨别奖励上升来自能力还是缩短输出。不能用含 padding 的张量长度替代这里的 $L$。

GRPO 的组必须仍对应同一 prompt 和所声明的生成条件。假设同组奖励为 `[0,1,2]`，这里只做均值中心化，原均值是 1，信号为 `[−1,0,1]`。过滤掉奖励 0 的回答后，若重算剩余两条的均值，就得到 1.5，信号变成 `[−0.5,0.5]`；若沿用原组统计，剩余信号则是 `[0,1]`。奖励 1 的同一条回答，甚至会从零信号变成负信号。

因此过滤发生在组统计之前还是之后，会改变学习目标；整组重采样又改变了候选数据。标准差归一化还会进一步改变尺度。全零方差组、超时组和部分组都要明确处理，不能只看最终是否凑足了训练样本数。

对多轮 agent，任务组对应同一任务与声明初始条件下的多个逻辑尝试，后续上下文可以因动作而不同。一次尝试拆成多个训练片段不应自动增加组内候选数；按行重复 reward 会改变均值和尺度，算例见[Agent 训练的数据与反馈闭环](<28_Agent环境与多轮训练.md#s3-数值推演相同轨迹怎样因归约方式得到不同权重>)。

<a id="s2-过滤后的供给才是-learner-的输入"></a>

### 过滤后的供给才是 learner 的输入

教学假设：每秒生成 8 个完整组，其中 25% 按组过滤，50% 的剩余组通过版本/有效性检查，则供给为 $8\times0.75\times0.5=3$ 组/秒。两个比例是按上述顺序的条件通过率，不假定统计独立。

若 learner 每秒可消费 4 组，它会缺数据；增加训练资源不能补足供给。若 learner 只消费 2 组/秒，仍要背压或舍弃额外 1 组/秒，否则队列会变旧。生成、过滤、过期、训练消费和环境失败应分别计数。

增加重采样可能提高完整组率，也可能改变任务分布：容易产生非零奖励差异的 prompt 会被更多消费。应按来源和任务类别记录接受率，区别吞吐变化与数据配比变化。

完整组还带来一道等待边界。假设一组三条回答连同判分分别在 1、2、5 秒就绪，需要完整组才能归一化，则这组最早在第 5 秒进入 learner；前两条只需保留训练记录，不一定继续占着生成 KV。若每条在期限内就绪的概率都是 0.9，且教学上假设相互独立，整组按时就绪概率是 $0.9^3=0.729$。真实任务的超时常相关，不能照搬独立乘积；这个例子只说明“单回答完成率很高”仍可能留下大量缺组。

为了凑齐组而反复采样，需要事先规定替补规则。只替换低分回答会把组分布改成更容易成功的样本；只替换基础设施失败也可能偏向较短、较易运行的任务。应保存原始候选数、替补原因和实际消费组，而不是让训练 batch 的最终行数隐藏这些成本。

<a id="s2-eval-的分母和失败处理"></a>

### Eval 的分母和失败处理

固定 100 个任务，90 个产生可评分结果，其中 72 个成功。按全部任务完成率统计是 72%，按完成任务的条件成功率是 80%；应同时报告失败的 10 个任务，不能静默去掉后把 80% 当作整体改善。

Eval early stop、超时、取消和工具失败可能使缺失与难度相关，不能默认随机缺失。保留任务级结果和缺失原因，让每个汇总值有可追溯的分母。

对每题 n 次采样，可以报告每次成功比例，也可以报告至少一次成功率。Pass@k 的估计还需声明 n、成功数 c、抽取方式和任务平均：固定候选集合均匀无放回抽取时，命中概率为 $1-\binom{n-c}{k}/\binom{n}{k}$，其中 $n\ge k$；每题独立计算后再平均。推导与估计来源见[HumanEval 原论文](https://arxiv.org/abs/2107.03374)。它不是把所有回答混在一起求一个总体成功率。

这里 $\binom{n}{k}=n!/[k!(n-k)!]$ 表示从 $n$ 条候选中选 $k$ 条的组合数。分母数出全部选择，分子数出“全部选到失败答案”的选择，再用 1 减去失败概率。例如 $n=4,c=1,k=2$：全部有 6 种，两条都失败有 $\binom32=3$ 种，因此 pass@2 为 0.5；单次成功比例仅为 $1/4$。若 $n-c<k$，不可能全失败，失败组合数按零处理。这个计算假设均匀抽取候选，不能当作一个有额外选择器的 best-of-k 系统实测成功率。

“80%”还需要样本量。若教学上把任务结果近似看成独立、同成功概率的 Bernoulli 变量，$n$ 题成功均值 $\hat p$ 的标准误差估计为 $\sqrt{\hat p(1-\hat p)/n}$；$\hat p=0.8,n=100$ 时约为 0.04，即 4 个百分点，而非 4% 的相对变化。真实任务难度不同、同题重复尝试相关，宜保留任务级结果并按任务重采样或做配对比较。少数题上的小幅上升不能由一个均值证明。

<a id="s2-成本与-time-to-quality"></a>

### 成本与 time-to-quality

对预先固定的评估阈值，记录达到阈值的墙钟时间和累计资源：生成、训练、reference/reward、环境与换权都在范围内。两个系统可能每步长度、有效样本量和更新次数不同，因此相同步数不一定是相同工作。

样本少或生成随机性强时，同时给任务级波动与重复 seed 的结果。改变异步程度、过滤或低精度后，短程 logprob 对齐检查局部正确性，独立评估曲线检查长期效果，二者各自承担证据职责。

## 3. 过滤和奖励故障怎样悄悄改写任务分布

假设任务一半容易、一半困难，完成并被接受的比例分别为 0.9、0.3。原始抽样各 100 次，期望进入训练的却是 90 条容易任务、30 条困难任务；训练数据变成 3:1。采样器没有改配置，系统已经改变了课程。

用 $p(x)$ 表示原始任务分布、$a(x)$ 表示给定任务最终被接纳的概率，在稳定条件下有

$$p_{train}(x)=\frac{p(x)a(x)}{\sum_{x'}p(x')a(x')}.$$

这是条件概率公式。实际 $a(x)$ 可能随策略、长度、时间、环境故障和组内奖励变化，按任务类别汇总只是一个可观测近似。如果接受条件直接依赖输出或奖励，仅平衡题目类别也不能恢复原来的回答分布。盲目用接受率倒数加权，在接受率很低时还会放大方差；接受率为零的任务没有样本可供恢复。

把分母也算出来：$P(\text{接受})=0.5\times0.9+0.5\times0.3=0.6$，所以容易任务占 $0.45/0.6=0.75$，困难任务占 $0.15/0.6=0.25$。分母是整体通过率，不是题目总数。若同一批中容易和困难任务的成功率分别为 0.8、0.2，原配比平均成功率为 0.5；仅因上述过滤后配比变化，接受集成功率就变成 $0.75\times0.8+0.25\times0.2=0.65$，即使两类能力都没变。此处另假设类内过滤与成功独立；若过滤直接看奖励，偏移还会更复杂。

这要求奖励服务将“得到了低分”和“没有得到分数”分开表示。一个教学接口可以把结果分为 `SCORED(value, grader_revision)`、`RETRYABLE_FAILURE`、`INVALID_INPUT` 与 `UNKNOWN_OUTCOME`，名称不要求与现有实现相同。判分器连接超时不能自动转成真实 reward=0；重试应针对同一份不可变答案或产物，并保存评分 attempt，避免重新生成后只保留更高分。

排查 reward 下降时，先沿同一批 task ID 比较原始抽样、生成完成、评分成功、组完整、训练接纳五层数量，再对照判分器版本及错误类型。如果困难任务大量缺失，训练 reward 甚至可能上升，此时单看均值会得到相反结论。

最后区分“没有组内策略信号”与“没有任何更新”。全组奖励相同，在仅靠中心化优势的策略项中通常得到零信号；若还有 KL、熵、辅助损失或优化器历史状态，参数仍可能变化。过滤零方差组可以节省部分训练工作，但会改变任务配比，也不能把所有留下的组都视为同等强的学习信号。

接受率导致的任务配比变化可用[标准库复算程序](<../examples/rl_infra_contracts.py>)检查，验证范围限于上述教学模型。

本章接口边界于 2026-10-15 对照 slime 提交 `b38426e91bc823aed2b31f86b0eb044218677094` 的 `rollout.py` 核对：训练数据转换会按 `rollout_id` 汇总 `rollout_mask_sums`，供片段归约使用；奖励后处理在相应归一化开关开启时按配置数量 reshape，数量不匹配时退为单行统计。这不保证自动按任意 group ID 重建奖励组。自定义多轮管线应分别检查奖励分组与损失分母，不能因为后者有 rollout 身份就认为前者已经正确去重。

## 本章回顾

有效训练供给取决于过滤、组完整性和目标分母。训练奖励是学习信号，独立评估才检验质量变化；吞吐、失败与成本应采用同一任务口径记录。
