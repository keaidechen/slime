## 1. 从预训练到微调与在线 RL：目标、参数和执行阶段

> 前置：[训练更新](<../04_Training/12_数据管线与训练循环.md#s1>)、[Packing 与 mask](<../04_Training/12_数据管线与训练循环.md#s2-packing的目标边界与有效分母>)。本文比较系统职责；具体算法的归约和正则项须另行声明。

<a id="s1-数据目标与参数更新是两条轴"></a>

### 数据目标与参数更新是两条轴

SFT、DPO、在线 RL 描述数据与目标如何构造；全参数微调、LoRA、QLoRA 描述更新哪些参数以及如何存储。SFT 可以使用 LoRA，在线 RL 也可以只更新 adapter，不能把它们当成互斥阶段。

| 配方 | 数据与目标 | 额外执行阶段 | 主要状态 |
|---|---|---|---|
| 自回归预训练 | 语料中的有效 next-token 预测 | 读取、采样、前后向与更新 | 模型、优化器、采样器 |
| SFT | 给定上下文与监督回答，按目标设置 mask | 通常离线数据供给，无须每步在线生成 | 模型、优化器、模板与数据版本 |
| LoRA 微调 | 目标可为 SFT、DPO 或 RL | 计算基座及低秩分支 | 冻结基座、adapter、adapter 优化器 |
| QLoRA 微调 | 冻结量化基座，训练低秩分支 | 解量化/融合计算、反向传播 | 量化基座及元数据、adapter 状态 |
| 标准离线 DPO | 同一 prompt 的 chosen/rejected 偏好对 | 策略与冻结 reference 的序列评分 | 配对身份、reference 版本、优化器 |
| 在线 PPO/GRPO 等 | 策略生成轨迹，再由反馈构造更新目标 | rollout、reward/环境、训练、换权 | 行为概率、组/轨迹、版本、队列 |

离线 DPO 不要求在每次训练更新中在线 rollout；数据集仍可能提前由生成系统产生。Reference 评分若预计算，必须与数据、tokenizer、mask 和 reference 参数版本绑定。不同偏好优化变体不一定采用标准 DPO 的全部职责。

<a id="s1-同样的序列训练目标怎样变化"></a>

### 同样的序列，训练目标怎样变化

设输入 `[BOS,p,a,EOS]`。独立序列的 next-token 目标可包含预测 `p,a,EOS`；若 SFT 将 `[BOS,p]` 作为 prompt，只训练回答，则保留预测 `a,EOS` 的 loss。Attention 仍让回答看到 prompt。

因此减少 loss 位置不直接消除 prompt 前向或全部反向成本；可训练参数仍可能依赖 prompt 的隐藏表示。计算节省要由实际 kernel、缓存或冻结路径验证。完整分母算例由[数据管线](<../04_Training/12_数据管线与训练循环.md#s2-packing的目标边界与有效分母>)维护。

<a id="s1-lora-减少哪些状态"></a>

### LoRA 减少哪些状态

对线性层 $W\in\mathbb R^{d_{out}\times d_{in}}$，令

$$y=Wx+(\alpha/r)BAx,$$

其中 $A\in\mathbb R^{r\times d_{in}}$、$B\in\mathbb R^{d_{out}\times r}$ 为训练参数，基座 $W$ 冻结。省去的是基座参数梯度及其优化器状态；传播到更早的可训练层仍可能需要基座算子的输入梯度和激活。[LoRA 原论文](https://arxiv.org/abs/2106.09685)。

教学例：$d_{in}=d_{out}=4096$、$r=16$ 时，基座有 16,777,216 个参数，A/B 合计 131,072，约为基座的 0.78125%。若仅为 adapter 配置 BF16 参数、FP32 梯度、FP32 主权重和两个 FP32 Adam 矩，每参数 18 字节，共 2.25 MiB；冻结 BF16 基座仍需 32 MiB。这里不计激活、工作区、分片和实现可能省去的副本。

低秩参数少，不代表长序列激活或通信必然可忽略。目标层选择、rank、并行布局和优化器决定实际成本。

<a id="s1-qlora-与部署量化的接口"></a>

### QLoRA 与部署量化的接口

[QLoRA](https://arxiv.org/abs/2305.14314)在冻结的量化基座上把梯度传播到 LoRA，并提出 NF4、double quantization 与 paged optimizer 等设计。量化基座仍需要计算和表示元数据；不能把整个训练的计算精度称作“四位”。

导出时至少区分三种对象：独立 adapter、基座加 adapter、已合并后重新量化的模型。合并可表示为 $W'=W+(\alpha/r)BA$，但再量化的舍入使其不保证与在线 adapter 分支逐位等价。Artifact 应保存基座 revision、目标层、rank、缩放、tokenizer/template 与量化配置。不要将 MLA 架构参数 `q_lora_rank` 直接当作 adapter rank。

<a id="s1-偏好对与在线轨迹有不同数据契约"></a>

### 偏好对与在线轨迹有不同数据契约

标准 DPO 对同一 prompt 的回答 $y^+,y^-$ 使用

$$L=-\log\sigma\left(\beta\left[\log\frac{\pi_\theta(y^+|x)}{\pi_{ref}(y^+|x)}-\log\frac{\pi_\theta(y^-|x)}{\pi_{ref}(y^-|x)}\right]\right).$$

序列概率按所定义的回答 token 累积，prompt、EOS 和截断规则需一致。Chosen/rejected 被分开 packing 后仍须保留配对身份；任意重新配对会改变目标。[DPO 原论文](https://arxiv.org/abs/2305.18290)。

在线 RL 则增加行为策略与反馈：一次生成何时完成、多个回答是否形成完整组、哪份权重生成了哪些动作，都会影响可消费性。执行图见[RL 全景](<25_RL目标与系统角色.md#s1>)。

<a id="s1-怎样比较资源和质量"></a>

### 怎样比较资源和质量

固定任务与评估，分别报告可训练参数、常驻状态、峰值激活、有效预测 token、前后向/评分/生成时间和总 GPU 时间。少更新参数、少做一个角色前向、减少无效 token，是不同来源的收益。

在相同数据上更快完成一步，不保证用更少成本达到相同质量。若改变目标、数据配比或 rank，应记录独立评估曲线；质量口径见[奖励与评估](<26_Rollout奖励与训练数据.md#s2>)。

实现连接：[slime 的 SFT 与 RL loss](<../appendices/source/slime/05_rl_algorithms.md>)、[SGLang adapter 生命周期](<../appendices/source/sglang/04_interfaces_and_models/03_control_plane_and_post_training.md>)。这些入口不表示 slime 实现了本节全部配方。


## 本章回顾

预训练、SFT、参数高效微调和偏好优化改变目标与可训练状态。训练循环的共同语义仍然成立，但激活保存、数据构造和额外评分模型的需求需要重新核算。

**检查理解：** 冻结基座后，哪些训练状态消失，哪些激活仍要保存？离线偏好数据与在线 RL 有何区别？

下一章讨论RL目标与系统角色。从反馈定义学习目标，将策略生成、奖励、概率与更新连接成完整闭环。
