## 1. 张量、形状、布局与复杂度

一段模型程序既在计算数值，也在安排数值存在哪里。本节先用一个六元素数组建立共同语言；只需要会看二维表格和矩阵乘法。[数字编码](<../appendices/foundations/信息与数字电路.md>)是补读，不是开始阅读的前提。

<a id="s1-数学对象与物理对象"></a>

### 数学对象与物理对象

这里把张量（tensor）理解为按多个维度组织的数值数组：一个数是零维，一个向量是一维，一个矩阵是二维。矩阵 `[[10,11,12],[20,21,22]]` 有 2 行、3 列，共 6 个元素，形状（shape）为 `[2,3]`。形状里的数字是各维长度，不是元素的值。

程序还需要知道元素怎样存放：

| 属性 | 本例可以是什么 | 回答的问题 |
|---|---|---|
| dtype，元素类型 | FP32，每元素占 4 字节的浮点格式 | 怎样解释存下来的二进制位？ |
| device，所在设备 | CPU（中央处理器）或 GPU（图形处理器） | 哪个设备持有这份存储？ |
| storage，底层存储 | 顺序排列的 `[10,11,12,20,21,22]` | 数值实际放在哪里？ |
| stride，步长 | `[3,1]`，单位为元素 | 某维下标增加 1，地址前进多少？ |
| storage offset，起始偏移 | 0 | 本张量从底层存储的哪里开始？ |

一个字节（byte）为 8 个二进制位（bit）。本例的纯数值负载是 6×4=24 字节，尚未计入 shape 等元数据。

下标从 0 开始。对 shape `[2,3]`、stride `[3,1]`，元素 $(i,j)$ 的存储偏移为 $3i+j$，所以 (1,2) 访问偏移 5，得到 22。转置后 shape 为 `[3,2]`、stride 为 `[1,3]`；新矩阵的 (2,1) 仍访问 2×1+1×3=5，数值不用移动。

这种只改变观察方式的对象称为视图（view）。转置后的第一行是 `[10,20]`，对应旧存储中的偏移 0 和 3；它们在数学上属于同一行，在物理上却并不相邻。若后续算子要求每行连续，就需要把数值重新排列成 `[10,20,11,21,12,22]` 并保存到另一份存储中。因此转置本身可以只改元数据，后续访问是否需要复制仍取决于算子的布局要求。

两个张量引用同一底层存储，称为存在别名关系。例如把原矩阵的 `(1,2)` 从 22 原地改成 99，转置视图的 `(2,1)` 也会读到 99，因为两个下标最终指向同一个存储位置。要获得可以独立修改的副本，就必须明确复制，而不能把“新建了一个视图对象”当作“复制了数据”。

<a id="s1-矩阵乘与广播"></a>

### 矩阵乘与广播

$X_{M\times K}W_{K\times N}=Y_{M\times N}$ 表示：

$$Y_{ij}=\sum_{k=0}^{K-1}X_{ik}W_{kj}.$$

M、N 决定输出行列，K 是把多项合成一个结果的规约维。求和、求最大值都属于规约（reduction）。例如行向量 `[1,2]` 乘列向量 `[3,4]`，得到 1×3+2×4=11。

GEMM 是 General Matrix Multiply，通用矩阵乘的简称。Batch 是一次一起处理的一组样本；batched GEMM 则对一组矩阵分别做矩阵乘。例如 X 的形状为 `[B,M,K]`，W 的形状为 `[B,K,N]` 时，第 b 组计算 `X[b] @ W[b]`，输出形状为 `[B,M,N]`。组之间没有求和：B 表示有多少个独立问题，K 才是每个问题内部需要求和的维度。

若所有组共用同一个 `[K,N]` 权重 W，也可以把 X 的前两维合成 `[B*M,K]`，做一次矩阵乘后恢复为 `[B,M,N]`。这样成立，是因为每一行始终乘同一份 W；若每组有不同的 W，就不能照搬这个变形。`reshape` 只改变元素的形状表达，是否仍在算原问题，需要逐项检查对应关系。

广播（broadcasting）规定了形状不同的数组怎样参与逐元素运算。设矩阵为 `X=[[10,20,30],[40,50,60]]`，希望每一行的三个位置分别加上 `b=[1,2,3]`。结果应当是：

```text
X 的第一行 + b = [10+1, 20+2, 30+3] = [11,22,33]
X 的第二行 + b = [40+1, 50+2, 60+3] = [41,52,63]
```

X 的形状是 `[2,3]`，b 的形状是 `[3]`。判断能否广播时，从最右边的维度开始对齐；缺少的前导维度按 1 看待，因此这里把 b 看作 `[1,3]`。每对对应维度必须长度相等，或其中一个长度为 1。这里列维度都是 3，行维度是 2 和 1，因此能够得到 `[2,3]` 的输出。相反，`[2,3]` 与 `[2]` 的最后一维是 3 和 2，既不相等也没有 1，不能这样相加。如果希望每行加一个不同的数，应把后者写为 `[2,1]`，明确让它沿列方向重复。

这里的“重复”首先描述取值规则：输出 `Y[i,j]` 总是读取 `X[i,j]` 和 `b[j]`。实现可以让两行都读取同一份 b，不必先创建 `[[1,2,3],[1,2,3]]` 这个实体数组。广播式读取与真正复制是两件事；普通加法的输出 Y 仍需要存放结果。是否产生额外临时副本，则取决于具体操作和后续布局要求。[PyTorch 广播规则](https://docs.pytorch.org/docs/stable/notes/broadcasting.html)采用这种形状匹配方式。

这种共用也解释了为什么训练时要合并影响。例如 b 的第一个数增加 0.1，Y 两行的第一个数都会增加 0.1；若损失就是 Y 所有元素之和，损失合计增加 0.2。也就是说，这个 b 元素对总损失的影响来自两条路径。到第 5 章学习梯度时，会把这个过程写成沿广播维度求和的公式。

<a id="s1-复杂度不是完整成本"></a>

### 复杂度不是完整成本

时间复杂度描述工作量随规模的增长趋势。两重循环各执行 S 次，工作量随 S² 增长，可写为 O(S²)；它没有说明一次操作需要多少秒。空间也要区分输入输出、长期保留的状态、临时工作区，以及同一时刻必须同时存活的数值集合。

FLOP 表示一次浮点运算。把乘法和加法各计一次，GEMM 的常见近似口径为 $2MKN$。FLOPs 在本书通常表示运算总数，FLOP/s 表示每秒完成的运算数。把数据拆到多个设备叫分片，设备之间传递数据叫通信；通信字节数不能仅从 FLOP 数推出。

例如 `[2,3]` 乘 `[3,4]` 得到 `[2,4]`，按 $2MKN=2\times2\times3\times4$ 的常见口径，近似需要 48 FLOPs。若逐个输出只计算 3 次乘法和 2 次加法，精确计数是 $8\times(3+2)=40$；48 使用每个乘积都配一次累加的近似口径，比较时要采用相同口径。

**纯数值负载**指张量中数值数据本身的存储大小，计算方法是“元素个数 × 每个元素的字节数”。FP32 的每个元素占 32 bit，即 32÷8=4 字节：

| 张量 | 形状 | 元素个数 | FP32 纯数值负载 |
|---|---|---:|---:|
| 输入 X | `[2,3]` | 2×3=6 | 6×4=24 字节 |
| 输入 W | `[3,4]` | 3×4=12 | 12×4=48 字节 |
| 输出 Y | `[2,4]` | 2×4=8 | 8×4=32 字节 |
| 合计 | — | 26 | **104 字节** |

这里假设两个输入和输出分别保存为独立的稠密 FP32 张量，没有共享底层存储。一个输入元素即使参与多次乘法，在这笔存储账里也只计一次。例如 X 的一个元素参与输出 4 列的计算，但保存这个数仍只需 4 字节。实际执行会从哪个存储层级读取它、读取几次，是另外的访存账。

104 字节尚未包含形状等元数据、分配器对齐开销和临时工作区，也没有据此估计实际读写次数或运行时间，后续章节会依次补上这些账。

<a id="s1-小例子相同-token-数不同-attention-工作量"></a>

### 小例子：相同 token 数，不同 Attention 工作量

Token 是模型处理的离散单位，可以是字、子词或其他编码片段，不固定等于一个汉字。此处先把它看作序列的一个位置。下一章的 Attention（注意力）会让一个位置查询其他位置的信息，因此需要考虑位置对的数量。

两条长度 512 的独立序列共有 1024 token，完整位置对矩阵共有 $2\times512^2$ 个元素；一条长度 1024 的序列则有 $1024^2$ 个，后者是前者的两倍。若只允许查看当前与过去位置，两者允许访问的位置对数分别为 $2\times512\times513/2$ 和 $1024\times1025/2$，仍不能只按总 token 数估计。

Packing 指把多条样本合装进同一计算容器，mask 指限制哪些位置之间可以互相访问。独立样本合装后，仍需要保留各自的访问边界。逻辑上禁止的位置是否真的省掉计算，还取决于实现。

因此配置应记录长度分布、mask、布局和 batch。模型特征宽度和注意力头数也影响成本，下一章再定义它们。仅用平均长度或总 token 数，可能漏掉工作量和峰值内存差异。

### 相同形状，还需要相同语义

两个 `[B,S]` 张量可以分别表示 token ID、有效位置或 token 概率。形状一致只证明它们能够逐元素运算，不能证明同一位置指向同一个事件。把一条回答的概率错移一位后，程序通常仍能运行。

因此描述张量时，还应说清轴的含义、位置对应关系和有效区间。例如 `action_logprob[b,t]` 应注明它对应哪个动作、条件上下文是否包含该动作，以及 padding 位置能否被消费者读取。对于变长序列，还需要每条序列的边界；拼接后的总长度不能恢复这些边界。

Attention mask 决定“当前位置能够读取谁”，loss mask 决定“哪个预测进入优化目标”。用户问题可以不计入 loss，却必须被回答读取；将两者混用会改变模型任务。布尔值的方向也属于接口约定：例如 PyTorch 的 [scaled_dot_product_attention](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.scaled_dot_product_attention.html) 中，布尔 mask 的 `True` 表示允许参与注意力，不能根据变量名把它当成屏蔽位。

排查时选取一条很短的样本，列出每个位置的 token、预测目标、可见前缀和 loss 权重。这样的逐位置表格往往比打印十个张量的 shape 更早找到问题，下一章会实际展开。

<a id="s1-从手写索引到布局抽象"></a>

### 从手写索引到布局抽象

现在可以分开回答三个问题：数学上计算什么，元素怎样映射到存储，需要多少算术和数据移动。后续的 GPU 分块、分布式切分和推理缓存都会反复使用这三个问题。

自检：把 `[2,3]` 转置成 `[3,2]`，元素数和纯数值字节数变了吗？没有；改变的是下标到地址的映射，是否额外复制由操作与消费者决定。

## 2. 浮点数、数值误差与低精度计算


<a id="s2-范围与精度"></a>

### 范围与精度

先用十进制科学记数法理解浮点表示：同一个数可以写成“符号 × 有效数字 × 10 的某个幂”，例如 −1250 = −1.25×10³。二进制浮点数也把信息分给符号、指数和有效数，只是以 2 为底，且能使用的位数有限。因此它只能表示一部分离散的数；落在两个可表示数之间的真实结果，要按舍入规则选取一个近似值。

范围回答“能表示多大、多小的数”，精度回答“在当前数值附近，能分辨多小的差别”。FP16 与 BF16 都占 16 bit：FP16 使用 5 个指数位、10 个显式小数位；BF16 使用 8 个指数位、7 个显式小数位，另各有 1 个符号位。BF16 把更多位分给指数，因而范围更宽；FP16 在正常数的同一数量级内通常具有更密的表示间隔。两者存储字节数相同，却会在溢出和舍入上表现不同。

正常数的有效数可写成二进制的 `1.f`，前面的 1 可以隐含保存，“显式小数位”是 f 实际占用的位数；FP32 则分为 1 个符号位、8 个指数位和 23 个显式小数位。次正规数（subnormal）用于表示接近零、低于正常数范围的值，其有效精度会随幅值减小而降低。结果超过格式有限范围叫溢出，可能产生 Inf（无穷大）；过小的数在低幅值区域舍入、甚至变成零，与下溢问题有关。NaN（Not a Number，非数）用于表示某些无效数值结果，例如 0÷0；Inf 和 NaN 都属于非有限值，不能当作普通有限数参与误差验收。

固定格式下，大幅值附近的相邻可表示数间隔通常更大。很小增量加到很大数上，可能被舍入掉；改变求和顺序也可能改变结果。数学上的结合律不能直接作为浮点逐位相等的保证。

<a id="s2-存储乘法与累加精度"></a>

### 存储、乘法与累加精度

一个算子可以用低精度输入、较高精度累加，最后再转换输出。这三者应分别记录。以 $Y_{ij}=\sum_k X_{ik}W_{kj}$ 为例，“FP16 输入、FP32 累加、FP16 输出”表示：读取以 FP16 保存的 X 和 W，用 FP32 保存并更新部分和，最后把结果舍入到 FP16 写入 Y。

| 精度位置 | 决定什么 | 提高这一精度的作用与边界 |
|---|---|---|
| 输入 | 算子开始时实际收到的数值 | 输入转换已经丢失的信息，后续高精度计算无法恢复 |
| 累加 | 求和过程中部分和的表示 | 减少小项被大部分和吞掉的机会；每次浮点加法仍可能舍入 |
| 输出 | 交给下一个算子或存入内存的结果 | 最终转换仍可能舍入或溢出，不能只报告累加器格式 |

例如 FP16 在 [2048,4096) 内相邻可表示数的间隔是 2。若每次相加后都采用“舍入到最近、正中间时取末位为偶数”的规则，2048+1 会舍入为 2048，再加 1 仍为 2048；用 FP32 累加这两个 1 则得到 2050，最后转成 FP16 也能保留这个结果。高精度累加能保留计算中的小贡献，但不能补回输入阶段已丢失的信息。严格分析时还应记录乘积的计算方式与舍入规则，三个存储类型并不能完整描述全部指令语义。

**分布式规约树**描述多设备部分结果怎样逐层合并。例如四张卡分别产生 a、b、c、d，可以按 `((a+b)+c)+d` 求和，也可以先并行计算 `(a+b)` 和 `(c+d)`，再合并两者。实数加法满足结合律，浮点加法却会在各次加法后舍入，所以改变括号位置可能改变结果。

这种差异在 FP32 中也存在。取 $a=2^{24}=16777216$、$b=1$、$c=-2^{24}$，采用上述舍入规则：先算 a+b 会舍入为 a，随后加 c 得到 0；先算 b+c 得到可准确表示的 −16777215，再加 a 得到 1。精确数学结果都是 1。设备数量或规约算法改变合并顺序时，就可能产生类似差异；使用 FP32 累加并不自动保证逐位一致。

**融合改变中间舍入位置**，可以从融合乘加 FMA（fused multiply-add）理解。分开执行乘法和加法时，结果可写为 $R(R(ab)+c)$；FMA 则按精确乘加后只舍入一次的语义计算 $R(ab+c)$，R 表示舍入到目标格式。前一种写法可能先丢掉乘积的低位信息，后一种写法保留它们参与加法。算子融合也可能让“矩阵乘 → 加偏置 → 激活”的中间结果一直留在 FP32，最后才转换输出，从而省去原来写回 FP16 时的舍入。是否实际改变舍入，必须看实现；仅合并 Kernel 启动、仍保留原有转换的融合也可能保持原来的数值行为。

**Bitwise 相同**指相同输出格式下，每个元素的二进制位完全一致；仅最后一位不同也不满足这个标准。“可接受误差”则是结果满足指定的绝对、相对误差或任务质量要求，后文给出容差公式。两份结果可以通过误差验收，却不逐位相同。改变规约顺序或融合方式是否仍在容差内，需要验证，不能仅凭数学等价推断。

判断差异是否可接受，先看参考值与误差的大小，再看后续计算会怎样使用它。例如两个接近的大数相减得到小结果时，输入的一点舍入误差就可能占结果的很大比例。数学上用“条件数”描述问题对输入扰动的敏感程度；这里先掌握这种敏感性即可，无须先计算条件数。单层误差较小也不能直接保证长期训练稳定，因为该输出还会影响后续梯度和多次参数更新。

<a id="s2-数值稳定的表达"></a>

### 数值稳定的表达

Softmax 把一组实数分数变成非负且总和为 1 的权重。直接写法是先计算每项的指数，再除以全部指数之和。为了避免大分数的指数超出表示范围，常先取 $m=\max_i x_i$，使用下面的等价形式：

$$p_i=\frac{\exp(x_i-m)}{\sum_j\exp(x_j-m)}.$$

为什么减去同一个最大值不改变概率？因为分子、分母都相当于乘了同一个因子 $e^{-m}$，约分后仍是原来的比值。例如分数 `[1000,1001]` 直接求指数容易溢出；减去 1001 后变为 `[-1,0]`，只需计算约 `[0.368,1]`，归一化后得到约 `[0.269,0.731]`。数值范围变得可处理，而两个位置之间的相对差异得到保留。

但若 mask 把整行都设为负无穷，最大值也为负无穷；相减会遇到“负无穷减负无穷”，无法产生有效概率。这时首先要定义没有可见位置意味着什么，例如该行是否是应排除的补齐行，再由实现显式处理。减最大值只能解决正常可见行的指数范围问题。

方差、归约和归一化也需要合适的累加与稳定算法。代码中的代数等价不自动代表有限精度等价。

<a id="s2-量化引入新的状态"></a>

### 量化引入新的状态

量化把连续尺度上的数映射到有限编码。一个示意的仿射量化规则是

$$q=\operatorname{clip}(\operatorname{round}(x/s)+z),\qquad \hat x=s(q-z).$$

其中 scale（尺度）$s>0$ 决定相邻编码相差多少真实数值，zero point（零点）z 是真实零对应的整数编码。round 将数舍入到整数，clip 把超出编码范围的结果截到端点。反量化得到的 $\hat x$ 是近似值，不一定能恢复原来的 x。

例如使用整数编码范围 −8 到 7、s=0.5、z=0，x=1.2 会先变成 2.4，再舍入为 q=2，恢复后是 1.0。x=5 会得到超范围编码 10，截到 7 后只能恢复为 3.5，误差明显更大。前一种是舍入误差，后一种还包含截断误差。只保存 q 而不保存 s 和 z，就无法知道编码 2 代表的是 1.0 还是其他数；使用逐通道或逐块尺度时，还必须知道每个编码属于哪一组。

更小的表示减少字节数，但增加 scale 读取、转换或专用 Kernel 要求。按通道或按块设置 scale 能适应局部分布，也增加元数据和实现复杂度。低 bit 权重文件不意味着每个算子都在相同 bit 宽下完成。

<a id="s2-问题驱动的分支"></a>

### 问题驱动的分支

| 问题 | 方法 | 需要继续处理 |
|---|---|---|
| FP32 状态与带宽昂贵 | 混合精度 | 范围、累加与优化器状态 |
| 某些梯度难以表示 | loss scaling 等机制 | 溢出检测、跳过更新和缩放管理 |
| 部署容量不足 | 权重量化 | 异常值、解量化与质量 |
| KV 容量或带宽过大 | KV 量化 | 误差随上下文和模型变化 |
| 更低精度需要适应训练分布 | 量化感知训练等路线 | 训练成本与部署一致性 |

Loss scaling 是否必要取决于格式与算法；不能照搬某个 FP16 配方到所有低精度训练。

<a id="s2-手算舍入为什么同一个和会得到零或一"></a>

### 手算舍入：为什么同一个和会得到零或一

以下采用 round-to-nearest、ties-to-even，每次加法后舍入到 BF16，记为 R；输入都是精确可表示的数。BF16 在区间 [256,512) 的间隔为 2，所以 257 位于 256 与 258 的中间，按偶数规则得到 256：

$$R(R(256+1)-256)=0,\qquad R(256+R(1-256))=1.$$

第二种顺序先得到可表示的 −255，再加 256。两个结果的数学目标都是 1。分桶、并行归约树和融合改变中间舍入位置时，就可能出现这种差异。这个反例只模拟指定运算的舍入；真实 GEMM 若用 FP32 累加，并不逐项执行 BF16 加法。

另一个例子从权重 1 开始，每次减 0.001。若每步立即存回 BF16，小更新可能每次都被舍掉，八步后仍为 1；若在 FP32 主权重中累加，主权重接近 0.992，再转换计算副本就能体现变化。主权重保留小更新，并不能消除低精度前反向已经产生的误差。

两个接近的数相减会暴露输入误差。例如真实值 1.001−1=0.001，但二者若都已舍入为 1，随后即使用 FP64 相减也只能得到 0。提高最后一步精度不能恢复此前丢失的信息。

<a id="s2-从局部误差到训练目标"></a>

### 从局部误差到训练目标

令参考值为 x、实际值为 y。绝对误差为 |y−x|；相对误差可用 |y−x|/max(|x|,ε)。ε 是报告口径，不能用一个很大的 ε 掩盖接近零处的绝对错误。常见逐元素验收为：

$$|y-x|\le\mathrm{atol}+\mathrm{rtol}|x|.$$

atol（absolute tolerance）是绝对容差，与 x、y 使用相同单位；rtol（relative tolerance）是无单位的相对容差。例如 atol=0.001、rtol=0.01，参考 x=10 时允许误差不超过 0.101，而 x=0 时只允许 0.001。参考接近零时，绝对容差提供判断尺度；这些阈值需要按任务要求选择，不能随结果调整到刚好通过。

张量范数误差适合看整体偏离，但可能掩盖少量异常通道。应同时保留最大绝对误差、误差分位数、非有限值数量和受影响位置。梯度还应检查方向与参数身份；范数一致不代表各参数的梯度一致。

对线性层 Y=XW，输入和权重误差分别为 ΔX、ΔW：

$$\Delta Y=X\Delta W+\Delta XW+\Delta X\Delta W.$$

因此同样大小的 ΔW，在不同激活方向上可能产生不同输出误差。一个近零参考输出可能来自大项抵消，相对误差会很大；这时应同时看输入尺度和绝对误差。多层网络还有非线性与状态复用，不能把各层相对误差简单相加当作最终质量损失。

对于 logits z（归一化前的分数），softmax 的局部导数为 ∂pᵢ/∂zⱼ=pᵢ(δᵢⱼ−pⱼ)，选中动作 a 的 logprob（对数概率）导数为 ∂log pₐ/∂zⱼ=δₐⱼ−pⱼ。∂ 表示对指定变量的局部变化率，δᵢⱼ 是 Kronecker delta：i=j 时为 1，否则为 0；下一章会把这些分数对应到具体张量，第 5 章再展开导数如何用于训练。共同平移所有 logits 不改变概率；改变相对差值则会改变概率。比较应固定相同输入和动作，报告 logits、logprob、概率分布距离，再单独评估自由生成。RL 的概率比率会消费这些差异，见[行为概率](<../06_Post_Training/27_权重发布异步与资源调度.md#s2>)。

[数值参考程序](<../examples/numerics_quantization.py>)通过位操作模拟有限 FP32 输入向 BF16 的舍入，验证上述顺序和小更新反例。它不模拟全部 IEEE 特殊值、GPU 指令或融合算子。数值行为的框架边界见 [PyTorch Numerical accuracy](https://docs.pytorch.org/docs/2.14/notes/numerical_accuracy.html)。

<a id="s2-验证顺序"></a>

### 验证顺序

固定输入与参考实现，比较输出、梯度和一步更新；再检查不同长度、异常值和 mask；最后评估长期训练或生成质量。记录 dtype、累加方式、容差和硬件 backend。见[RL 数值正确性](<../06_Post_Training/26_Rollout奖励与训练数据.md#s1>)。
