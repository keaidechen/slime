## 1. 计算图、自动微分与状态生命周期

上一章用预测概率得到一个损失数。训练需要知道：参数略微变化，会让损失朝哪个方向变化？这个局部变化率叫导数；把各参数的导数放在一起就是梯度。符号 ∂L/∂w 表示损失 L 对参数 w 的变化率，本节从一个标量例子开始。

<a id="s1-链式法则如何变成执行图"></a>

### 链式法则如何变成执行图

计算图记录操作之间的数据依赖。令输入为 x、目标为 y、可学习参数为 w，先计算 u=wx，再计算 L=(u−y)²。取 x=2、y=4、w=3，前向依次得到 u=6、误差 e=2、损失 L=4。

反向从 L 开始：L 对 e 的导数为 2e=4，e 对 u 的导数为 1，u 对 w 的导数为 x=2，所以 w 的梯度为 4×1×2=8。这种沿路径相乘的规则称为链式法则：

$$\frac{\partial L}{\partial w}=2(u-y)x.$$

最简单的梯度下降是 $w_{new}=w-\eta\,\partial L/\partial w$，η 叫学习率，决定每次移动多少。取 η=0.1，w 从 3 变成 2.2，重新前向得到 u=4.4、L=0.16。梯度是局部信息，学习率太大仍可能令损失上升。

一个值被多条路径使用时，各路径的影响相加。例如 v=w×w，两个乘法输入都来自 w，各贡献 w，合计梯度为 2w。自动微分（automatic differentiation）按实际操作建立依赖图，反向执行“沿路径相乘、分支汇合时相加”的局部规则。

当中间结果有多个分量时，仍然沿用同一条链式法则。例如 $u_1=2w$、$u_2=3w$，后续损失传回 $\partial L/\partial u_1=4$、$\partial L/\partial u_2=5$，那么 w 的梯度就是 $4\times2+5\times3=23$。这里的 4、5 称为上游梯度：它们总结了这些中间值对后续最终损失的影响。

若把所有输出对所有输入的偏导排成表，这张表就是雅可比矩阵。反向传播只需要上游梯度与该表相乘得到的结果，这称为向量—雅可比积；实现通常直接计算这个乘积，无须保存整张可能很大的表。矩阵和张量的反向公式，就是把刚才的逐路径乘法与求和整理起来。

有限差分采用另一种验证方式：把参数略微增减，重复前向，观察损失变化。对前面的 $L(w)=(2w-4)^2$，取 w=3、扰动 h=0.001，则 $L(3+h)=4.008004$、$L(3-h)=3.992004$，两者差除以 2h 得到 8，与反向结果一致。它适合核对小模型，但逐个扰动大量参数需要反复前向，不能当作常规训练的反向算法。

<a id="s1-为什么需要保存激活"></a>

### 为什么需要保存激活

激活（activation）在这里泛指本次前向产生的中间数值，包含 Attention 输出等，不仅指非线性激活函数的输出。Forward／backward 分别是前向／反向的英文名称。

对 Y=XW，若上游梯度为 G=∂L/∂Y，则 dW=XᵀG、dX=GWᵀ。反向仍需要 X 和 W，所以前向完成后不能立即丢掉所有输入。保存哪些值取决于具体 backward 实现，并非每个前向输出都必须一直保留。

参数跨多个训练步保留，激活通常只服务当前计算图。动态图根据实际执行路径建立依赖；图编译尝试提前整理并优化这些操作，需处理形状变化、条件分支和副作用，见[编译器分层](<../03_Execution/10_编译器与运行时.md#s1>)。

<a id="s1-梯度累积与目标定义"></a>

### 梯度累积与目标定义

一次参数更新所需的大批样本可以拆成小批次依次处理，每个小批次叫 microbatch（微批次）。先累加各片梯度，全部完成后再更新一次参数；它不等于每片都更新一次。

两个 microbatch 分别有 2 和 6 个有效 token，各自 mean loss（平均损失）为 L₁、L₂。全局均值应为 (2L₁+6L₂)/8。若 L₁=1、L₂=3，结果是 2.5；直接平均两份均值得到 2，改变了目标的权重。

PyTorch 是常用的张量计算与训练框架，它的反向默认把梯度累加进参数的 `grad` 字段，因此更新周期开始时通常要清零。以后分布式训练中，每个参与进程会有编号 rank；不同 rank 的有效位置数也可能不同，不能无条件平均各自的 mean。

广播也遵循分支求和。回到第 3 章的两行矩阵加同一个向量：$Y_{ij}=X_{ij}+b_j$。固定第 j 列，bⱼ 分别进入两行加法，每条加法路径对 bⱼ 的局部导数都是 1。若损失对两行输出的上游梯度分别为 2 和 3，则经第一条路径得到 2×1，经第二条路径得到 3×1，合并为 5。一般写成

$$\frac{\partial L}{\partial b_j}=\sum_i\frac{\partial L}{\partial Y_{ij}}.$$

这里求和的是各行传回的影响，不能只选一行，也不能因为有两行就擅自平均。若损失本身定义为均值，相应的除法已经通过上游梯度传入。

<a id="s1-重计算如何改变内存"></a>

### 重计算如何改变内存

保存所有必要中间值便于反向，但会占空间。Activation checkpointing（激活检查点／重计算）只保存一些边界，反向需要内部值时重新执行那段前向。它与把训练状态保存到磁盘的 checkpoint 不同；后者用于故障恢复，后文另讲。

例如三段串联计算 X→A→B→C，反向第二段需要 A。若只保存 X 和边界 C，可以重新由 X 算出 A、B，但要付额外计算。能否降低端到端时间，取决于省下的内存是否允许更合适的 batch 或并行方案。

重执行应产生所需的同一计算。Dropout 是训练时随机屏蔽部分数值的机制；若重算时随机选择变了，反向就可能对应另一条前向路径。因此随机状态、可变状态和副作用都需要管理。

<a id="s1-常见边界"></a>

### 常见边界

`detach` 切断自动微分关系，但可能仍共享存储；`clone` 复制数值，却不自动切断梯度。前者回答“是否沿这条路径求导”，后者回答“是否持有独立存储”，两种问题不能混用。保留输出引用还可能让它依赖的图和中间值延寿，原地修改则可能破坏反向需要的旧值。

### 同一个损失数，为什么可能有不同梯度

前向数值相同并不保证反向图正确。设 $x=2$，比较 $L_1=x^2$ 与 $L_2=x\,\operatorname{stopgrad}(x)$。两者数值都是 4；前者梯度为 4，后者只有一条路径求导，梯度为 2。这里 stopgrad 保留数值并切断求导路径，可用 `detach` 表达。

这个区别在后训练中尤其重要：固定目标、历史策略概率和奖励可能由模型计算得到，但在当前策略更新中仍需要视为常量。是否求导由学习目标决定，不能仅根据“它是一个 Tensor”决定。第 25 章会将这个例子落实到策略梯度。

验证时既要比较损失值，也要检查哪些参数应有梯度、哪些不应有。小模型可用有限差分检查指定目标；但若目标含 stopgrad，每次扰动时必须冻结相应目标值，否则有限差分检验的就是另一函数。`model.eval()` 也不等于禁用自动微分，它改变的是某些层的运行行为；具体区别见 [Autograd 的梯度模式说明](https://docs.pytorch.org/docs/2.14/notes/autograd.html#locally-disabling-gradient-computation)。

<a id="s1-演进与验证"></a>

### 演进与验证

现在可以把一次训练拆成前向求损失、反向求梯度、优化器更新参数三个阶段。优化器是根据梯度及可选历史状态决定更新的规则，本章第 2 节会进一步展开。

自检：把大 batch 拆成两片，为什么不能总是各自取 mean 再相加？因为每片有效位置数可能不同，必须先保持同一个全局目标。数值验证应比较输出、梯度和更新，而不只看前向结果。

参考：[PyTorch Autograd mechanics](https://docs.pytorch.org/docs/stable/notes/autograd.html)、[checkpoint API](https://docs.pytorch.org/docs/stable/checkpoint.html)。

## 2. 优化器原理：从 SGD、Momentum 到 AdamW

> 前置：本章的[自动微分](<#s1>)。本节解释梯度怎样变成更新；读完即可继续下一章。第 12 章的[训练 step](<../04_Training/12_数据管线与训练循环.md#s1>)会把全局归约、unscale、裁剪和跳步连接成完整时序。

<a id="s2-梯度给出局部方向优化器决定怎样使用历史"></a>

### 梯度给出局部方向，优化器决定怎样使用历史

记更新前参数为 $\theta_{t-1}$，本次梯度为 $g_t=\nabla L_t(\theta_{t-1})$，学习率为 $\eta_t$。梯度已经按预期目标归约；改变有效 token 分母会先改变这里的输入。不同优化器也会产生不同参数，因此真实训练中后续梯度通常不再相同。

最基本的 SGD 为 $\theta_t=\theta_{t-1}-\eta_t g_t$。如果某个方向的梯度持续同号，另一个方向受噪声影响反复变号，可以通过历史平滑减少第二种振荡。本节采用未归一化动量：

$$b_t=\beta b_{t-1}+g_t,\qquad \theta_t=\theta_{t-1}-\eta_t b_t,\qquad b_0=0.$$

恒定梯度 $g$ 下，$b_t=(1-\beta^t)g/(1-\beta)$，所以动量不仅平滑方向，也改变幅度。另一种写法 $m_t=\beta m_{t-1}+(1-\beta)g_t$ 在同一初值下满足 $m_t=(1-\beta)b_t$；比较实现时需要连同学习率一起看。Nesterov 还改变实际使用的方向，不能只比较名为 momentum 的数值。

<a id="s2-adam每个坐标使用自己的历史尺度"></a>

### Adam：每个坐标使用自己的历史尺度

Adam 为每个参数分别保存两份历史。一份是梯度的指数移动平均 m，用来平滑方向；另一份是梯度平方的指数移动平均 v，用来描述这个坐标过去的梯度尺度。这里“一阶矩”和“二阶原点矩”分别指这两种平均；先平方再平均不等于计算方差，因为还没有减去均值平方。两份历史都与参数同形状，更新规则为：

$$m_t=\beta_1m_{t-1}+(1-\beta_1)g_t,\qquad
v_t=\beta_2v_{t-1}+(1-\beta_2)g_t\odot g_t.$$

这里 $\odot$ 为逐元素乘法；$v_t$ 不是减去均值后的方差。零初始化时，恒定梯度下有 $m_t=(1-\beta_1^t)g$、$v_t=(1-\beta_2^t)g^2$，由此得到偏差校正：

$$\hat m_t=\frac{m_t}{1-\beta_1^t},\qquad
\hat v_t=\frac{v_t}{1-\beta_2^t},\qquad
d_t=\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon},\qquad
\theta_t=\theta_{t-1}-\eta_t d_t.$$

除法和平方根均逐元素。较大的历史平方梯度会增大对应分母，但这不是计算完整 Hessian，也不是按矩阵奇异方向归一化。偏差校正补偿零初始化，不意味着能消除数据非平稳性或梯度估计偏差。算法来源：[Adam 原论文](https://arxiv.org/abs/1412.6980)。

当 $t=1$、$\epsilon=0$ 且每个梯度非零时，$d_1=\operatorname{sign}(g_1)$。这是首步的特殊结果，后续依赖历史，并非每步都做 sign 更新。正 epsilon 还会改变小梯度区域的尺度。

| 配置 | 控制什么 | 需要观察的后果 |
|---|---|---|
| $\eta_t$ | 最终更新尺度及其调度 | 更新/参数范数、loss 和验证曲线 |
| $\beta_1$ | 一阶历史的保留 | 方向平滑与方向改变后的响应 |
| $\beta_2$ | 平方梯度历史的保留 | 尺度变化后的适应、尖峰的持续影响 |
| $\epsilon$ | 小分母区域的保护和尺度 | 小梯度更新；放在根内或根外不是同一公式 |
| step $t$ | 偏差校正和调度的位置 | 跳步、缺梯度参数和恢复后的计数 |

指数历史的权重按 $\beta^k$ 衰减；$1/(1-\beta)$ 可作时间尺度的粗略直觉，不是固定长度窗口。实际 API 的参数和执行选择见 [PyTorch Adam](https://docs.pytorch.org/docs/2.14/generated/torch.optim.Adam.html)。

<a id="s2-adamw让衰减不进入矩状态"></a>

### AdamW：让衰减不进入矩状态

若目标添加 $\lambda\|\theta\|_2^2/2$，送入 Adam 的梯度变为 $g_t+\lambda\theta_{t-1}$。衰减会进入 m/v 并被自适应分母缩放。AdamW 则对任务梯度更新 m/v，单独收缩参数：

$$\theta_t=(1-\eta_t\lambda)\theta_{t-1}-\eta_t d_t.$$

这里明确采用学习率乘 weight decay 的约定；其他文献可能把收缩系数单独命名。普通无动量 SGD 中，两种形式按这个约定一致；对 Adam 通常不一致。[AdamW 原论文](https://arxiv.org/abs/1711.05101)。

反例：$\theta_0=[1,2]$、任务梯度为零、m/v 为零、$\eta=0.1$、$\lambda=0.1$、$\epsilon=10^{-8}$。Adam 加 L2 的首步输入为 $[0.1,0.2]$，更新后约为 $[0.9,1.9]$；AdamW 的自适应项为零，得到 $[0.99,1.98]$。这里任务梯度是显式零张量；`grad=None` 是否跳过衰减要查具体实现。

哪些参数进入 decay 组是配方的一部分。Bias、norm、embedding 和共享参数应按所用规则记录；“命令行叫 adam”也不证明使用耦合 L2，见[源码中的后端选择](<../appendices/source/megatron/03_state_and_memory/04_adam_muon_execution.md>)。

<a id="s2-两步数值推演历史怎样改变方向"></a>

### 两步数值推演：历史怎样改变方向

固定外部梯度序列 $g_1=[2,-1]$、$g_2=[0,3]$，初始参数 $[1,-2]$，学习率 0.1。Momentum 取 $\beta=0.5$；Adam/AdamW 取 $\beta_1=\beta_2=0.5$，初始状态为零，$\epsilon=0$；本例每步 v 的每个元素均为正。只有 AdamW 加 $\lambda=0.1$。这些数值为了手算，不是训练推荐值，也不是收敛实验。

| Adam 状态 | 第一步 | 第二步 |
|---|---|---|
| $m_t$ | $[1,-0.5]$ | $[0.5,1.25]$ |
| $v_t$ | $[2,0.5]$ | $[1,4.75]$ |
| $\hat m_t$ | $[2,-1]$ | $[2/3,5/3]$ |
| $\hat v_t$ | $[4,1]$ | $[4/3,19/3]$ |
| $d_t$ | $[1,-1]$ | $[1/\sqrt3,5/\sqrt{57}]\approx[0.577350,0.662266]$ |

第二步第一个坐标当前梯度为零，Adam 仍因历史动量继续更新；第二个坐标的当前梯度从负转正，历史也使更新不同于直接减去 0.3。

| 优化器 | 第一步参数 | 第二步参数 |
|---|---|---|
| SGD | $[0.8,-1.9]$ | $[0.8,-2.2]$ |
| Momentum | $[0.8,-1.9]$ | $[0.7,-2.15]$ |
| Adam，无衰减 | $[0.9,-1.9]$ | $[0.842265,-1.966227]$ |
| AdamW | $[0.89,-1.88]$ | $[0.823365,-1.927427]$ |

AdamW 第二步例如第一坐标为 $0.99\times0.89-0.1/\sqrt3$。同一个真实 loss 上，各方法走到不同参数后，第二步梯度会改变；固定梯度例只隔离更新规则。

CPU 对照见[优化器数值参考](<../examples/optimizer_walkthroughs.py>)。跨 rank 归约、裁剪、AdamW 更新与 Inf 跳步接成完整一次 step 的推演见[训练更新](<../04_Training/12_数据管线与训练循环.md#s1-一次完整更新从缩放梯度到adamw与跳步>)。

<a id="s2-状态融合与分片"></a>

### 状态、融合与分片

| 方法 | 本节配方的持久优化器张量 | 更新的耦合范围 |
|---|---|---|
| SGD，无动量 | 无 | 单个参数元素 |
| Momentum | 一个动量张量 | 单个参数元素的时间历史 |
| Adam/AdamW | m 和 v | 单个参数元素的时间历史 |
| 标准 Muon | 一个动量张量 | 一块逻辑矩阵内的奇异方向 |

这里不计参数、梯度、master weight、步计数与工作区；AMSGrad、自适应 Muon 等变体另有状态。相同精度下，两个 Adam 矩改成一个动量可减少这部分持久字节，但矩阵算法还会增加临时计算与通信。

Adam 的逐元素结构允许 owner 在拿到正确全局梯度与对应 m/v 后更新自己的元素分片。全局 norm、非有限值决策、共享参数和参数同步仍需要跨 rank 协作。Fused/foreach 改变提交和读写方式，CPU offload 改变执行位置，它们不是新的更新公式；数值等价还需检查 dtype、舍入和操作顺序。[PyTorch AdamW](https://docs.pytorch.org/docs/2.14/generated/torch.optim.AdamW.html)。

恢复训练应保留参数组到张量的身份、m/v、计数、学习率调度与必要精度状态。只恢复权重或重新初始化矩，会改变上述第二步。一般恢复协议见[Checkpoint](<../04_Training/18_Checkpoint与故障恢复.md#s2>)，低精度状态见[训练精度](<../04_Training/13_精度激活与训练状态.md#s2>)。

## 本章回顾

反向传播沿依赖累加梯度，保存与重算决定中间状态的寿命。优化器将当前梯度与历史状态结合，因此参数更新和恢复都不能只考虑权重。
