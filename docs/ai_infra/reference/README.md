# 证据范围与书稿维护

## 正文与附录的分工

[全书目录](../README.md)定义唯一的七篇、32 章阅读顺序。正文解释继续阅读必需的定义、机制、推导和算例；附录保存特殊模型、历史、论文、固定源码与工具材料。新增内容先判断所属章节，不新建面向训练、推理、设计、Agent 或 Omni 的平行学习路线。

正文每章只有一个标题和一组章末前后章导航。章内小节可以有局部目录；附录使用主题查询目录，不增加与正文竞争的前后篇导航。普通交叉引用不改变章节顺序，也不把附录变成正文的隐含前置。

训练篇完整维护数据、目标、更新、精度、状态、并行、收敛和恢复；推理篇维护生成、KV、调度、容量和服务；RL 篇在两者基础上增加反馈、轨迹、行为概率、版本与环境。通用硬件、算子和通信原理由前面的共同基础维护。综合案例连接原理和指定实现，不再重写一套算法教材。

## 公式、引用与验证

公式在附近定义符号、形状、单位和成立条件。教学数字、源码行为和设备测量分别标明。数学推演、CPU 示例、源码检查和 GPU 实测证明不同层次，不能用链接通过或程序可解析替代事实核验。

首次承担推理作用的术语应说明“对象是什么、怎样起作用、在本段为何重要”，不能只展开英文缩写。成本与数值结论还应给出成立条件，必要时用小算例展示原因；例如纯负载应展开元素数与每元素字节，混合精度应分别说明输入、累加和输出。附录允许引用正文前置，但仅有术语索引不能替代关键语境中的解释。同名词需按语境分开说明，例如训练与推理的 DP、缓存保留策略与主机页锁定的 pinned。

来源紧邻相关结论，必要时在章内列参考资料。原理不依赖某个框架版本；具体支持状态、性能数字与实现分支必须说明版本和负载条件。书稿结构调整不自动更新既有技术结论，也不宣称旧快照是上游最新状态。

## 数值程序与实验边界

[配套程序](../examples/README.md)包含张量、梯度、优化器、并行归约、预算和状态机等教学核对。标准库脚本不执行真实 NCCL、Transformer Engine 或大模型训练，不证明端到端容错、性能或长期收敛。

[CPU 实验报告](cpu_evidence_20261012/report.json)保留原始计时、输入、trace、源码 hash 与进程退出恢复结果；它不覆盖 GPU、多机和实际模型质量。[Omni 核对结果](omni_checks_20261012.json)只覆盖其声明的数学与离散状态模拟，不是媒体质量或实时硬件测量。

设备带宽、阶段耗时、成功率与成本单位若标为教学输入，替换后需重新核对容量、依赖和质量约束。本次书稿整理不新增 GPU、集群、服务或模型质量实测。

## 文件与检查

正文章节位于 `01_Introduction` 至 `07_Practice`；附录位于 `appendices`，CUDA 配套实验保留在 `cuda`，通用数值程序在 `examples`，原始证据在 `reference`。目录迁移后修复仓库内链接，不保留重复正文或旧路线跳转页。

运行 `python3 tools/validate_learning_docs.py` 检查 Markdown 本地链接、锚点、标题、代码围栏、可达性、正文章序与 Python 示例语法。若修改了数值算法或生成证据的程序，还应运行对应的有意义验证。

编辑参考文献见[资料调研记录](中英文资料调研与阅读方法.md)。这份记录服务于作者，不定义读者的学习顺序。
