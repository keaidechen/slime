# 目录整理记录

本次整理把原 `learn_docs` 与 `docs` 下的源码走读、模型架构、性能分析、论文、Runtime 对比及 CUDA 材料收拢到 [AI Infra 深入解析](../README.md)。仓库中英文 README 与文档 README 都指向这个入口，产品使用文档仍保留在 `docs/en` 和 `docs/zh`。

## 目录怎样分工

`00`–`11` 解释基础机制与设计取舍，`12_Performance_Reliability` 集中性能方法、观测、跨层案例与恢复，`13_Source_Analysis` 跟踪固定版本实现。`papers` 保留论文的问题与论证，`runtime` 比较系统边界，`cuda` 通过完整示例解释执行过程；它们都由总入口和相关原理文章连接。

每个知识点优先维护一处完整解释。相邻文章用必要的短回顾与链接承接上下文，不再复制整段定义。公式、执行顺序、数值算例和有区别的实现边界继续保留。

## 删除与合并的内容

- 删除 112 个旧路径兼容页，以及重复目录清单、逐章节迁移台账、已完成的计划和重复阅读路线。
- 旧学习笔记中的独有 GPU 层次说明并入 [GPU 执行与内存基础](../03_Hardware_Systems/GPU执行与内存基础.md#gpu-hierarchy)，删除重复笔记、图示片段及其图片副本。
- 合并 GEMM、Grouped GEMM 与算子库文章中重复的定义；删除论文和 Runtime 文章中重复的结尾总结、自测问题与二次引言。
- CUDA 的练习要求改成正文中的不变量、反例和边界分析，保留完整程序作为辅助材料。
- 删除无仓库内引用的迁移锚点与重复页尾导航，章节目录按实际正文重建。

旧文件 URL 不再保留跳转页；仓库内链接已随路径更新。外部书签需要改为新入口或新文章路径。

## 过时信息怎样处理

RL Infra 综述从滚动的产品支持矩阵、路线图和无条件性能比例，改为编排、数据流、策略版本与资源边界的分析。比如旧稿把 NeMo RL 的 SGLang、Muon 和投机解码统一列为规划项，而 [v0.6.0 发布说明](https://github.com/NVIDIA-NeMo/RL/releases/tag/v0.6.0)已列出相关功能；具体后端覆盖仍需按该版本说明理解。历史方法和原论文结论保留其时间与工作负载条件。

源码基线和历史哈希仍见 [维护规则与证据范围](README.md)，不会因为整理目录而覆盖旧证据。此次没有把所有旧文的技术事实重新审计一遍，也没有执行 GPU 性能测量。

## 瘦身规模与检查

以第一轮整理前的相关目录及重构提案为基线，Markdown 从 384 篇降至 264 篇，正文与导航合计体积约减少 16%；加上清除的重复 JSON 台账与图片副本，相关文件总体积约减少 42%。这些数字描述文件规模，不把删除跳转页等同于删除知识点。


`python3 tools/validate_learning_docs.py` 直接检查实际文件的链接、锚点、标题、代码围栏、从入口的可达性与 Python 示例语法。首轮检查覆盖当时的 264 篇正文及 3 个仓库入口；Markdown 解析与 7 组 CPU 参考程序通过，24 个源码文件及符号记录与历史快照相同。主仓库提交不同的情况保留在证据说明中。

CPU 参考程序用于核对数学状态和路径迁移；它们不替代框架集成验证或 GPU 编译、并发及性能验证。

## 第二轮：围绕阅读主线编辑

首页改为默认主线、专题查询和源码深读三种入口；[26 篇主线](../guides/系统阅读路线.md)按计算、GPU、内存通信、训练、推理、RL、性能可靠性推进，文章末尾说明下一问题为何出现。[专题导航](../guides/专题导航.md)承担完整目录。

第二轮检查覆盖 262 篇 Markdown 与 3 个仓库入口，3,107 个本地链接无错误；26 篇主线的双向导航与过渡、全部 Markdown 解析、7 组 CPU 参考程序均通过。源码证据的 24 个文件与符号记录未改变，历史主仓库提交差异继续保留。
