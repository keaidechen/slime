# 从一次计算到完整系统：26 篇阅读主线

这条主线建立共同语言，不要求先读完所有基础专题。每一阶段都沿前一阶段留下的问题前进；特殊模型、八类并行的其他分支和框架源码放在相应专题中深入。

只需要能读基本 Python 和矩阵乘法记号；公式中的符号、形状与假设在正文解释。数字电路、Linux 环境等可从[专题导航](专题导航.md)补读。

## 怎样完成第一遍

进入第 1 篇之前，可先读[系统全景与设计方法](../design/系统全景与设计方法.md)，看一次生成、一次更新和一轮 RL 如何连接。下表仍保留 26 篇机制主线；完成相关基础后，再沿[系统设计路线](系统设计阅读路线.md)把负载、质量、预算和候选方案放在同一张表里比较。

沿下表顺序阅读正文中的概念与小算例。标有“进阶选读”“源码”“架构细节”的部分可以第二遍再看；这些链接用于向下深挖，不要求每遇到一个链接就跳出当前文章。第一次的目标是能画出数据和状态的变化，而不是背完缩写或装齐工具。

本系列反复使用五个问题：**算什么，存什么，谁负责，何时可用，怎样证明结果正确且更快？** 每换一个层次，把相同问题应用到新对象上：

| 层次 | 需要跟踪的对象 |
|---|---|
| 模型 | 张量形状、预测概率、损失与梯度 |
| GPU | 工作块、片上存储、显存搬运与执行依赖 |
| 多卡训练 | 参数/梯度分片、通信结果与更新边界 |
| 推理服务 | 请求、历史 KV、批次与输出顺序 |
| RL | 轨迹、行为概率、奖励与模型版本 |
| 性能与恢复 | 关键路径、有效产出与一致恢复点 |

遇到一个公式，先为每个量写单位：元素数、字节、秒、字节/秒不能混加。相同字母会在不同公式中复用，以当前定义为准。例如张量的 B 常是 batch，通信带宽用 BW；概率 p 与并行度 p 也需按上下文区分。

## 七个阶段自测

每完成一个阶段，先独立回答，再展开核对。若答不出，回到对应小算例即可，不需要从头重读整条主线。

| 读到这里 | 用自己的话或数字回答 |
|---|---|
| 第 3 篇 | `[2,3]@[3,4]` 输出形状是什么？一个参数为何会有来自多条路径的梯度？ |
| 第 6 篇 | A 写 X、B 读 X，分别提交到两个 Stream 后，B 能直接运行吗？分块为何能减少读取却不减少乘加数量？ |
| 第 9 篇 | `[1,2]` 与 `[10,20]` 做求和 AllReduce、AllGather 分别得到什么？为什么通信消息变大十倍，耗时不一定十倍？ |
| 第 15 篇 | DP、TP、FSDP、PP 分别拆分什么？两卡局部有效 token 数不等时，为什么不能直接平均局部平均梯度？ |
| 第 19 篇 | 3 个 prompt token 完成 Prefill 并采出首个输出后，已计算 KV 长度是多少？三个 token 在 100/120/170 ms 返回时，TTFT 与后两个 ITL 是多少？ |
| 第 22 篇 | 训练版本 13、可服务版本 12、样本行为版本 11 能否同时存在？样本应保存哪一版的行为概率？ |
| 第 26 篇 | A=4 ms 后 B=6 ms、C=3 ms 并行，再执行 D=2 ms，只加速 C 会缩短总时间吗？训练恢复为什么不能只加载权重？ |

<details>
<summary>核对答案与常见误解</summary>

1. 输出 `[2,4]`；共享参数通过多条依赖路径影响损失，各路径贡献相加。转置与视图改变布局，不会凭空改变数学元素数。
2. 跨 Stream 需要明确依赖，并保证 X 的存储仍有效；分块让读入的数值被多个输出复用，数学乘加仍然相同。
3. 求和 AllReduce 为 `[11,22]`，AllGather 为 `[1,2,10,20]`；固定启动成本不会随消息字节数同比增长。
4. DP 分数据，TP 分层内计算，FSDP 分重复状态并按需展开，PP 分层与调度。局部均值直接平均给每个 rank 相同权重，不一定给每个有效 token 相同权重。
5. 此时已计算 KV 长度是 3；刚采出的 token 尚未进入下一次前向。假设请求在 0 ms 到达，TTFT=100 ms，ITL 分别为 20、50 ms。
6. 可以。样本的行为概率必须对应实际生成它的版本 11 及采样处理；发布新权重不能改写旧样本身份。
7. 总时间为 12 ms，B 较长，单独缩短 C 不改变它。训练续跑还依赖优化器、更新计数、数据游标，以及实现所需的随机数等状态。

</details>
