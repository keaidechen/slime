# Omni 能力与架构边界

一个用户上传会议视频，请模型解释争论原因，并希望听到语音回答。这包含至少三件不同的事：从画面和声音中获得信息，形成回答，把回答变成声音。把它们统称为“多模态”容易掩盖各阶段的限制。

本篇是 [Omni 支线](<README.md>)的起点。先建立能力边界，相关资料再计算媒体表示；不需要先记住具体模型名称。

## 模态、表示和能力是三层概念

**模态（modality）**是信息的形式，例如文本、图像、音频、视频。**表示（representation）**是模型处理它的数值形式，例如词表索引、图像 patch 特征、音频特征帧。相同信息可以有多种表示：一句话既能表示成文字，也能表示成包含音色、停顿和语调的波形。

**能力**则是系统在指定输入下能完成什么任务。把声音转成文字的自动语音识别（ASR）可能保留说了什么，却丢掉背景声和部分情绪信息。文本转语音（TTS）接收文字并生成声音；会做 ASR 和 TTS，不自动保证系统能理解音乐、对齐视频或保持多人说话身份。

| 要验证的维度 | 一个可执行的问题 | 不能由此推出的结论 |
|---|---|---|
| 输入理解 | 仅给音频，能否区分门铃声与口头描述门铃？ | 能生成自然语音 |
| 输出生成 | 能否根据文字生成一段指定内容的语音？ | 能生成图像或视频 |
| 跨模态对应 | 能否指出视频中谁在何时说话？ | 只要图像和声音分别理解正确就已完成对应 |
| 流式输入 | 不等完整文件，能否处理不断到达的片段？ | 可以输出流式结果 |
| 流式输出 | 完成全部生成前，能否交付可播放的音频块？ | 模型能在发声时继续听懂用户 |
| 全双工交互 | 双方同时发声时，系统能否继续理解、响应与停止旧回答？ | 所有打断、回声和重叠说话都能正确处理 |

全双工（full duplex）强调两个方向能够同时推进。网页一边上传麦克风数据一边播放音频，只证明传输同时进行；模型是否消费新增输入、如何避免把自己的回声当成用户、何时停止旧输出，仍需模型和交互协议共同支持。

## 三种组合方式

**级联系统**把任务拆给专门模型，例如音频 → ASR → 语言模型 → TTS。每段易于独立替换和测量，但文字这个中间接口可能丢掉笑声、重音等信息；中间错误也会传播。级联可以做流式处理，不能简单把“级联”和“非流式”画等号。

**共享理解骨干**通常让音频/视觉编码器把媒体变成特征，再映射到语言模型可消费的宽度。编码器（encoder）提取特征；投影层（projector）转换特征维度。接入方式可能是把媒体位置放进序列，也可能通过交叉注意力读取独立特征。两者的 KV 和长度成本不同，必须先确定结构。

**理解与生成协同的系统**还包含音频或图像生成分支。共享骨干并不意味着只有一个计算模块、一个词表或一种训练损失；媒体生成可能采用离散自回归、连续值迭代或两者组合。“端到端训练”描述优化路径能否覆盖多个模块，“一个服务端点”描述产品接口，它们不是同一件事。

```text
级联语音：波形 → ASR → 文字 → 语言模型 → 文字 → TTS → 波形
特征路径：波形/画面 → 编码器 → 特征 → 理解骨干 → 文字/生成条件
生成分支：生成条件 → 语音或图像生成器 → 媒体解码器 → 可播放/显示数据
```

不要把上图每个箭头都理解为网络 RPC。同进程函数、同机设备间传输和跨机服务调用都可以实现一个箭头；部署选择在第五篇讨论。

## 用真实模型校准名称

Qwen3-Omni 的报告描述文本、图像、音频、视频输入以及文本和语音输出；其 Thinker–Talker 架构和语音解码路径说明“Omni”可以包含专用生成模块，而不意味着任意模态输出。[Qwen3-Omni 技术报告 v1](https://arxiv.org/html/2509.17765v1)

Moshi 将用户与模型自己的语音建模为并行流，是理解全双工建模的一个具体入口。它帮助我们提出“模型在说话时如何继续接收对方”的问题，不能代替具体部署中的打断和回声测试。[Moshi 技术报告](https://arxiv.org/abs/2410.00037)

这两个例子用来校准概念。本系列下面的尺寸和时间数字使用独立的教学配置，不移植论文的性能数字，也不假定所有 Omni 模型结构相同。

## 两个案例为什么需要不同账本

案例 A 接收 10 秒音频，输出可连续播放的语音。输入有采集时间，输出有播放期限；关键状态包括编码器特征、理解骨干 KV、语音生成状态、待播放缓冲。某段内容即使已生成，只要没有播放，就不能当作用户已经听到。

案例 B 根据文本和可选参考图生成一张图。条件编码完成后，生成器可能多次更新同一份连续 latent；latent 是压缩空间中的中间表示。主要状态是当前 latent、迭代步、随机数状态和条件特征，完成前通常没有一张合格的最终图可交付。两者都需要调度，但工作的推进单位不同。

为任何新模型建立一张能力卡：输入/输出模态、表示方式、条件依赖、是否接受增量输入、最小可交付输出、取消边界、训练与推理时的可见上下文。遇到“原生多模态”“统一生成”等命名时，用这张卡还原实际计算。

## 自测

**能接收视频并回答文字的模型，是否已经是视频生成模型？** 不是。输入编码器能理解视频，与生成连续视频帧所需的输出模型、训练目标和解码器是不同能力。

**为什么不能只保留 ASR 文本来复现一次音频理解请求？** 文字可能没有背景声、说话人、时间信息；还应记录原媒体身份、预处理配置和使用的模型版本，才能知道复现时输入是否相同。
