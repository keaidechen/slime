# 多模态与扩散计算：工作量、状态与系统边界


## 一张图片怎样进入语言模型

典型路径为媒体解码→resize/crop→patch embedding→视觉 encoder→projector→与文本 embedding 组合→语言模型。视觉指令模型的代表设计见 [LLaVA](https://arxiv.org/abs/2304.08485)，patch Transformer 的基础见 [ViT](https://arxiv.org/abs/2010.11929)。下面的数字是自行构造的算例，不对应两篇论文的默认配置。

假设图片边长 224，patch 边长 14，无额外 CLS、无多 crop、无 token 压缩。视觉 token 数为 (224/14)²=256。把分辨率升到 448，视觉 token 变为 1024；encoder 中完整 Attention 的 score 元素数随之增加为 16 倍，线性投影部分约随 token 数增加四倍，因此不能把整个 encoder 耗时说成 16 倍。

若视觉特征宽度为 1024、用 BF16 保存，256 个 token 的特征纯负载为 0.5 MiB，1024 个为 2 MiB。Projector 可以改变宽度或 token 数；若有 pooling、resampler、动态分辨率切块，应以输出特征序列重新计数。

## 视觉长度如何进入语言模型账本

再固定文本长 128，所有视觉特征直接作为 decoder 的前缀位置。两种分辨率下 LLM 序列分别为 384 和 1152。完整 Attention 的 S² 项增加九倍，而不是单独视觉 token 的十六倍；只算文本 token 会漏掉大部分工作。

假设标准 KV 模型有 32 层、8 个 KV heads、head dim 128、每元素 2 字节，每驻留位置为 128 KiB。两种请求的前缀 KV 纯负载分别为 48 MiB 和 144 MiB，不含页对齐、输出增长与 workspace。

视频若逐帧独立编码 16 帧、每帧 256 个特征，且全部送入同一 decoder，则总序列为 4096+128=4224，前缀 KV 为 528 MiB。若实际模型使用时空 Attention、特征压缩或 cross-attention，以上公式需改写。音频同样应从采样、特征帧率和 encoder 下采样率推导长度，不能直接按音频字节换算文本 token。

## 训练与服务各自增加哪些约束

视觉特征可以参与 Attention，却未必对应词表预测目标。对只训练回答的监督任务，图像位置和 prompt 位置通常按目标定义屏蔽 loss；这与是否允许关注图像是两件事。冻结 encoder 时，可在输入和参数身份相同时缓存其特征；解冻后还需要反向激活与优化器状态，旧特征缓存可能失效。

一次请求的 TTFT 包含排队、媒体下载／解码、encoder、投影和 LLM prefill。若两个 encoder 各能供给 20 图/秒，LLM 池可消费 30 图/秒，忽略其他阶段的稳态上界仍为 30 图/秒；增加第三个 encoder 不能提高这个上界。以图/秒比较还必须固定分辨率、帧数和文本长度。

Encode–Prefill–Decode 分离需要传递 feature 与 KV 两类状态，各自携带模型／processor 版本、位置、有效长度、dtype 和所有权。相同 URL 或相同 placeholder token 不代表相同图片。部署与取消的具体边界见[多模态服务](<../../05_Inference/23_服务部署与容量设计.md#s2>)。

## 扩散训练的噪声目标

在 DDPM 的噪声预测表述中，选时间步 t、采样 ε∼N(0,I)，构造：

$$x_t=\sqrt{\bar\alpha_t}x_0+\sqrt{1-\bar\alpha_t}\epsilon,$$
$$L=\|\epsilon-\epsilon_\theta(x_t,t,c)\|^2,$$

其中 ᾱ_t 是到 t 的保留信号比例，c 表示可选条件。训练常采样时间步并执行一次网络前反向，不需要每个训练样本都展开完整生成链。不同参数化、loss 权重和 flow matching 目标应另行说明，不能都套噪声预测损失。算法基础见 [DDPM](https://arxiv.org/abs/2006.11239)。

标量例：x₀=2、ᾱ_t=0.64、ε=−1，得到 x_t=0.8×2+0.6×(−1)=1。若预测 ε̂=−0.5，则重建 x̂₀=(1−0.6×(−0.5))/0.8=1.625，重建误差 −0.375，未加权噪声平方误差为 0.25。该结果验证一次转换，不表示执行了一步特定采样器。

## 扩散推理怎样核算工作量

生成从噪声状态开始，按采样器的时间序列反复调用去噪网络，再更新 latent。一步依赖上一步的 latent，条件编码可能复用，latent 相关的中间状态通常会变化。不能直接套用自回归 LLM 的 KV 追加缓存；跨步特征缓存需要专门验证近似误差。

以 latent DiT 为例，假定图像空间下采样 8 倍，latent patch 边长为 2。512×512 图像对应 (512/8/2)²=1024 个 token；1024×1024 图像对应 4096 个 token。完整 Attention 的 S² 项为 16 倍。这里没有声称每个 DiT 都使用这一配置；Transformer 去噪网络的设计参考 [DiT](https://arxiv.org/abs/2212.09748)。

设条件编码 50 ms，20 次去噪各 40 ms，最终解码 30 ms，且全部串行，总时延为 880 ms。减少步数可以降低调用次数，但可能改变质量；classifier-free guidance 的条件／无条件分支可能增加网络求值量，合并 batch 后的墙钟变化需要实测，不能简单宣布时延恰好翻倍。

## 比较性能时保持同一任务

多模态至少固定媒体内容、分辨率、crop／帧采样、processor、文本、输出限制与评估集。扩散还应固定或明确比较 seed 集合、采样器、步数、guidance、分辨率和质量目标。只固定 seed 不保证更换算法后输出相同；像素差异也不能独立代表感知或任务质量。
