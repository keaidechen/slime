# 一套并行方案如何同时满足容量、通信与正确性

并行配置把计算图映射到设备，但设备数量只是约束之一。模型能否放下取决于状态峰值，训练是否更快取决于暴露的通信与不均衡，结果是否仍正确则取决于布局转换、梯度语义和更新边界。


## 从模型与工作负载确定状态

总参数与激活参数区分 MoE 的容量和每 token 计算；layers、hidden、intermediate、词表及 tied embedding 决定权重形状。MHA/GQA/MLA/sparse/linear 的历史状态不同，heads/KV heads/head dimension 不能互换。expert 数、top-k 与 shared experts 进一步决定路由和算子形状。

序列 p50/p95/max、micro/global batch 和梯度累积决定激活与调度。参数、梯度、优化器、激活和 KV 的 dtype 应分别核算；只写“FP16 模型”无法推导训练峰值。

## 逻辑网格必须落到物理拓扑

节点数、每节点 GPU/HBM、PCIe/NVLink/NVSwitch、每节点 NIC 与链路速率、IB/RoCE、GPU–NIC 亲和性和跨机架超售限定可用通信路径。点对点与 collective 的有效带宽属于不同口径。

在这里讨论的标准 decoder 网格中，dense 层满足 `W=TP×CP×DP×PP`，expert 层满足 `W=ETP×EP×EDP×PP`。SP 复用 TP 组，状态分片的 DP shard/replicate 是 DP 内部分解，不能再次乘到 world size 外。PP groups 是否一致、VPP chunks、CP 通信类型和 ETP 的最终展开值都是执行的一部分；ETP 未显式指定时不能自动当作 1。

## 每次布局转换都有消费者

| 状态 | 需要同时解释的内容 |
|---|---|
| QKV、MLP 和 expert 权重 | global shape、每 rank shard、replica group、前反向消费者 |
| residual activation | token/hidden 分片、norm 边界、保存与回收时机 |
| KV 或 recurrent state | 请求/序列归属、历史访问方式、并行复制与分片 |
| logits | 词表切分、归一化与目标 token 的全局语义 |

同形状张量可能是副本，也可能是部分和。布局标签和从上一算子到下一算子的通信，决定它的数值含义。

## 峰值不能按总量平均

参数、梯度、优化器、激活是持久与阶段性状态；通信 buffer、workspace、CUDA Graph、分配器碎片与预留余量增加物理占用。Full-parameter gather、prefetch、PP 在途激活和 MoE 临时重排会重叠。稳定占用下降并不保证峰值下降。

通信还需要阶段、group、原语、shape×dtype、频率和 exposed time：TP 前向、DP 反向、PP 边界、CP Attention、EP dispatch/combine、ETP token AG/output RS、EDP 专家梯度同步，以及 RL 换权分别发生在不同依赖位置。

## 组合增加了哪些失效方式

从单算子到一个并行维度，再到两维转换、节点内完整配置、跨节点和全规模，新增的约束依次包括数值、布局、拓扑、算法切换、长尾与恢复。真实长度和 routing 分布会暴露固定 synthetic batch 看不到的不均衡。

正确性要求全局目标分母一致，TP/CP/EP 重排保留 token、mask 和 position；PP 首尾 tied weight 的梯度与更新相容；FSDP/TP 重分片恢复保持参数语义；overflow 与 clipping 使用正确的 group。切换 ETP 时，expert ID、FC1/FC2 shard、输入梯度和每专家参数梯度必须对应，同时 EP/EDP 也可能改变。RL 额外要求 policy version 与行为 logprob 对齐。

## 性能收益与常见反例

| 现象 | 可能的机制 |
|---|---|
| TP 增大反而变慢 | GEMM 变小、collective 固定开销占比增加或跨节点 |
| PP 气泡大 | microbatch 不足、stage 不均衡、P2P 暴露 |
| CP 对长短样本表现差异大 | 固定 degree、causal 不均衡或 packing 元数据 |
| EP 的 p99 抖动 | 热专家、变长 All-to-All 与专家 GEMM 不均衡 |
| FSDP 仍然 OOM | full-param/prefetch 峰值、unit 颗粒度、workspace |
| loss 随 world size 变化 | 分母、reduction group 或梯度重复计数 |
| collective 挂起 | 组成员、调用次序、步数不一致或 rank 先失败 |

tokens/s/GPU、step p50/p95/p99、峰值 HBM、暴露通信、PP bubble/最慢 stage、EP max-to-mean、强弱扩展效率共同描述训练成本。MFU 与 HFU 的 FLOPs 分子不同；服务还看 TTFT/TPOT/goodput，RL 还看 sample-to-update 与 policy staleness。

一套合理配置应说明为何放弃其他选择、显存和性能余量、版本限制、回退配置与回归阈值。它是带着前提的设计决定，不是通用最优的一组 degree。
