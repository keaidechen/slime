# Omni 并行与执行优化

[评估篇](<../performance/Omni性能与质量评估.md>)确定了质量与时延口径。本篇按瓶颈选择优化：先知道哪个阶段消耗多少工作和状态，再决定副本、切分、编译或近似。增加 GPU 数量本身不构成优化结果。

## 多阶段流水与模型内部并行

案例 A 的编码器、理解、语音生成和波形解码可以分别调度。跨阶段流水允许不同请求占据不同阶段；同一请求的相邻块也可能在条件就绪后重叠。这与把一个 Transformer 的层切成训练 PP 不完全相同，前者包含不同模型和不同推进单位。

| 方法 | 改变的工作分配 | 要额外核对的边界 |
|---|---|---|
| 阶段副本 | 多个完整阶段处理不同请求 | 路由、状态黏性与尾部负载 |
| TP（张量并行） | 一层的矩阵/Attention 工作跨设备切分 | 小步通信与局部工作量是否匹配 |
| PP（流水线并行） | 层或模块跨设备顺序执行 | 依赖、气泡、首音频路径 |
| CP/SP | 序列上下文或特定激活布局切分 | 全局注意力、时间/空间边界与重排 |
| EP | MoE 专家分布到不同设备 | 路由不均、all-to-all、模态带来的负载变化 |

这些方法的基础推导在[八类并行主线](<../../04_Training/14_数据并行与状态分片.md>)。音视频长度和分辨率会改变每阶段的负载分布；不能把文本模型的并行配置不加核算地移到所有模块。

## 案例 A：先复制瓶颈，再检查新的瓶颈

沿用[运行时篇](<../serving/Omni多阶段运行时.md>)的完整请求服务量 `[40,100,80,20]` ms。各阶段独占设备、单副本、忽略通信时，上限是 10 请求/秒；理解阶段变成两个副本后，上限是 12.5；再复制语音阶段，上限是 20；再复制理解阶段到三个，上限是 25，编码器成为瓶颈。

这个结果只用于容量推理。真实的批处理可让单位请求服务量下降，但等待组批会增大延迟；设备共享和带宽竞争也可能使服务量上升。实测时应记录阶段 busy time、队列时间与每种负载形状，不能仅凭 GPU utilization 判断哪个阶段值得复制。

若编码器特征跨机传输，本例每请求 512000 字节；若误把媒体部分全部 KV 当作交接负载，则是 31.25 MiB，约大 64 倍。正确的跨阶段接口会直接影响拆分收益。分离编码与语言推理和分离 prefill/decode 是不同边界，分别核对数据格式及重用条件。

## 共置、拆分与执行重叠

共置减少传输，适合短小阶段或低负载，但波形解码器与大 prefill 同卡时，可能被长计算延后而错过播放期限。拆分让资源和队列独立，适合工作量不平衡的阶段，代价是传输、跨服务故障和部署容量。

重叠需要独立资源和真实可并行依赖。生产者尚未完成特征时，消费者不能提前读；下游已满时，上游继续产生更多块也不能称为有效重叠。应把设备完成事件、传输完成和消费确认画出来，再考虑异步提交。

## Shape 分桶与 CUDA Graph

CUDA Graph 记录可重放的 GPU 操作图，减少反复提交的 CPU 开销。媒体输入和输出块通常变长，可以按分辨率、帧数、batch 和 chunk 大小分桶，为兼容形状准备执行路径。相关基础见[执行优化与功能组合](<../../05_Inference/22_推理并行量化与执行优化.md#s3>)。

补齐形状可能增加实际计算量；还要保留有效帧、Attention mask 和有效输出采样数。图重放所依赖的地址、缓冲与模块状态必须稳定；取消只改变逻辑有效性时，仍需等待已发出的工作完成后再复用地址。不要把 eager 路径的取消行为直接假定为图路径行为。

量化可以分别作用于编码器、骨干、语音生成器与解码器。权重、激活和 KV 的误差会在不同阶段传播：编码器误差改变理解条件，codec 索引错误可能导致不同音频，波形阶段误差还可能表现为噪声或接缝。校准集应覆盖各模态和长度；容量节省之后仍按[评估篇](<../performance/Omni性能与质量评估.md>)检查任务质量。

## 案例 B：分辨率与迭代数分别放大什么

512×512 图像的 latent 为 `[64,64,4]`、32 KiB，2×2 patch 得 1024 位置。若图像变成 1024×1024，则 latent 变为 `[128,128,4]`、128 KiB，位置数为 4096。位置数扩大 4 倍；朴素全注意力的成对计算项扩大 16 倍，线性层的序列项约扩大 4 倍，所以不能只按像素或 latent 字节推测时延。

以原分辨率的教学预算计算：条件编码 50 ms + 20×40 ms 迭代 + 解码 30 ms + 传输 20 ms = 900 ms。若把步骤从 20 降到 10，且每步成本保持不变，算术预算是 500 ms，速度比为 1.8；质量能否保持必须另测。不能把 1.8 当成已测模型加速。

Classifier-free guidance（CFG，无分类器引导）的一种常见形式把有条件预测与无条件预测组合，例如 `p_u + s(p_c-p_u)`，s 为引导强度，p 的含义由噪声/速度参数化决定。若每步需要两个分支，20 步有 40 次分支求值；把两分支放在同一个 batch，可能只有 20 次批量前向，但工作量并未凭空减半。本例 40 ms 已含所有分支，不重复乘 2。[CFG 原始论文](https://arxiv.org/abs/2207.12598)

视频还增加时间维。若网络同时对空间与时间位置做注意力，简单逐帧独立生成会丢失模型要求的跨帧依赖。可以研究时间/空间切分、窗口或分块解码，但必须明确它们是等价执行还是改变上下文的近似方案。

## 哪些缓存能复用，哪些只是近似

固定文字和参考图的条件编码可按完整身份复用；某些结构还允许缓存独立于 latent 的条件投影。依赖当前 latent、时间步或引导分支的隐藏状态通常不能原样跨步复用。跨步近似缓存是用可接受质量变化换计算量，需要明确刷新策略和误差评估。

减少采样步数、蒸馏、量化、近似注意力和跨步缓存作用不同。应一次改变一个可解释因素，记录求解器、时间网格、引导强度和相同输入的质量结果。固定 seed 可帮助配对，但仍要报告输出差异与失败样本。

## 取消与恢复不能被优化破坏

案例 B 的第 8 步在 330–370 ms 执行，340 ms 收到取消。本例不支持 kernel 中途终止，应丢弃其结果、停止后续步骤，在 370 ms 完成后释放 latent。异步 stream、graph 和双缓冲只会使引用关系更复杂，不会取消这条依赖。

精确恢复至少需要当前 latent、已完成步数、时间网格、条件身份和求解器状态；随机过程还需要 RNG 状态。仅保存 seed 表示可以尝试从头重做，不表示能从第 8 步接着算。若近似缓存属于执行状态，也要决定恢复时重建还是保存。

## 自测

**分辨率翻倍，位置数和 Attention 成对项分别变多少？** 在本例二维 latent/patch 假设下分别是 4 倍和 16 倍，但总时延还取决于其他算子与硬件。

**缓存名称里有 KV，就能跨扩散步复用吗？** 不能。先问它是否依赖正在变化的 latent 与时间步，再判断是否等价。
