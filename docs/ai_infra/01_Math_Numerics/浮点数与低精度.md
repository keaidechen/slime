# 浮点数、数值误差与低精度计算

> 类型：基础概念与方法。前置：[bit 与编码](../00_Physical_Foundations/信息与数字电路.md)。

## 范围与精度

浮点数使用符号、指数和有效数表示有限集合的实数近似。指数位影响可表示范围，有效数位影响相邻数间隔。FP16 与 BF16 都占两字节，但二者指数与有效数分配不同，因此不能只根据字节数判断数值行为。

固定格式下，大幅值附近的相邻可表示数间隔通常更大。很小增量加到很大数上，可能被舍入掉；改变求和顺序也可能改变结果。数学上的结合律不能直接作为浮点逐位相等的保证。

## 存储、乘法与累加精度

一个算子可以用低精度输入、较高精度累加，最后再转换输出。这三者应分别记录。分布式规约树改变加法顺序，融合改变中间舍入位置；它们可能保持可接受误差，但不保证 bitwise 相同。

“结果不同”需要结合误差尺度、条件数和任务质量判断。单个张量的相对误差也不能完整代表训练长期稳定性。

## 数值稳定的表达

Softmax 常使用 $m=\max_i x_i$：

$$p_i=\frac{\exp(x_i-m)}{\sum_j\exp(x_j-m)}.$$

精确数学结果不变，但避免直接对大正数指数化。对于 mask 后全部不可见的行，必须定义合法行为，不能假定减最大值自动处理所有 NaN。

方差、归约和归一化也需要合适的累加与稳定算法。代码中的代数等价不自动代表有限精度等价。

## 量化引入新的状态

示意的仿射量化为 $q=\operatorname{clip}(\operatorname{round}(x/s)+z)$，反量化为 $\hat x=s(q-z)$。scale、zero point、分组方式与布局是表示的一部分。

更小的表示减少字节数，但增加 scale 读取、转换或专用 Kernel 要求。按通道或按块设置 scale 能适应局部分布，也增加元数据和实现复杂度。低 bit 权重文件不意味着每个算子都在相同 bit 宽下完成。

## 问题驱动的分支

| 问题 | 方法 | 需要继续处理 |
|---|---|---|
| FP32 状态与带宽昂贵 | 混合精度 | 范围、累加与优化器状态 |
| 某些梯度难以表示 | loss scaling 等机制 | 溢出检测、跳过更新和缩放管理 |
| 部署容量不足 | 权重量化 | 异常值、解量化与质量 |
| KV 容量或带宽过大 | KV 量化 | 误差随上下文和模型变化 |
| 更低精度需要适应训练分布 | 量化感知训练等路线 | 训练成本与部署一致性 |

Loss scaling 是否必要取决于格式与算法；不能照搬某个 FP16 配方到所有低精度训练。

## 手算舍入：为什么同一个和会得到零或一

以下采用 round-to-nearest、ties-to-even，每次加法后舍入到 BF16，记为 R；输入都是精确可表示的数。BF16 在区间 [256,512) 的间隔为 2，所以 257 位于 256 与 258 的中间，按偶数规则得到 256：

$$R(R(256+1)-256)=0,\qquad R(256+R(1-256))=1.$$

第二种顺序先得到可表示的 −255，再加 256。两个结果的数学目标都是 1。分桶、并行归约树和融合改变中间舍入位置时，就可能出现这种差异。这个反例只模拟指定运算的舍入；真实 GEMM 若用 FP32 累加，并不逐项执行 BF16 加法。

另一个例子从权重 1 开始，每次减 0.001。若每步立即存回 BF16，小更新可能每次都被舍掉，八步后仍为 1；若在 FP32 主权重中累加，主权重接近 0.992，再转换计算副本就能体现变化。主权重保留小更新，并不能消除低精度前反向已经产生的误差。

两个接近的数相减会暴露输入误差。例如真实值 1.001−1=0.001，但二者若都已舍入为 1，随后即使用 FP64 相减也只能得到 0。提高最后一步精度不能恢复此前丢失的信息。

## 从局部误差到训练目标

令参考值为 x、实际值为 y。绝对误差为 |y−x|；相对误差可用 |y−x|/max(|x|,ε)。ε 是报告口径，不能用一个很大的 ε 掩盖接近零处的绝对错误。常见逐元素验收为：

$$|y-x|\le\mathrm{atol}+\mathrm{rtol}|x|.$$

张量范数误差适合看整体偏离，但可能掩盖少量异常通道。应同时保留最大绝对误差、误差分位数、非有限值数量和受影响位置。梯度还应检查方向与参数身份；范数一致不代表各参数的梯度一致。

对线性层 Y=XW，输入和权重误差分别为 ΔX、ΔW：

$$\Delta Y=X\Delta W+\Delta XW+\Delta X\Delta W.$$

因此同样大小的 ΔW，在不同激活方向上可能产生不同输出误差。一个近零参考输出可能来自大项抵消，相对误差会很大；这时应同时看输入尺度和绝对误差。多层网络还有非线性与状态复用，不能把各层相对误差简单相加当作最终质量损失。

对于 logits z，softmax 的局部导数为 ∂pᵢ/∂zⱼ=pᵢ(δᵢⱼ−pⱼ)，选中动作 a 的 logprob 导数为 ∂log pₐ/∂zⱼ=δₐⱼ−pⱼ。共同平移所有 logits 不改变概率；改变相对差值则会改变概率。比较应固定相同输入和动作，报告 logits、logprob、概率分布距离，再单独评估自由生成。RL 的概率比率会消费这些差异，见[行为概率](../11_RL_Systems/行为概率与异步校正.md)。

[数值参考程序](../examples/numerics_quantization.py)通过位操作模拟有限 FP32 输入向 BF16 的舍入，验证上述顺序和小更新反例。它不模拟全部 IEEE 特殊值、GPU 指令或融合算子。数值行为的框架边界见 [PyTorch Numerical accuracy](https://docs.pytorch.org/docs/2.14/notes/numerical_accuracy.html)。

## 验证顺序

固定输入与参考实现，比较输出、梯度和一步更新；再检查不同长度、异常值和 mask；最后评估长期训练或生成质量。记录 dtype、累加方式、容差和硬件 backend。见[RL 数值正确性](../11_RL_Systems/RL数据与数值正确性.md)。
