# AI Infra 深入解析

一次模型计算怎样变成 GPU 上的工作，又怎样跨设备、请求和训练轮次保持正确、高效？这套文章沿这条线索，连接模型、硬件、分布式系统与真实框架。

面向能阅读基本 Python、了解矩阵乘法的读者。首次出现的张量布局、梯度和 GPU 执行概念在主线中解释；更底层的数字电路与特殊模型结构可按需补读。推导、算例和执行时间线都在正文中展开，阅读无需运行实验。

## 第一次阅读：沿一次计算走到完整系统

[从第 1 篇「张量、形状与布局」开始](01_Math_Numerics/张量形状与复杂度.md)，或查看[26 篇默认阅读主线](guides/系统阅读路线.md)。主线分为七段：

| 阶段 | 这一段解决的问题 |
|---|---|
| 1–3：模型计算 | token 如何成为张量，Attention 如何计算，梯度依赖哪些状态？ |
| 4–6：GPU 执行 | 谁计算、谁搬数据，线程与算子怎样协作？ |
| 7–9：内存与通信 | 状态占多少空间，跨设备移动需要付出什么代价？ |
| 10–15：分布式训练 | 一次更新如何拆给多张卡，同时保持目标与梯度正确？ |
| 16–19：推理服务 | 一个请求怎样生成 token，多请求如何共享容量与时间？ |
| 20–22：RL 闭环 | 生成样本怎样成为训练信号，跨版本状态如何相容？ |
| 23–26：性能与可靠性 | 怎样解释等待和性能变化，失败后怎样恢复一致状态？ |

每篇主线文章末尾说明下一篇为什么出现，并提供连续阅读链接。路线页还提供[七个阶段自测](guides/系统阅读路线.md#七个阶段自测)与核对答案；首次阅读可以先跳过标出的进阶和源码细节。已有相关基础时，可以从对应阶段进入。
