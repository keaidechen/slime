# 写作、归属与证据约定

## 条目的最小完整性

概念文章开头说明定义与边界，并链接真正必要的前置。正文解释机制，提供一个可检查的算例、状态图或执行过程，明确代价和不适用条件。结尾连接实现、相邻方法和一手资料。简单术语不必机械填满全部小节。

专题综述负责连接已有条目，围绕问题与约束组织方法。历史沿革应区分原始提出、后续改进、框架采用和当前状态；没有来源时不填写精确年份或“首次”判断。

## 正文归属

一个核心机制有一处主要解释。其他文章可以做必要短回顾，然后链接主条目；模型特有推导、源码差异与实验步骤仍在各自上下文保留。具体分工见[概念关系](概念关系与正文归属.md)。

数学符号首次出现要定义，公式需声明精度、分片、batch 和存储口径。通信与内存算例分别标明每 rank、全局、单向、双向及单位。示意量不写成设备实测。

## 证据等级

| 内容 | 所需依据 | 不能推导什么 |
|---|---|---|
| 稳定概念与数学 | 定义、推导、权威资料 | 所有实现都采用同一种路径 |
| 历史方法 | 原始论文及版本 | 发表较晚就全面替代较早方法 |
| 框架行为 | 代码快照或对应版本文档 | latest 链接永久支持同一 API |
| 性能结论 | workload、硬件、版本与测量边界 | 一个数字适用所有模型和负载 |
| 工程判断 | 写明假设与推理 | 未测量的收益已经成立 |

原稿保留的前沿资料须标为版本相关或待复核。检查链接和语法不能代替技术事实检查。代码示意、可执行脚本与实测记录必须明确区分。

## 目录与链接

领域目录表示概念归属，不表示课程顺序。正文用稳定主题名；术语索引包含中英文和缩写。迁移时同步修改仓库内引用，保留旧路径到新正文的机器可读记录。更改标题时保留仍被引用的旧锚点。

当前文章在 `encyclopedia_catalog.json` 登记，旧稿来源身份在 `document_manifest.json` 保留；不要为了让旧路径看似存在而复制多份正文。新增领域或改变归属时同步修改主目录、关系表和问题索引。
