# RL Infra 学习清单

> 目标：RL 框架与调度、训练／推理性能优化。起点：已有 RL 算法经验，Infra 按初学者处理。预算：每周 20+ 小时，先按约 16 周、320 小时安排。GPU：使用实际可用的 H20，从小负载逐级扩展。

这是一份可勾选的能力清单。勾选代表完成阅读范围与验收，不代表只看过文章。时间用于控制范围；基础未通过时，先减少专项数量，保留基础练习。

每周建议约 7 小时原理/源码、10 小时实践、3 小时整理。每次实验记录环境、输入、命令、正确性和原始数据。下面直接引用主章节，按验收结果记录进度。

## 第 1–3 周：系统与单卡基础，约 60 小时

- [ ] **认出 RL 系统角色。** 读[系统地图](00_Foundations/00_课程与系统地图.md)，再看 [slime 01](../docs/code_walkthrough/01_architecture_and_ray_orchestration.md)的角色与主循环。交付一张控制/样本/权重图；复杂 placement 二读。
- [ ] **固定运行环境。** 读[Linux 课](00_Foundations/01_Linux与运行环境.md)和[基线教程](../docs/performance_analysis_guide/01_baseline.md)。交付实际 H20 型号/数量、driver、框架、节点与可见设备记录。
- [ ] **理解 tensor 的存储与梯度。** 读[PyTorch 系统课](00_Foundations/02_PyTorch张量与自动微分.md)。完成 view/copy/stride 和梯度累积算例；能解释引用与显存。
- [ ] **区分四种异步。** 读[进程线程课](00_Foundations/03_进程线程与四种异步.md)。运行 asyncio 示例，画提交/等待/完成点；Ray 深入留到后面。
- [ ] **理解 GPU 工作与内存。** 读[GPU 基础](00_Foundations/04_GPU执行与内存基础.md)中的 CPU/GPU、内存层级、thread/warp/block/SM、Kernel/fusion/tiling；再读 [CUDA 执行](01_Kernel_GPU_Programming_Compiler/01_CUDA执行模型与调度.md)的入门部分。硬件代际与高级 issue 细节二读。
- [ ] **取得第一份可信测量。** 读[性能语言](../docs/performance_analysis_guide/00_concepts.md)、[PyTorch 操作](../docs/performance_analysis_guide/02_pytorch.md)，完成[实验课](../docs/performance_analysis_guide/07_labs.md)的实验 1–2。交付 warmup/同步/重复统计与一份可解释的 trace。
- [ ] **画模型 shape 与 KV。** 读[Transformer/KV](00_Foundations/05_Transformer执行与KV基础.md)。交付一个 Dense block 的 shape/dtype 和一个明确假设下的 KV 容量算例。

通过条件：能解释一次 Python 调用到 GPU 操作的路径、tensor 为何复制、为什么普通计时会错。资源：CPU + 1 卡；不要求多卡模型。

## 第 4–5 周：通信与并行起步，约 40 小时

- [ ] **两进程两卡。** 读[torchrun 课](00_Foundations/06_两卡通信与torchrun.md)，运行 [collectives.py](labs/collectives.py)。CPU/Gloo 先核对语义，H20/NCCL 再运行；保存 PID/rank/device 与断言结果。
- [ ] **通信原语与模型。** 读[原语](02_Distributed_Communication_Memory/03_通信原语与Collective.md)、[算法](02_Distributed_Communication_Memory/04_Collective通信算法.md)、[性能模型](02_Distributed_Communication_Memory/08_通信性能模型.md)。手画 AllReduce/AllGather/ReduceScatter；做小到大消息扫描。
- [ ] **知道数据走哪条路。** 读[节点内互联](02_Distributed_Communication_Memory/05_节点内GPU互联.md)、[跨节点网络](02_Distributed_Communication_Memory/06_跨节点网络.md)、[NCCL](02_Distributed_Communication_Memory/07_NCCL软件栈.md)。交付实际拓扑图；尚无多机条件时只标待验证，不填虚构带宽。
- [ ] **用小矩阵理解 DP/TP。** 先读 [DDP](03_Parallelism/02_DP与DDP.md)、[TP](03_Parallelism/04_TensorParallelism.md)入门例子，再读[统一布局](03_Parallelism/01_统一切分语言.md)。交付 shard/partial 区别与两卡 Linear 的数值对齐。
- [ ] **理解显存与重叠。** 读[显存核算](02_Distributed_Communication_Memory/02_GPU内存组成与显存核算.md)、[通信重叠](02_Distributed_Communication_Memory/09_通信计算重叠.md)、[Stream](01_Kernel_GPU_Programming_Compiler/10_CUDA_Stream与依赖.md)。记录 producer/consumer 依赖与 buffer 复用边界。

通过条件：不再用“同步一下”代替明确 collective；能分别画逻辑 group 与物理设备图。资源：2 卡起，按实际节点扩展。

## 第 6–8 周：训练执行与训练性能，约 60 小时

- [ ] **跑通一个小训练 step。** 读[Megatron 安装与数据](../docs/megatron_code_walkthrough/01_foundations/00_ecosystem_install_and_data.md)、[训练主线](../docs/megatron_code_walkthrough/01_foundations/02_training_mainline.md)、[模型构建](../docs/megatron_code_walkthrough/01_foundations/03_model_and_transformer.md)。画 batch→forward/backward→optimizer 的调用与状态图。
- [ ] **理解状态分片。** 读[ZeRO/FSDP](03_Parallelism/03_ZeRO与FSDP.md)、[训练显存](02_Distributed_Communication_Memory/10_训练显存优化.md)、[Megatron 优化器](../docs/megatron_code_walkthrough/03_state_and_memory/01_data_parallel_optimizer_checkpoint.md)。交付参数/梯度/主权重/m/v 的逻辑 owner 与物理存储账本。
- [ ] **理解 PP/SP 与多维组合。** 读 [SP](03_Parallelism/05_SequenceParallelism.md)、[PP](03_Parallelism/06_PipelineParallelism.md)、[多维并行](03_Parallelism/10_多维并行与DeviceMesh.md)，再对照 [Megatron groups](../docs/megatron_code_walkthrough/02_parallelism/01_parallel_state_and_tensor_parallel.md)和 [schedule](../docs/megatron_code_walkthrough/02_parallelism/02_pipeline_parallel.md)。画 warmup/steady/drain，核对 local shape。
- [ ] **知道 CP/EP 解决什么。** 首读 [CP](03_Parallelism/07_ContextParallelism.md)、[EP](03_Parallelism/08_ExpertParallelism.md)、[词表并行](03_Parallelism/09_Embedding与词表并行.md)入门例子。复杂 MoE 与长序列实现留到专项。
- [ ] **完成训练性能报告。** 用[配置设计](03_Parallelism/11_训练并行方案设计.md)、[配置工作表](03_Parallelism/16_实验与配置工作表.md)、[训练性能教材](../docs/performance_analysis_guide/04_megatron.md)完成实验课 4。固定 workload 做一次并行/重算/overlap 单变量对比。
- [ ] **验证恢复与数值。** 读[Checkpoint](02_Distributed_Communication_Memory/12_分布式Checkpoint与恢复.md)、[数值正确性课](00_Foundations/08_RL数据与数值正确性.md)，运行 [loss_normalization.py](labs/loss_normalization.py)。在独立小任务中保存、重启并核对样本进度、LR、参数和指标。

通过条件：能定位一个训练 step 的显存、计算与通信成本；不能只凭训练没报错通过。资源：小模型、2/4 卡起，容量需要时扩展。

## 第 9–11 周：推理执行与调度，约 60 小时

- [ ] **先有 Runtime 全景。** 读 [SGLang 概念课](../docs/sglang_code_walkthrough/01_foundations/00_runtime_concepts.md)的普通请求、Scheduler/KV/ModelRunner 分工，再看[学习地图](../docs/sglang_code_walkthrough/01_foundations/01_learning_map.md)。
- [ ] **跟一条普通请求。** 读[请求链](../docs/sglang_code_walkthrough/01_foundations/02_process_topology_and_request_path.md)，首读普通文本路径、对象形态和进程；特殊模型分支二读。交付 request id、消息、owner 与结束路径。
- [ ] **理解 Scheduler 与 KV。** 读[调度](../docs/sglang_code_walkthrough/02_runtime_core/01_scheduler_and_batch.md)、[KV 实现](../docs/sglang_code_walkthrough/02_runtime_core/02_kv_cache_and_radix_attention.md)，配合 [Orca](../docs/paper_read/06_Orca与Continuous-Batching论文详解.md)、[PagedAttention](../docs/paper_read/02_PagedAttention-vLLM论文详解.md)、[RadixAttention](../docs/paper_read/03_SGLang-RadixAttention论文详解.md)的设计与算例，论文实验细节二读。
- [ ] **理解执行和采样边界。** 读[ModelRunner](../docs/sglang_code_walkthrough/02_runtime_core/03_model_runner_attention_cuda_graph.md)、[API/采样](../docs/sglang_code_walkthrough/04_interfaces_and_models/01_api_request_and_sampling.md)。记录实际 backend、shape、采样配置与冷启动/稳态区别。
- [ ] **完成容量与缓存实验。** 用[推理性能教材](../docs/performance_analysis_guide/05_inference.md)、[推理并行设计](03_Parallelism/12_推理并行方案设计.md)完成实验课 5。固定长度分布，扫描并发，报告吞吐/TTFT/ITL/错误/KV；对比 prefix 冷热。
- [ ] **验证取消和路由。** 读[部署路由](../docs/sglang_code_walkthrough/03_scaling_and_deployment/02_deployment_topology_and_routing.md)、[可靠性](../docs/sglang_code_walkthrough/05_production_engineering/03_reliability_capacity_operations.md)。做有界取消实验，区分可驱逐缓存与泄漏。

通过条件：把容量曲线变化解释到请求、调度、KV 或执行层；不只报一个峰值 tokens/s。资源：单实例起，再比较 TP 和副本，使用相同总卡预算。

## 第 12–14 周：RL 框架与协同调度，约 60 小时

- [ ] **Ray 与有界队列。** 读[Ray 课](00_Foundations/07_Ray与队列调度.md)，运行 [ray_backpressure.py](labs/ray_backpressure.py)。解释 ObjectRef、窗口、完成顺序与队列增长。
- [ ] **读通同步主线。** 完整读 [slime 编排](../docs/code_walkthrough/01_architecture_and_ray_orchestration.md)、[rollout](../docs/code_walkthrough/02_rollout_sglang_server_mode.md)、[训练后端](../docs/code_walkthrough/06_megatron_backend_and_mbridge.md)。先跑最小同步闭环，再考虑更多角色与异步。
- [ ] **核对数据与目标。** 读[数据/buffer](../docs/code_walkthrough/03_data_buffer_partial_rollout_async.md)、[算法实现](../docs/code_walkthrough/05_rl_algorithms.md)、[reward/eval](../docs/code_walkthrough/08_rm_hub_and_eval.md)。已有算法推导可快读，mask、归一化、logprob 与过滤组语义重点读。
- [ ] **核对换权。** 读[同步与显存](../docs/code_walkthrough/04_weight_sync_and_memory.md)、[HF↔Megatron 转换](../docs/code_walkthrough/13_megatron_bridge_internals.md)、[SGLang 控制面](../docs/sglang_code_walkthrough/04_interfaces_and_models/03_control_plane_and_post_training.md)。交付 shard 往返和请求/KV/版本账本。
- [ ] **比较资源与异步策略。** 读[角色级并行](03_Parallelism/13_RL角色级并行.md)、[动态负载](../docs/performance_analysis_guide/09_dynamic_workloads.md)，在同步基线之后只改变一项资源或调度策略。记录队列、lag、有效样本、角色空闲与质量指标。
- [ ] **完成 RL 端到端报告。** 用[RL 性能教材](../docs/performance_analysis_guide/06_slime.md)完成实验课 6；需要时读[自定义接口](../docs/code_walkthrough/07_customization_and_agentic.md)。tau-bench、多轮 Agent、独立 TransferQueue 是后续项目选项，不同时加入首个闭环。

通过条件：能解释局部加速为什么影响或不影响整轮；能明确系统优化的正确性与质量边界。资源：按小模型所需分配角色池；共置/分离比较注明总 GPU 成本。

## 第 15–16 周：Kernel 实践与工程交付，约 40 小时

- [ ] **完成一个小 Kernel。** 读[Triton 入门](00_Foundations/09_第一个TritonKernel.md)，运行 [vector_add.py](labs/vector_add.py)，复习 [GEMM](01_Kernel_GPU_Programming_Compiler/03_GEMM与高性能Kernel模式.md)与[编译栈](01_Kernel_GPU_Programming_Compiler/06_PyTorch编译栈.md)。此项也可提前到第 3 周开始。
- [ ] **追一个真实热点。** 按 [CUDA 工具教材](../docs/performance_analysis_guide/03_cuda_kernels.md)先 nsys 后 ncu，限定 shape/范围；把微基准与端到端收益分开。
- [ ] **做一项可复现代码改动。** 从前面报告选择调度、资源生命周期、数据路径或性能问题；先写最小复现和正确性标准，再改动并回归。参考 [slime 工程化](../docs/code_walkthrough/09_engineering_observability.md)、[SGLang 扩展验证](../docs/sglang_code_walkthrough/05_production_engineering/02_extension_and_correctness.md)。
- [ ] **交付完整证据。** 使用[现场工作表](../docs/performance_analysis_guide/experiment_worksheet.md)、[正式报告](../docs/performance_analysis_guide/performance_report_template.md)、[观测教材](../docs/performance_analysis_guide/10_observability.md)。记录未通过或未运行项目；长期质量不能用短程 loss 代替。

最终成果：环境/拓扑图、训练 step 图、请求与版本状态图、训练/推理/RL 三份实验记录、一个 Kernel 报告，以及一项有回归证据的代码改动。没有合适问题时，以完整复现与诊断报告作为阶段交付，避免为“做优化”制造无依据改动。
