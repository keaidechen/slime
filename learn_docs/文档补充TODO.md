## 每项完成时的统一检查

1. 正文说清定义、假设、范围、具体过程、代价和不适用条件，必要时链接前置；新增字数不是验收标准。
2. 数值有可核对的输入输出；时间、字节、每rank/全局、逻辑/物理口径明确；脚本只验证它真实覆盖的内容。
3. 历史与能力陈述有一手资料；当前实现记录commit/文件身份和实际分支；旧稿被核实或修正的范围明确。
4. 实测包含配置、产物位置、对照、容差及结论；未运行、运行失败和未归因分别说明，不填推测的结果。
5. 主要正文留在所属领域，源码导读与贯穿案例通过链接连接，避免复制多份同一机制。计划中的新文件尚未创建，不预建空目录。
6. 新增Markdown登记到`encyclopedia_catalog.json`；更新所属README以及真正相关的术语、问题、推演或案例索引。
7. 运行结构检查；只在数值、脚本或证据范围变化时执行相应检查，不为纯文字改动重跑昂贵实验。

```bash
python3 tools/validate_learning_docs.py
```

若修改相关数值或脚本，再按需运行对应CPU参考；源码证据检查需Python 3.10或更新版本：

```bash
python3 learn_docs/labs/parallel_runtime_walkthroughs.py
python3 learn_docs/labs/training_rl_walkthroughs.py
python3 learn_docs/labs/loss_normalization.py
python3 learn_docs/labs/case_source_evidence.py --check learn_docs/reference/贯穿案例源码证据.json
```

源码快照检查失败表示需要分析漂移；不能为了让检查通过直接覆盖证据文件。新实验另存新快照，并在相关正文说明复核范围。
