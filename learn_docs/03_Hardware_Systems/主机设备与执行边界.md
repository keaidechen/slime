# 主机、设备与执行边界

> 类型：系统基础。前置：[处理器](../00_Physical_Foundations/计算电路与处理器.md)、[地址空间](../04_Memory_Storage/地址转换与内存分配.md)。

## 从程序到设备工作

应用进程运行在操作系统管理的地址空间中，通过框架、运行时和驱动提交设备工作。GPU 在自己的执行资源上处理 Kernel 和传输；CPU 与 GPU 的进度没有天然的一一对应关系。

一行 Python 可能只建立 tensor view，也可能触发多个 Kernel 或一次同步。读取设备结果到 host、日志和调试操作都可能改变等待位置。

## 三种调度层次

操作系统调度 CPU 线程；运行时安排请求、任务和设备提交；GPU 将线程块等工作映射到硬件资源。某层队列里有工作，不意味着下一层已经有可执行任务。

GPU 空闲可能源于 CPU 数据准备、解释器或调度开销，也可能源于等待通信、依赖或资源释放。仅增加 CUDA stream 数量不能解决尚未产生输入的问题。

## 异步与并发

异步描述提交方与完成方解耦；并发描述多个工作可以在同一时间段推进；并行描述实际同时执行。三个概念相关但不等同。

两个 stream 中的工作若依赖同一结果，仍需建立顺序；若都需要大量相同资源，也可能不能有效重叠。设备是否支持某类并发也应按具体平台确认。

## 资源生命周期

Context、stream、event、allocator、通信组和进程各有生命周期。重复初始化可能增加延迟和资源消耗；提前释放可能破坏在途工作。异常和取消路径应同正常路径一样说明谁负责清理。

## 演进的问题链

同步逐步执行易理解，但 host 与 device 相互等待；异步队列减少等待，增加完成追踪；批量提交减少控制开销，限制动态变化；复杂运行时支持动态负载，进一步需要状态机、观测和取消协议。
