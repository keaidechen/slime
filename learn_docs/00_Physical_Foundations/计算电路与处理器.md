# 计算：从算术电路到 CPU、GPU 与矩阵单元

> 类型：基础概念与演进。前置：[数字电路](信息与数字电路.md)。讨论设计取舍，不把 CPU、GPU、专用加速器写成互相淘汰的年代序列。

## 一次加法需要什么

整数加法器逐位处理输入与进位。更快的进位组织能缩短关键路径，但需要更多电路和布线。浮点加法还需要对齐指数、运算、规格化与舍入；浮点乘法与整数乘法也有不同的数据通路。因而不能把“执行一个算子”换算为与精度无关的固定电路成本。

乘加 $a b+c$ 是矩阵运算的基本构件。FMA 按其指令语义将乘加融合，并通常只在最终结果舍入；它与先舍入乘积再相加可能得到不同末位。FLOP 统计习惯常把乘加计为两次浮点运算，指令条数则未必是两条。

## 从电路到指令

处理器需要知道取哪个操作数、执行什么、结果写到哪里。指令集是软件可见契约，微架构是实现契约的具体组织。相同指令集可以由不同宽度的执行单元、不同流水线和缓存实现。

简化执行过程是取指、译码、读取操作数、执行、写回。现代处理器可能重叠这些步骤。流水线提高多个独立操作的吞吐，不会自动消除单个操作从输入到结果的全部延迟。

示意：一个有 4 级、每级一个周期的理想流水线，10 个互不依赖任务需要约 $4+10-1=13$ 个周期。若每个任务必须等上一个任务结果，无法直接使用这个吞吐公式。

## 性能来自多种并行性

| 并行性 | 暴露什么独立工作 | 主要限制 |
|---|---|---|
| 指令级 | 一个线程中的独立指令 | 数据依赖、分支、调度窗口 |
| 数据级 | 相同运算作用于多个数据 | 对齐、布局、分支差异 |
| 线程/任务级 | 多个执行上下文 | 同步、共享资源、负载均衡 |
| 分布式 | 多个设备处理不同状态或任务 | 通信、划分边界、故障 |

SIMD 用向量指令描述多个数据元素上的运算。GPU 的 SIMT 模型让程序员描述线程，再把线程组织成共同执行指令的组。线程的逻辑独立不意味着每个线程拥有完全独立的硬件控制资源。

## CPU 与 GPU 的不同取舍

CPU 通常投入较多资源降低复杂控制流和单线程执行的延迟。GPU 将大量资源用于吞吐，并依靠足够多的可运行工作覆盖等待。两者都包含缓存、流水线和并行执行，但资源配置与编程接口不同。

GPU 线程数量不是计算单元数量。程序提交的是工作集合；硬件分批执行，并受寄存器、共享内存和执行槽位限制。占用率描述驻留工作资源的使用情况，不能单独证明算术单元持续满负载。

矩阵计算单元进一步专门化规则的乘加。它们依赖支持的数据类型、形状与布局；不规则索引、归约、同步和数据搬运仍需其他资源。峰值矩阵吞吐提升后，这些部分可能成为新的主要成本。

## 演进中的瓶颈迁移

| 约束 | 设计方向 | 获得什么 | 新问题 |
|---|---|---|---|
| 单条长路径限制吞吐 | 流水线 | 多个操作重叠 | 冒险与依赖 |
| 指令中存在独立工作 | 多发射、乱序 | 利用指令级并行 | 控制与能量开销 |
| 同类数据大量重复计算 | 向量化、SIMD/SIMT | 摊薄控制开销 | 布局与分支差异 |
| 通用运算资源利用不足 | 矩阵专用单元 | 规则乘加吞吐 | 供数与非矩阵部分占比 |

这些方向常共存。优化应先确认程序能提供哪种并行性，而不是仅检查理论峰值。

## 从矩阵乘法连接到系统

对 $C_{M\times N}=A_{M\times K}B_{K\times N}$，常用计算量约定为 $2MNK$ FLOP。若每个输出独立从远端内存读取全部输入，就会重复搬运同一数据。分块使输入在较近存储复用，计算吞吐才有机会转化为实际性能。
