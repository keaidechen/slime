# 通信：从电信号和光信号到可靠的数据链路

> 类型：基础概念与演进。前置：[数字电路](信息与数字电路.md)。链路参数依设备而变，本章的数字全部是明确假设的算例。

## 发送 bit 需要一整条路径

发送端将逻辑数据编码成介质可传播的信号，接收端恢复时序并判定符号，再还原数据。芯片内部导线、封装连接、板级走线、电缆与光纤具有不同约束。距离、串扰、衰减和功耗决定了接口设计空间。

光连接减少某些长距离电传输限制，但发送与接收侧仍有转换、调制、检测与处理成本。不能仅凭介质传播速度判断一次软件请求的完成时间。

## 串行、多 lane 与带宽

并行接口同时传多个信号，需要管理它们之间的偏差和布线。高速串行接口以更高符号速率、编码和均衡等技术工作，多 lane 组合获得聚合带宽。符号速率、每符号携带的 bit 数、原始位速率和有效载荷吞吐必须分开。

即便收发方向可同时工作，也要说明报告的是单向带宽还是双向总和。把多个端口的带宽相加，只表示聚合潜力；一个连接或一个 GPU 未必能利用全部端口。

## 一次消息需要多久

粗略拆解为：

$$T=T_{submit}+T_{queue}+T_{serialize}+T_{propagate}+T_{process}.$$

串行化时间约为消息位数除以实际可用位速率。传播时间取决于距离与介质；排队时间取决于其他流量。分组网络还可能涉及多跳转发和重传。

示意：假设有效载荷吞吐为 25 GB/s，固定路径开销 5 μs，则 4 KiB 的传输项约 0.164 μs，而 64 MiB 约 2.68 ms。小消息倾向于受固定成本影响，大消息更容易体现带宽。这只是无额外拥塞的 $\alpha+n/\beta$ 模型，不能直接作为网卡或 NCCL 的实测。

## 可靠性和流量控制

差错检测发现某些损坏，纠错可修复编码覆盖范围内的错误，重传则重新发送。它们有不同的冗余与时延代价。可靠传输也不保证应用操作“恰好执行一次”：连接断开时，发送方可能不知道接收方是否已执行。

流量控制处理接收方是否有空间；拥塞控制处理路径上的共享资源是否过载。缓冲能吸收短期突发，但持续输入超过输出时，队列会不断增长。大缓冲并不创造更多链路容量。

## 拓扑决定并发流量是否争用

节点之间能够连接，不表示任意通信图都能同时达到端口线速。多个发送方可能共享上行链路、交换端口或接收端注入能力。观察拓扑应同时考虑路径、超售、双向口径和并发通信模式。

NVLink、PCIe、Ethernet、InfiniBand 等处于特定生态和接口约束中，不应排列为一条通用替代路线。选型要说明通信距离、参与设备、拓扑、软件栈和工作负载。

## 问题推动的演进

| 问题 | 方法 | 新代价 |
|---|---|---|
| 高频并行信号难以对齐 | 串行收发与时序恢复 | 编码、均衡和收发器复杂度 |
| 一条连接无法满足聚合需求 | 多 lane、多端口与交换网络 | 布线、交换和争用 |
| 软件逐字节搬运成本高 | DMA 与设备侧传输 | 缓冲所有权、地址映射与完成语义 |
| 网络有突发与错误 | 流控、拥塞控制、重试 | 队列时延和状态管理 |
