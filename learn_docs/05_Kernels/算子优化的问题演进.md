# 算子优化：从数学操作到资源调度

> 类型：专题综述。前置：[处理器](../00_Physical_Foundations/计算电路与处理器.md)、[局部性](../00_Physical_Foundations/局部性与数据移动.md)。

## 正确实现只是起点

数学表达式没有指定数据布局、线程分工和资源生命周期。两个实现可以产生容差内相同结果，却具有不同的访存交易数量、启动次数和并行度。

优化前应写出输入输出、dtype、stride、mask、别名条件和数值容差。这样才能判断优化的是相同问题。

## 从独立输出到合作复用

每个线程独立计算一个输出容易实现，但可能重复读取数据。线程块合作装载 tile，再让多个输出复用输入，可以减少某层流量。同步保证消费者读到生产者完成的数据；同步范围必须与共享范围一致。

更大的 tile 增加复用，也增加寄存器与共享内存需求；资源占用过高会降低驻留工作，甚至 spill。布局和 tile 应与实际 shape 一起选择。

## 从串行搬算到流水线

朴素方式是先搬一块，再计算一块。双缓冲让下一块搬运与当前块计算重叠，需要独立缓冲和正确的完成通知。更深流水可覆盖较长等待，也增加容量和同步复杂度。

Warp specialization 将不同工作分配给不同 warp；持久化 Kernel 则让驻留工作单元连续处理多项任务。两者可以组合，但不是同义词，也不自动适合所有小 shape。

## 从单算子到融合

将 GEMM 的 epilogue 与 bias、激活等融合，可减少中间读写和提交。跨更多算子融合可能增加代码和状态、限制调度自由度，也可能失去更强的独立库实现。

FlashAttention 是把数学变换、在线归约与存储层次共同设计的案例；Grouped GEMM 则处理一组形状相关但不一定相同的矩阵任务。它们展示不同问题，不应由“少几个 Kernel”统一推断收益。

## 演进的判断表

| 证据 | 可尝试的方向 | 新的检查点 |
|---|---|---|
| 重复远端读取多 | 分块与缓存复用 | 近端容量、占用率 |
| 搬运与计算交替等待 | 异步流水 | 依赖、缓冲轮转 |
| 大量小 Kernel | 融合、批量调度 | 额外寄存器与数值差异 |
| 不规则任务负载失衡 | 动态调度、Grouped GEMM | 调度开销与长尾 |
| 启动开销突出 | 图提交或持久化 | 动态性与资源驻留 |

性能不只看均匀平均输入。MoE 需要偏斜的专家 token 分布，Attention 需要变长与不同 mask，归约需要边界尺寸和数值极端值。
