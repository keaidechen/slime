# 地址转换、分页与内存分配

> 类型：基础概念。前置：[存储器件](../00_Physical_Foundations/存储器件与层次.md)。

## 地址不是数据本身

虚拟地址是程序使用的命名空间，地址转换将它映射到物理资源。不同进程中的相同数值指针通常不代表同一份数据；跨设备访问还要满足平台的映射、权限和同步条件。

页表记录映射与权限，TLB 缓存地址转换结果。TLB miss 是转换缓存未命中，不等于数据页一定不在内存；page fault 则需要由系统处理，原因也不只包括从磁盘调页。

## 一次分页算例

假设页大小 4 KiB，虚拟地址 0x2345 可分为虚拟页号 2 和页内偏移 0x345。如果页 2 映射到物理页框 9，则对应地址为 0x9345。这只是固定页大小的教学算例；真实平台支持的页大小、地址位数和多级页表不同。

分页允许逻辑连续对象使用不连续物理页框。它减少某些连续分配约束，同时增加页表和转换成本。大页降低映射数量，但可能增加内部浪费并限制细粒度管理。

## 分配器是另一层

框架向系统申请大块存储，再给 tensor 分配小块，减少频繁系统调用或同步。缓存分配器保留可复用块，所以对象释放和设备总使用量下降不必同时发生。

内部碎片是分配单元内部未被有效使用的空间；外部碎片是总空闲足够却无法满足某个连续块需求。具体分配器的合并、分桶和虚拟映射策略会改变实际行为。

## 所有权与异步生命周期

CPU 不再引用某个对象，不代表 GPU 上排队的消费者已结束。跨 stream 或设备共享 buffer 时，生产完成、消费者可见和安全回收要用正确依赖表达。提前复用可能产生偶发错误，延迟回收则可能增加峰值。

## OS 分页与 KV 分页的关系

PagedAttention 借鉴逻辑块到物理块的映射思路，但通常由推理运行时维护 KV block table，并由相应 Kernel 解释。它不意味着每个 KV block 就是 OS 页，也不自动意味着可把 KV 换到磁盘。

## 从问题到设计

隔离需求推动地址空间与权限；连续分配压力推动分页；频繁分配推动内存池；异步计算使生命周期跟踪成为必要。每加一层间接映射，都要回答映射由谁维护、何时有效、何时能回收。
