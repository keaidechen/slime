## 证据分成四层

| 层级 | 本轮状态 | 能支持的结论 |
|---|---|---|
| 源码定位与分支核对 | 已完成 | 该快照中有哪些路径和条件 |
| CPU数学/教学状态参考 | 现有三个数值脚本通过 | 固定假设下的目标、梯度、依赖和账本 |
| 真实模型、请求和GPU trace | 本轮未采集 | 需实际运行后才能判断数值对齐与性能 |
| 多机/故障恢复 | 本轮未执行 | 需隔离实验验证，不能从方法名推断 |

本轮没有修改训练、服务或恢复的生产实现。案例中的“建议观察字段”“临时打点”和“故障实验”是具体取证方案，不代表已有统一的日志接口。

[源码证据快照](../reference/贯穿案例源码证据.json)还记录24个关键文件的SHA-256、是否匹配HEAD内容、函数限定名和行号。HEAD不能代替工作区文件身份；本次记录的24个文件均与各自HEAD内容一致。源码变化后重核正文，不要仅刷新快照就宣布旧结论有效。

使用Python 3.10或更新版本读取这些源码；macOS自带的旧Python可能无法解析其中的match语法。脚本本身仅依赖标准库，不导入torch/Ray或模型：

```bash
python3 learn_docs/labs/case_source_evidence.py --check learn_docs/reference/贯穿案例源码证据.json
```

要为自己的实验生成新快照，可输出到独立实验目录：

```bash
python3 learn_docs/labs/case_source_evidence.py --output /tmp/slime-case-source.json
```

该检查只核对源码是否漂移，不是运行正确性测试。已经提交的源码证据文件也不包含用户模型、样本或任何训练结果。

## 每个真实实验应留下什么

| 产物 | 最少内容 |
|---|---|
| 配置与身份 | run_id、源码快照、完整解析配置、模型/tokenizer身份、设备与拓扑 |
| 输入 | 固定token/样本身份、采样参数、mask和分组；保留实际使用的输入 |
| 事件或dump | 原始文件、rank/进程、时钟域、单位、采集窗口和扰动说明 |
| 对照 | 参考条件、改变的唯一变量、容差、逐项比较结果 |
| 结论 | 已证实、观察到但未归因、尚未验证，三者分别写出 |

同一run_id把这些产物放在同一实验目录；不要仅保留截图。跨进程事件优先用request/sample/collective身份关联，未同步的跨机器时间不能直接相减。

## 从数学预检到真实证据

```bash
python3 learn_docs/labs/parallel_runtime_walkthroughs.py
python3 learn_docs/labs/training_rl_walkthroughs.py
python3 learn_docs/labs/loss_normalization.py
```

这些脚本提供数学参考。实际dump的概率不是人为fixture中的常数，真实NCCL也不是教学表的固定2 ms；把实际输入代入相同定义，才能形成有效对照。
