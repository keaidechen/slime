# 成本模型、关键路径与测量方法

> 类型：基础概念与方法。前置：[局部性](../00_Physical_Foundations/局部性与数据移动.md)、[链路时延](../00_Physical_Foundations/通信信号与链路.md)。工具操作和框架实验继续在[性能指南](../../docs/performance_analysis_guide/README.md)维护。

## 先说明优化对象

训练可关注有效 token/s、step time 或达到目标质量的成本；推理可关注满足 SLO 的吞吐与尾延迟；RL 还要考虑有效样本率和版本差。不同目标不能只用同一个 GPU 利用率衡量。

## 时间线与关键路径

将任务表示为有依赖的活动图。端到端耗时取决于完成所需的关键路径，也受资源争用影响。把所有 Kernel 时长相加可能重复计算重叠；取最大值又可能漏掉不能并行的依赖和资源竞争。

例如计算 8 ms、通信 5 ms，若理想情况下完全独立并可充分重叠，下界为 8 ms；若通信消费计算输出，则至少有相关串行部分。stream 上看起来同时运行，也可能因争用让两个活动都变慢。

## 三种模型各回答什么

| 模型 | 适用问题 | 容易遗漏 |
|---|---|---|
| Roofline | 计算与某层流量的吞吐上界 | 小任务、依赖、并行度 |
| $\alpha+n/\beta$ | 消息规模与传输时间 | 拥塞、拓扑、到达偏斜 |
| Amdahl | 优化某部分的整体上限 | 工作量变化与新的瓶颈 |

若可优化部分占 30%，局部加速 2 倍，则理想整体加速为 $1/(0.7+0.3/2)\approx1.176$。这是工作量不变的模型，不含调度变化。

## 计时边界必须匹配问题

异步提交的 host 返回时间通常只覆盖提交。设备事件用于特定设备工作区间，端到端墙钟则需要正确等待目标工作完成。同步位置改变重叠关系，因此 microbenchmark 和真实系统运行都应保留。

编译、预热、缓存建立、内存分配和稳定运行应分开报告。Profiler 用于解释执行，但其开销可能改变测量对象；收益应使用适当的无 profiler 基准复核。

## 证据闭环

现象 → 假设 → 可区分假设的观测 → 单因素干预 → 正确性检查 → 端到端复测。仅看到网络利用率高，不能证明网络是可优化的关键路径；长 NCCL 区间也可能包含等待其他 rank 到达。

## 可复核记录

记录硬件拓扑、软件与代码版本、输入长度分布、精度、并行配置、计时边界、重复次数与原始结果。使用[实验工作表](../../docs/performance_analysis_guide/experiment_worksheet.md)和[报告模板](../../docs/performance_analysis_guide/performance_report_template.md)。
