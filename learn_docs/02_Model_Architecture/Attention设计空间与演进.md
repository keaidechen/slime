# Attention 的设计空间与问题演进

> 类型：专题综述。前置：[Transformer 基础](Transformer与Attention基础.md)。本页按问题归类，具体方法的发表时间与采用版本以原始来源为准。

## 五个相互独立的设计轴

| 设计轴 | 问题 | 代表方向 | 后续约束 |
|---|---|---|---|
| 数学与数据搬运 | 中间注意力矩阵读写昂贵 | FlashAttention 等 IO-aware 实现 | 分块、在线归约、硬件映射 |
| 状态宽度 | 每个历史 token 的 KV 太大 | MQA、GQA、MLA | 表达能力、投影和内核支持 |
| 访问集合 | 历史太长，不想读取全部位置 | 局部、块稀疏、动态检索 | 选择质量、索引与不规则访问 |
| 历史表示 | 不想保存随长度增长的 token 状态 | 递推与线性状态 | 固定状态容量、精确检索、训练并行 |
| 物理管理 | 动态请求导致分配浪费 | 分页、共享与分层 KV | 映射、引用、淘汰和传输 |

这五个轴可以组合。分页属于运行时存储组织，GQA 属于模型参数化；FlashAttention 的核心目标是高效实现注意力计算，不能据此推导它消除了所有序列长度相关计算。

## 从完整计算到 IO 优化

直接构造分数矩阵容易理解，却会产生大中间结果。分块和在线 Softmax 允许在不保存完整矩阵的情况下累积结果。新的问题是保持数值稳定、处理反向、安排片上资源和并行任务。

详细推导和论文沿革维护在[FlashAttention 论文](../../docs/paper_read/01_FlashAttention论文详解.md)，Kernel 视角见[算子案例](../05_Kernels/案例_FlashAttention与GroupedGEMM.md)。

## 从多头缓存到压缩表示

减少 KV heads 降低缓存宽度，GQA 在共享程度与表示能力之间提供设计空间。MLA 使用潜变量表示并结合执行变换，其容量收益需要与额外计算、位置处理和特定 backend 一起评估。见[MLA 推导](mla/README.md)。

这条路线仍需处理历史长度。压缩每个 token 的状态不等于不再读取长历史。

## 从扫描历史到选择历史

局部窗口直接限制可见范围，块稀疏改善规则性，动态选择适应输入。选择过程可能包含打分、Top-K、索引表和 gather；被省掉的 attention 工作必须大于新增成本，还要保持所需任务质量。见[稀疏专题](sparse_attention/README.md)。

## 从 token 列表到递推状态

递推结构将历史汇总到状态，并按 token 更新。它改变记忆与读取方式，不应仅凭线性复杂度推断速度或质量。顺序更新如何并行训练、状态如何分片、推测失败后如何回滚，都成为系统问题。见[线性注意力](linear_attention/README.md)。

## 方法比较的共同条件

固定模型规模、任务质量、输入输出长度分布、batch、精度、硬件与实现成熟度。分别记录 prefill、decode、显存和端到端指标。某个方法在长上下文训练中有优势，不能自动外推到小 batch 的低延迟服务。

参考：[FlashAttention](https://arxiv.org/abs/2205.14135)、[GQA](https://arxiv.org/abs/2305.13245)、[PagedAttention](https://arxiv.org/abs/2309.06180)。
